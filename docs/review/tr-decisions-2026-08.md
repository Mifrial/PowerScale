# Решения по аудиту ТР — 2026-08

Рабочий журнал решений Андрея по результатам аудита.

Важно:

- этот файл не является ТР;
- решения не означают автоматического изменения кода или ТР;
- реализация каждого решения выполняется отдельной задачей после согласования объёма;
- нерассмотренные пункты остаются в `docs/review/tr-audit-2026-08.md`.

## DEC-001 — модель membership персонажа в игре

- **Дата:** 2026-08-29
- **Связанный пункт аудита:** TR-003
- **Решение:** канонической считается текущая модель кода A/L/O/P:
  - `activeVersion` — активная одобренная версия;
  - `latestVersion` — последняя версия персонажа;
  - `pendingVersion` — версия на модерации;
  - `overlay` — сессионные изменения.
- **Последствие:** старую модель `active_json / pending_json / draft_json` не считать канонической; ТР и backend-контракт привести к A/L/O/P отдельной задачей.
- **Код пока не изменять.**

## DEC-006 — ревизия правил и время публикации

- **Дата:** 2026-08-29
- **Связанный пункт аудита:** TR-002
- **Решение:** `revision` — числовой номер ревизии, уникальный внутри пространства.
- **Frontend-контракт:** frontend передаёт `spaceId + revision`.
- **Backend-контракт:** backend разрешает пару `(spaceId, revision)` в запись `SpaceRevision`, получает из неё неизменяемое `publishedAt`, а затем строит срез правил по этому времени.
- **Терминология:**
  - `SpaceRevision` — опубликованный набор правил;
  - `RuleVersion` — версия одного правила;
  - `revision` — номер `SpaceRevision` внутри пространства;
  - `publishedAt` — время коммита ревизии.
- **Инварианты:** коммит ревизии атомарен; записи `RuleVersion` immutable; timestamp коммита не может приводить к включению версий будущей ревизии.
- **Последствие:** `rules_version_at` считать неточным названием поля времени публикации; в текущем ТР использовать `publishedAt`.
- **Код пока не изменять.**

## DEC-012 — множественные проверки попадания

- **Дата:** 2026-08-29
- **Связанный пункт аудита:** MISS-001
- **Решение:** текущий рабочий канон:
  - `1 → 1`: одна проверка попадания атаки против одной проверки защиты — реализовано;
  - `1 → N`: одна проверка попадания атаки против нескольких проверок защиты — реализовано;
  - `N → 1`: несколько проверок попадания атаки против одной проверки защиты — не реализовано;
  - `N → N`: не заявлено и не считать реализованным.
- **Инвариант:** «один удар по нескольким целям» и «несколько одновременных ударов» — разные оси модели; `attack_mode: wide` не описывает их полностью.
- **Последствие:** ТР должен описывать матрицу поддержанных вариантов и явно отмечать `N → 1` как backlog.
- **Код пока не изменять.**

## DEC-024 — результат валидности персонажа

- **Дата:** 2026-08-30
- **Связанный пункт аудита:** TR-012
- **Решение:** API возвращает вычисляемый результат `validation: { valid, problems }`.
- **Инварианты:** это не lifecycle-статус и не часть `CharacterVersion`; результат пересчитывается по версии персонажа и её ревизии правил.
- **Последствие:** Game не должен полагаться на `status === 'ready'`; сохранение и подача используют серверную проверку.
- **Код пока не изменять.**

## DEC-031 — источники магии

- **Дата:** 2026-08-30
- **Связанный пункт аудита:** новый магический контур
- **Решение:**

## DEC-033 — магический контент до релиза

- **Дата:** 2026-08-30
- **Связанный пункт аудита:** TR-015
- **Решение:** обязательный магический контур включает:
  - источник волшебства: Магическое ядро и его ветку навыков;
  - пути Волшебник, Псионик, Шаман и их ветки;
  - все общие навыки волшебства;

- **Критерий runtime:** репрезентативный набор заклинаний должен покрывать все основные механики; остальные должны быть выгружены и отображаться.

- **Код пока не изменять.**

## DEC-034 — экономика игры

- **Дата:** 2026-08-30
- **Связанный пункт аудита:** новый инвентарный контур
- **Решение:**
  - `moneyBudget` — только исторический стартовый лимит создания;
  - `money` — текущий баланс валюты;
  - хранение — одно число в минимальных денежных единицах;
  - магазины — game-scoped наборы позиций с ценой покупки, отдельной опциональной ценой продажи и остатком;
  - обязательны покупка, продажа, discard, передача предметов, передача денег и loot;
  - ведущий настраивает права/режимы, обычные разрешённые операции не требуют ручного approve.
- **Последствие:** `moneyLimit` не должен использоваться как постоянный лимит текущих денег.
- **Код пока не изменять.**

## DEC-059 — упрощённая модель Character/Game membership

- **Дата:** 2026-08-30
- **Связанный пункт аудита:** RTR-004 и связанная модель Character/Game
- **Решение:** A/L/O/P и история CharacterVersion не являются целевой моделью. Backend хранит один `actualCharacter`; browser draft является локальным состоянием. Membership игры хранит `characterId`, `approvedCharacterVersion` как полную immutable-копию принятого состояния и `gameOverlay`; персонаж может состоять не более чем в одной игре.
- **Session:** `sessionCharacterVersion = resolve(approvedCharacterVersion, gameOverlay)`. Overlay не может менять владельца, `characterId`, `spaceId`, `rulesRevision`, права или `visibility`. Во время сессии actual и approved snapshot неизменяемы.
- **Session commit:** завершение сессии атомарно разрешает overlays, валидирует результат, обновляет actual characters, очищает overlays и отмечает изменённые memberships для модерации; optimistic guard отклоняет устаревшее состояние.
- **Moderation:** moderation не является CharacterStatus. Она требуется при отсутствии approved snapshot или при diff approved/actual; `needs_fix` вычисляется и не хранится как lifecycle status. Return for rework сохраняет membership и пишет сообщение в обсуждение; reject разрешён только для submitted, active reject невозможен.
- **Migration:** при смене ревизии игры несовместимые персонажи мигрируются владельцами и после миграции проходят moderation. До migration и approve блокируется только следующая сессия несовместимого персонажа, не вся игра. Выход из игры разрешён.
- **Последствие:** DEC-001, DEC-016, DEC-036, DEC-037, DEC-038, DEC-051 и DEC-052 superseded в части модели Character/Game membership; current-ТР фиксирует контракт, реализация — `CODE_GAP / implementation OPEN`.
- **Код пока не изменять.**
