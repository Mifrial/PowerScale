# Контекст ревью 9 — аудит frontend-rules.md + срез баррелей

Волна 2026-08-03. По замечанию пользователя: проверить правила на лишнее,
ошибки, неточности, пропущенное. Найдено и исправлено.

## Найденные проблемы

1. **«Один экспорт на файл» был размещён в блоке SFC** (раздел 1) — неверно:
   у `.vue`-компонентов нет именованных экспортов (SFC имеет единственный
   default export); правило про TS-файлы. Плюс «Одна задача на файл» и «Один
   экспорт» стояли рядом и дублировались по смыслу.
2. **Баррели `Component/Grid/index.ts` (6 реэкспортов) и
   `Component/FilterBar/index.ts` (7)** — много-экспортные, не покрыты
   исключением init.ts/routes.ts; при этом наружу реально используются только
   `initBaseRenderers`/`initBaseFilterHandlers` (main.ts). Компоненты
   импортируются глубокими путями, `rendererRegistry`/`filterHandlerRegistry`
   из барреля не нужны. Мёртвый реэкспорт + противоречие правилу.
3. **`Service/Instance/` не упоминался в перечне анатомии** (был покрыт лишь
   оговоркой «перечень не закрыт»).

## Решения пользователя

- **Синглтоны — форма A**: `Service/Instance/xService.ts` + короткое имя
  (`xService`). Не `init.ts` (тянет Vue → ломает vitest CSS), не в файле класса
  (case-коллизия TS1149), не суффикс `Instance`/`Singleton` (шум в вызовах).
- **Формулировка правила**: «Не более одного экспорта на TS-файл» (точнее, чем
  «Один экспорт на файл»: допускает файлы без экспортов, scope явно по TS).
- Про `index.ts` переформулировано без ложной связи с init.ts: суть —
  «баррелей не создаём, импортируем по прямому пути».
