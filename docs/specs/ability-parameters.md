# Дизайн: параметрические значения способностей

> Дата: 07.08.2026 (черновик, Дискуссия 2). **Актуализировано 08.08.2026** — параметры реализованы
> в S3 (модель, цена, резолв) и расширены в S6/S8 (расовый потолок «X», бесплатное авто-значение,
> докупка сверх авто). Открытым остаётся текстовая подстановка `{code}` в описании (§4).
> Базируется на правилах `their-right` в ссылках по `code`, слоях «правило-шаблон»/«персонаж-экземпляр»
> (см. ability-resource-design.md).

## 1. Что выражаем

В чертах докла значение «X» — параметр, который заполняет игрок (или правило) в момент
покупки/использования. Нужен единый механизм подстановки, чтобы:
- не дублировать вид данных в каждой зоне/гранте/описании;
- заклинания (много параметров «всюду») не ломали контракт при появлении активации.

## 2. Два вида параметров (по `resolution`)

1. **`purchase`** — значение выбирается **при покупке** способности; хранится на инстансе
   (в `build.abilities` у персонажа). Например: «Энергохранилище X», «Сопротивление магии X».
2. **`activation`** — значение выбирается **при активации**. Активацию в ближайшем срезе не делаем —
   параметр декларируем в секции, но не используем до появления активации (без вреда контракту).

> Одна способность может нести несколько параметров разных видов, напр. заклинание со «сложностью
> сотворения» (purchase) и «X урона электричеством» (activation).

## 3. Спецификация параметра в AbilitySpec

Значение параметра — **размерная величина** (`DimensionalNumberValue`), а не только примитив:
нужно для `activation` (напр. «X урона электричеством», где X — размерность), и допустимо для
`purchase` (числовые ограничения хранятся как числа/выражения).

```ts
interface AbilityParameter {
  code: string          // ссылочный ключ, напр. 'x' — подстановка {x}
  label: string         // «Энергохранилище ×»
  resolution: 'purchase' | 'activation'
  default: DimensionalNumberValue | number
  min?: DimensionalNumberValue | number  // пределы опциональны
  max?: DimensionalNumberValue | number
}
```

Блок `parameters: AbilityParameter[]` в секции. Способности без параметров теряют его (= `[]`).

> **Реализовано (S3):** `AbilityParameter` в `Rule/Dto/Ability/AbilityParameter.ts` (совпадает со спекой),
> `parameters?: AbilityParameter[]` на `AbilitySpecBase`. `activation` остаётся декларированным, не используется.

## 4. Как параметр попадает в места

Принцип: **числовая величина кода поля всегда ссылается на `Formula`/структуру, которая умеет
раскрыть `{code}`**; литерал остаётся для константных случаев. Дерево резолва по разрешению:
- `purchase` → значение из инстанса способности (`build.abilities[x].parameters[code]`);
- `activation` → резолвится отложенно (сейчас не вызывается).

Точки подстановки (реализация):

| Место | Что меняем | Вид | Статус |
|-------|------------|-----|--------|
| `AbilityCost` (цена зоны) | `kind: 'parameter'` | `{ kind:'parameter'; parameter_code; per_unit }` — стоимость = `per_unit × X` | ✔ S3 |
| `AbilityCost` (цена зоны) | `kind: 'parameter_table'` | `{ kind:'parameter_table'; parameter_code; costs: Record<string, number> }` — стоимость = `costs[X]` (нелинейная; ключи — `toString()` размерного значения). «Врождённая Сила X» (модификатор −3..+3 → −3..+8 ОС) и «Врождённая Магия X» (дар, размерные 3↓..5↑ → 1..20 ОС из доковой таблицы) | ✔ S8/S9 |
| `Grant.value`/`amount` | `Formula { type:'parameter' }` | резолв в `FormulaEvaluationService.evaluateDimensional` (`value = X × per_unit`) | ✔ S3 |
| `Grant.value` (resistance) | `{ type:'parameter'; parameter_code; per_unit }` | резолв в `CharacterEditorService.resolveGrant` → размерное `{ base: X×per_unit }` | ✔ S3/S8 |
| `Grant` (дать характеристику параметром) | `{ type:'characteristic_parameter'; characteristic_code; parameter_code; per_unit }` | резолв в `resolveGrant` → `characteristic` со значением X (база = X); напр. «Врождённая Магия X» даёт характеристику «Магия» | ✔ S9 |
| `Description` | текстовая подстановка `{code}` | строка | ✖ не реализовано |
| `SpellSpec` (позднее) | поля-числа ссылаются на параметр | по мере Фазы 5 | — |

## 5. Расовый слой (S6/S8)

Раса может задать способности параметр «X» через `RaceAbilityRef.parameters: Record<code, DimensionalNumberValue>`:
- у **приобретаемой** ref (`automatic: false`) — это **потолок** доступной величины;
- у **автоматической** ref (`automatic: true`) — это **бесплатное значение**, с которым способность даётся.

Модель редактора (`EditorAbilityParameter`):

```ts
interface EditorAbilityParameter {
  code: string;
  label: string;
  value: DimensionalNumberValue;   // выбранное / авто-значение расы / 0
  min: DimensionalNumberValue;
  max: DimensionalNumberValue;     // min(максимум спеки, потолок расы)
  perUnit: number;                 // стоимость за единицу (os-зона kind 'parameter')
  cappedByRace: boolean;           // потолок расы задан → имя «до N»
  freeValue: number;               // бесплатное авто-значение расы (0 = нет)
}
```

Механика докупки сверх авто (Аэрон: «Сопротивление магии 2» бесплатно, опции 3–5 докупаются):
- автоматические значения собираются отдельно (`racialAutomaticValues`), потолки — `racialParameterCaps`;
- `freeValue` = бесплатное авто-значение; **стоимость докупки** = `per_unit × (X − freeValue)`
  (`parameterCostValue`, `Math.max(0, …)`);
- автоматический грант применяется только если способности **нет** в `build.abilities` — иначе при
  докупке грант задвоился бы (`forEachActiveGrant`, `resolveGrant`);
- `cappedByRace = cap !== undefined`: имя способности показывает «до N» всегда при заданных
  `parameters` (даже если потолок = максимуму спеки, напр. «Магия до 5»).

Значение параметра для цены/дара: выбранное (`build.abilities[x].parameters[code]`), иначе дефолт спеки.

**Связь параметров способностей (S8)** — `AbilityParameter.linked { ability_code, parameter_code, max_delta }`: значение этого
параметра не может отличаться от значения связанного более чем на `max_delta` («Врождённая Стойкость X» ↔ «Врождённая
Сила X», max_delta 3). В `editorParameters` диапазон сжимается: `max = min(specMax, other + delta)`, `min = max(specMin, other − delta)`,
где `other` — выбранное значение связанного параметра из `chosenParametersByCode` (не выбрана → 0).

## 6. Открытые вопросы

- [x] `AbilityCost` для параметрических цен — **решено**: фиксированная цена за единицу `per_unit × X`.
- [x] Точный вид `Formula`-узла — **решено**: `{ type:'parameter'; parameter_code; per_unit }`.
- [x] Как показывает UI: поле «X» в покупке + пересчёт цены/предпросмотра — **решено**: степпер
      «−/+/снять», цена = `per_unit × X`, у автоматических — докупка сверх `freeValue`.
- [x] Показ предела в UI (если `min`/`max`) — **решено**: `cappedByRace` → «до N».
- [ ] Текстовая подстановка `{code}` в описании — не реализовано (опционально, не блокирует).

## 7. Связь с гэпами

- Гэпы «ХОС/2xОС параметрические цены» и «простейшие заклинания X» (S3) разрешаются этим механизмом.
- Сопротивление магии X (Грант `resistance`) использует параметр `x` как `value`.
- Таблица «Магия Х» и «Телосложение: X» (S8/S9) используют потолок и докупку сверх авто (S6/S8).
