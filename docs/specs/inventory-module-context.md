# Контекст: этап «Инвентарь» (закупка предметов) — анализ и план захода

> Создан 2026-08-11. Статус: **план согласован, анализ документа предметов в работе**.
> Источник данных: `docs/rule/battle/AI.html` (экспорт Google Docs, предметы/бой). Нормализованный каталог: `docs/rule/battle/catalog.md` (заполняется).

## 1. Цель захода

Реализовать этап «Закупка (инвентарь)» редактора персонажа по ТР §7 (п.5):
- каталог предметов ревизии правил (тип `item`), фильтр по категории;
- покупка предметов за деньги (гм) с указанием количества;
- экипировка купленного снаряжения (флаг `equipped`, без слотов);
- **отмена покупки** до сохранения персонажа (предметы, добавленные во время редактирования, удаляются, деньги возвращаются);
- остаток бюджета конвертируется в монеты в инвентаре (формат «5 гз, 7 гс, 9 гм» — размен в UI).

## 2. Ключевые решения (согласованы 2026-08-11)

| № | Решение |
|---|---------|
| R1 | Каталог предметов — **импорт реального документа** (`docs/rule/battle/AI.html` → `catalog.md` → `mockItemImport`), как навыки «Развития» (S14). |
| R2 | **«Отмена покупки»** — только предметы, **добавленные во время редактирования** (сверх базовой линии): удаляются, деньги возвращаются. **«Продажа» изначальных предметов — будущее, сейчас не делаем.** |
| R3 | Экипировка — **простой тумблер `equipped`** (без жёстких слотов); карточка читает все экипированные оружия/доспехи. |
| R4 | Деньги — **число гм** + размен «гз·гс·гм» в UI; отдельных предметов-монет не заводим. |
| R5 | Предметы без `cost_gm` (или `innate`) в каталог закупки не попадают. |
| R6 | Покупка сверх лимита денег разрешена в модели (черновик; «Готово» гейтится `money.exceeded`). |
| R7 | **Естественное оружие (2026-08-25).** Руки/ноги не хардкодятся в overview: вид даёт automatic `humanoid-body` → grant `{ type: 'item', item_code, quantity }`. `quantity` — число конечностей, не два тайла атаки. Предмет `innate`: в инвентарь экипированным, не в закупке (R5), не снимается. Владение — экземпляр `vladenie-oruzhiem` ур.1 `gifted` (бюджет 0); апгрейд платит сверх 1. Раса last-write-wins по `item_code`. Мутационный innate не из automatic-гранта вида/расы не трогается. |

## 3. Семантика денег и базовая линия отмены

- `build.money` = наличные персонажа (остаток после закупки).
- **Edit**: `fromVersion` кладёт `money = version.money`; базовая линия — снапшот оригинала в `initDraft`.
- **New**: `CharactersNewPage.start` кладёт `money = moneyBudget`. При первом входе в шаг «Инвентарь» деньги донормируются до `effectiveMoney` (учитывает особенности богатства «Личности») и фиксируется базовая линия `{ inventory: [], money: effectiveMoney }`. Пограничный случай «взял Богатого, но в Инвентарь не заходил» — принят для прототипа.
- **Базовая линия** — `CharacterDraftEntry.inventoryBaseline?: { inventory: InventoryItem[]; money: number } | null`:
  - edit: `{ inventory: [...version.inventory], money: version.money }`;
  - new: `{ inventory: [], money: effectiveMoney }`.
- Покупка: `money −= cost_gm×qty`, строка инвентаря создаётся/инкрементируется по `ruleId`. Отмена: `money += cost_gm×qty`, quantity не опускается ниже baseline (изначальные предметы не продаются — кнопки нет).
- `moneySpent = effectiveMoney − build.money` (существующая формула `buildBudgets`; работает при корректной инициализации).

### 6.3. Ключевые находки и развилки

1. **Курс валют.** Документ противоречит сам себе: проза «1 гз = 100 гс, 1 гс = 100 гм», сводная «Условная валюта» — «1 гз = 10 гс = 100 гм». **Внутренние перекрёстные проверки (кристаллы: 3гс×1.2 = 36гм; 96гс×1.2 = 11гз 52гм) подтверждают «1 гз = 10 гс = 100 гм»** — проза ошибочна. Это совпадает с текущим кодом (`moneyBreakdownLabel`) и ТР.
2. **Цены** — в гз/гс/гм смешанно; у товаров диапазоны («от 120 до 200 гс»). Для `cost_gm` нужна нормализация в гм.
3. **Навыки владения** (таблица «Для../Стоимость») = уровни владения оружием (основы/понимание/специалист) — это D113 «Владение оружием по профилям», отложено ранее.
4. **Оружейные навыки** (~107) — способности, привязанные к оружию, с требованиями владения; пересекаются с каталогом «Развития» (ОР).
5. **Модификаторы** (качество/материал/вес/размер) — отдельная подсистема изменения предмета, моделью не поддержана.
6. **Естественное оружие** — врождённое, не покупается; привязано к телу/расам.
7. **Единицы дистанции** — «ипари», «½ ипари», «от 2» — потребуют парсинга в числа.

Ссылки на мощность — формулами (не предрасчётом), чтобы будущие модификаторы оружия пересчитывались. |

## 8. Семантика «Силы удара/броска/выстрела» (дурабельное правило, не только выгрузка)

**Сила удара/броска/выстрела — НЕ урон оружия.** Это промежуточное значение действия:

```
Сила (характеристика) → + модификаторы атаки (сильный удар +2 от перегрузки, двуручный хват +1…) → Сила удара/броска/выстрела
Сила удара → + модификатор оружия (урон «{сила удара + 1}») → Урон
```

Пример (пользователь, 2026-08-11): персонаж Сила {3|1}, у оружия урон «{сила удара + 1}» рубящий; он применяет «Сильный удар» (+2 к силе удара от перегрузки) → Сила удара = {Сила}.modify(+2) = {3|2} → Урон = {Сила удара}.modify(+1) = {4|2} рубящего (4 огромных = 16 средних).

- Характеристика для всех трёх действий — **Сила** (strength). Ловкость ни при чём (мок-луки на dexterity — legacy, не переносить).
- **Модификаторы атаки** (сильный удар и т.п.) — фикция `action: { type:'strike', modifiers: [{ characteristic:'str', value:2, source:'перегрузка' }] }`. Экшнов в модели нет; `actionCharacteristic`-формула — крючок под них (оценка добавит их позже).
- **МКС** — «на сколько полных размеров сила удара превышает минимальную силу оружия» (пер-оружие мастерство, будущий заход «Владение оружием»). Сейчас игнорируем (R25), сырой текст с МКС — в свойствах предмета.

## 9. Курс валют — находка (2026-08-11)

Документ `docs/rule/battle/AI.html` противоречит сам себе: проза «1 гз = 100 гс, 1 гс = 100 гм» против сводной «Условная валюта» «1 гз = 10 гс = 100 гм». **Перекрёстные проверки по таблице магических кристаллов подтверждают 1 гз = 10 гс = 100 гм**: «3гс (х0.5)… 36гм (х1.2)» → 3 гс × 1.2 = 3.6 гс = 36 гм; «96гс (х3)… 11гз 52гм» → 96 гс × 1.2 = 115.2 гс = 11 гз 52 гм (при факторе 100 было бы 1105.2). Совпадает с кодом (`moneyBreakdownLabel`) и ТР. Проза документа ошибочна.

Данные документа: у каждого оружия таблица «Навыки владения» = столбцы **Для../Стоимость/Схожее/Напоминающее**.
Групп владения всего **4**: «Ближний бой», «Стрельба», «Многооборотная техника метания», «Безоборотная техника метания» (названия-варианты: «Многооборот. метание»/«Безоборотное метание»).
У каждого оружия своя лестница стоимостей уровней (Ближний бой: 1,2,3 … 3,5,7; Стрельба: 1,1 … 2,2,3,3,3; Метание: 1,2,3 и т.п.). «Схожее» — оружие с общим владением (Кинжал→Кинжал,Нож; Лук→Лук); «Напоминающее» — связанное (прогрессия).

**Модель:**
- **Способность «Владение оружием»** — `type: 'skill'`, `multiple: true`, домен = группа оружия (поле на предмете), зона `or`. Экземпляр = группа (напр. «Кинжалы и ножи»). Стоимость уровней экземпляра — из лестницы предмета группы (первое/каноническое оружие группы или общий минимум — решается на шаге C).
- **Грант** экземпляра → `characteristic_modify` на стат мастерства (ближний/дальний) **с маркером оружия** (per-weapon скоуп): не суммируется в базовый стат, отдаётся на тайл оружия.
- **Производные тайлы** оружий: «Мастерство ближнего/дальнего боя {оружие}» = база стата + общие навыки + бонус владения. В карточке (CombatSection) и редакторе.
- **«Схожее»/«Напоминающее»** — данные на предмете, механика переноса владения — будущий заход.
