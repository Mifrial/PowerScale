# Контекст: Модификаторы предметов (R29) — анализ и план захода

> Создан 2026-08-21. Статус: **заход 1 + экземпляры + статы + хвосты цены/keywords (2026-08-22)** — `applyStack`: импровизированное=0, множители craft-quality (`hard-to-craft`/`easy-to-craft`/`very-hard-to-craft`, носорог `price_scale`), keyword add/remove, мин. 2 ОД, проводник магии. Таблица качества доспеха — не в этом заходе.
> Источник данных: `docs/rule/mods/AI.html` (экспорт Google Docs, модификаторы). Нормализованный каталог: `docs/rule/mods/catalog.md`.

## 1. Что это за документ

Экспорт Google Docs с **каталогом модификаторов предметов** реальной системы правил: свойства, которые можно применить к оружию, щитам и доспехам при покупке (и, редко, к уже купленному предмету). Модификатор меняет цену предмета, несёт текстовое описание эффекта и структурные `ops` (вес, прочность, блок, защита, профили, сопротивления). Эффективный `ItemSpec` не хранится в инвентаре — пересчёт `ItemModifierService.applyStack`.

## 2. Данные и структура каталога

`docs/rule/mods/AI.html` — 143 строки таблиц. Секции:

| Секция | Применимо | Модификаторы |
|---|---|---|
| Связанные с модификаторами свойства оружия | конкретное оружие (посох импровизируемый, мечи «трудное в изготовлении», кнут «простое») | флаги качества |
| Модификаторы оружия ближнего боя | оружие | качество изделия/материала, вес, баланс |
| Уникальные модификаторы с признаком Посох | оружие с признаком «посох» | оковка (стальная/серебряная) |
| Модификаторы щитов | щиты | вес, качество, покрытие, материал |
| Модификаторы материала (общие) | оружие · щит · доспех | посеребрённое/серебряное/золотое |
| Модификаторы доспехов | доспехи | комплектация, вес, качество, утепление |
| Модификаторы материала (шкуры) | кожаное | кожа молниевой змеи/ската/саламандры/носорога |
| Таблица качества | доспехи (выбираемые свойства) | удобство, надёжность, крепкость |

**Ключевое решение каталога (2026-08-21):** записи, повторяющиеся в нескольких секциях (например «Тяжёлый» у щитов и «Утяжелённый» у оружия — по сути один модификатор), **схлопнуты в одну запись**. Один модификатор = **одно правило**. Группировка (`group_code`) для дедупликации **не нужна** — дублей в каталоге нет.

## 3. Применимость

Определяется **только по признакам предмета** (`rule.keywordIds` → коды keywords). Подтип (оружие/щит/доспех) — это тоже признак: `weapon`, `shield-item`, `armor-item`.

```ts
interface ItemModifierApplies {
  /** AND: предмет обязан иметь ВСЕ эти признаки. Пусто = не ограничивает. */
  keyword_all: string[];
  /** OR: предмет обязан иметь хотя бы один. Пусто = не ограничивает. */
  keyword_any: string[];
  /** AND-запрет: предмет НЕ должен иметь ни одного. */
  keyword_none: string[];
}
```

Пустое `keyword_all` + `keyword_any` = «всему». Примеры из каталога:

| Каталог | Признаки |
|---|---|
| Всему | `{ all: [], any: [] }` |
| Металлическому | `{ all: ['metal'] }` |
| Кожаному | `{ all: ['leather'] }` |
| Не двустороннее / не древковое | `{ none: ['double-ended'] }` + `{ none: ['polearm'] }` (`two-handed` ≠ двустороннее) |
| Металлическое и [оружие или щит] | `{ all: ['metal', 'weapon'] }` (щит несёт `weapon`) |
| Оружие с признаком Посох | `{ all: ['weapon', 'staff'] }` |

## 4. Цена

```ts
interface ItemModifierPrice {
  /** Множитель: 1.2 / 3 / 10 / 0.5 («/2») / 1/3 («/3»). null — не меняет цену множителем. */
  factor: number | null;
  /** Слагаемое в гм: «+25гс»=+250, «+50гз»=+5000, «+30гз»=+3000. Отрицательное — уменьшение НА величину. */
  add_gm: number | null;
  /** Слагаемое на 100 грамм: «+10гс на 100 грамм» = +100 гм/100г. */
  add_gm_per_100g: number | null;
  /** Нижний порог итоговой цены в гм: «10 гз»=1000, «100 гз»=10000. */
  min_final_gm: number | null;
  /** Override полей при совпадении keyword предмета (порядок: armor-item, shield-item, weapon). */
  by_keyword?: Record<string, Partial<ItemModifierPrice>>;
}
```

Формула (по **реальному** весу предмета — после применённых ранее модификаторов):

```
cost = round(base * factor)
     + add_gm
     + round(realWeightGrams / 100) * add_gm_per_100g
cost = max(cost, min_final_gm)   // если задан
```

- Множитель и деление — единым `factor` (деление = `1/n`).
- `realWeightGrams = round(weightDimensional.toNumber() * 1000)`, где `weightDimensional.toNumber()` = `floor(base × 2^size)`. Если вес отсутствует — слагаемое 0.
- `min_final_gm` применяется после всех операций.
- Нет ни одного ценового поля — модификатор цену не меняет.

## 5. Инвентарная идентичность

Модифицированная копия предмета — **отдельная строка инвентаря**.

```ts
// InventoryItem
modifierRuleIds: string[];   // дефолт [] — не модифицированный
```

Идентичность стекуемых = `ruleId` (quantity). Снаряжение (оружие/щит/доспех) — **экземпляры**: каждая покупка = новая строка `quantity: 1`; модификаторы и экипировка на `item.id`. Exclusive-тип: второй модификатор того же `type_code` заменяет первый.

## 8. Открытые вопросы (если появятся по ходу)

- Вес предмета без признака веса (`weight: null`) — `add_gm_per_100g` считаем 0.
- Порядок применения нескольких модификаторов к одному предмету — линейно по `modifierRuleIds`: на шаге сначала ops (вес и прочие поля), потом цена; `add_gm_per_100g` считает от веса **после** ops этого шага (выход шага = база следующего: и цена, и вес). Не от каталожного веса.
- «Применимо: оружие» = `all: ['weapon']` + `none: ['shield-item']` (щиты несут `weapon`).
- Таблица качества доспеха и уникальные свойства изготовления — не покупаемые `item_modifier` (keywords на предметах / будущий заход).
- Коды типов без `mod-type-`. Тип «Вес» — `item-weight` (`weight` занят характеристикой). Коды модификаторов без префикса `mod-`.
