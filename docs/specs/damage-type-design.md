# Тип урона

> Дата: 2026-08-23. Статус: **спека + каталог + хуки v1 + клик-атака (apply/attack)**. Увечье вызывает фазу `injury`.

## Зачем

`damage_type` больше не метка. У типа есть склонения и список карточек с механиками. Механики версионируются (`code@version`) и вешаются на **фазы**: увечье / применение урона / атака.

## Спека

```ts
interface DamageTypeSpec {
  type: 'damage_type'
  forms: { genitive: string; dative: string }
  attached_rule_codes: string[]  // карточки с mechanicId, не коды механик
  defense_ignored?: boolean      // защита не складывается в сопротивление этому типу
}
```

`mechanicId` на самом типе не используем.

## Надёжность

Одна механика (ТР §15 п.22, в коде): набранные **X РУ атаки** сами игнорируют всё с надёжностью **≤ X** — без оплаты РУ и без диалога. Типы с хуком фазы `attack` (`pay_sr_vs_reliability`). Видимость сопротивления/расчёта по ролям — позже.

## v1 (выгрузка)

| Тип | injury | apply | attack |
| --- | --- | --- | --- |
| Колющий | +floor(РУ/2) к сложности | истощение → рана ×1 | РУ vs надёжность |
| Рубящий | помеха на проверку увечья | истощение → рана ×2 | РУ vs надёжность |
| Дробящий | — | истощение → стан; KO при РУ≥6 или урон≥Стойкость | — |
| Режущий | — | урон как раны по размеру цели | РУ vs надёжность |

Огонь/яды — метки без хуков, пока нет выгрузки.
