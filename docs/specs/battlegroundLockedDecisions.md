# Battleground — зафиксированные решения

> Канон обсуждения 2026-08-31. Не код. При расхождении с более старыми абзацами
> implementation/idea-планов верить этому файлу.
> Следующий канон ТР: `docs/tr/battleground-system.md` (`DEC-069`, REQUIREMENT, не код).

## Порядок работ

1. Расширить ТР (`battleground-system.md`, REQUIREMENT / OPEN / BACKLOG).
2. PHP/MySQL по логической модели.
3. Frontend против того же контракта (mock совместим с API).

Код battleground не начинать до ТР. DEC-026 не отменяется: абстрактное движение
уже есть; сцена — отдельный контур.

## Сцены, шаблоны, копии

- `SceneTemplate` — личный шаблон автора; в первом релизе не шарится.
- `GameScene` — независимый snapshot шаблона внутри игры (не live-ссылка).
- Дубль `GameScene` — снова независимый экземпляр, новые ID токенов.
- Ссылки на акторов (персонаж/NPC) при копировании сохраняются.
- Токены шаблона — декоратив и служебные; PC/NPC кладёт ведущий из состава игры.
- У игры несколько сцен enabled/disabled и ровно одна `current`.
- `BattlemapView` — полноэкранный режим; не отдельная сущность хранения.
- Состояние сцены живёт с игрой; reload без потери позиций и knowledge.

## Права

- Правит сцену только ведущий (в т.ч. активную `current`).
- Игрок двигает принадлежащего ему персонажа и действует за разрешённого.
- Движение и атаки — доменные команды, не «только drag в UI».
- Сервер авторизует; клиентская fog-маска не защита скрытых данных.
- Ход игрока и правка ведущего заранее не блокируют друг друга.
- Команда несёт `sceneVersion`; stale — отказ, re-read, повтор с явным UI.

## Подложка и assets

- Подложка — asset с привязкой к логическим координатам пространства.
- У каждого `SceneSpace` своя подложка и привязка. Пиксели ≠ ипари.
- Слой **ground cover** (трава/песок/снег/доски): отдельная заливка пола, не occupancy
  и не `TerrainArea`. Кисть материалов не первый срез; в срезе — default пространства
  + подложка. Крыша/настил — своя текстура опоры, не этот слой.
- Подложка у клиента может быть; скрытие — визуально. Тайлы не секрет.
- Shared immutable `assetId`; копия сцены копирует ссылки, не байты.
- Удаление asset — archive, не hard-delete из чужих сцен.
- Mock: не data URL картинок; контракт как у бэка.

## Мир карты и оболочка

- Мир карты целиком **WebGL** (лес, река, токены, fog, путь, facing, гизмо).
- Оболочка **Vue** (чат, панель, диалоги, tabs пространств).
- SVG на карте не используем. Не два пайплайна токена (лес GL / поляна SVG).
- Редактор не хранит флаг «это GL». Инструменты: кисть дерева, стена, токен.
- Своя картинка токена — `assetId` листа / override, слой токенов.

## Пространства и опоры

- `SceneSpace` — 2D-карта (поляна; этаж дома). Не «этаж всей локации».
- Поляна **содержит** дом (`Enclosure`). Этажи 1/2 — только интерьер дома.
- Enclosure — только если внутри **другая карта**. Двор, кольцо частокола, атриум:
  стены/забор на **том же** space, середина проходима, без заливки пятна как объёма.
- Крыша и мост — `SupportSurface` на поляне, не вкладки.
- Позиция: `spaceId`, xy, `supportId`, `altitude`.
- Настил — сплошная плита: с моста не провалиться, потому что под ним дешевле.
- Сквозь стойку по полу нельзя.
- Вкладки UI — пространства, не каждый настил.

## Геометрия, facing, дистанция

- Координаты сцены — **целые** в единицах `SceneResolution`. Не float JS.
- Не `DimensionalNumber.toNumber()` для пространства (округляет вниз к нулю).
- Шаг перемещения, размер токена и занимаемая область — независимы.
- Footprint: круг, эллипс, прямоугольник (AABB-стены как полосы с толщиной).
- Произвольный polygon стен — BACKLOG; форма расширяема.
- Метрика расстояния — **евклид** в единицах сцены, не Манхэттен и не клетки.
- Facing: 0–359°, 0 = вверх экрана, по часовой.
- Секторы относительно facing защитника: front и rear по ±45°, иначе flank.
- Visual grid — помощь вводу, не единица мира.

## Движение

- Рёбра: `walk` / `climb` / `vault` / `drop`; нет ребра — нельзя.
- Объекты сами порождают рёбра. Планировщик не сходит с опоры без ребра.
- Неоднозначный клик — выбор (по мосту / под мостом; приземлиться / пролететь).
- Протискивание — режим движения, `squeezeMovementProfile`, без требования навыка.
- `freeTurn` ≤90° после каждого успешного действия движения; planner учитывает.
- Поворот до хода или >90° — отдельная `turn`.
- Planner сам выбирает промежуточный facing; итог — направление последнего сегмента.
- Клик: конечная позиция; polyline + checkpoint ОД; бэк проверяет тот же путь.
- На save: навмеш **на каждую опору**. Клик → иерархический A* + воронка → полилиния
  в единицах сцены (не клетки occupancy). Сервер: та же полилиния + точный круг
  vs препятствия. Навмеш не заменяет vis-столбик.
- Squeeze/полёт — существующий action/movement контур (`front+up` уже есть).
- Pathfinding в поставке (иерархический A* / navmesh), не «только клик без маршрута».
- Collision с частичным проходом: положительная дистанция сохраняется, ОД не возвращаются.

## Порталы и проёмы

- Проём — закрываемый блокер (`open`/`closed`). Закрыт — стена (ход и vis).
- Портал (смена сетки) — только если цель другое пространство. Калитка двора:
  блокер, `portalId = 0`. Дверь в enclosure: блокер **и** парные записи портала.
- Смена пространства — opening с порталом (дверь, лестница, окно, телепорт).
- Описание: исходное и целевое пространство, области входа/выхода, стоимость.
- Связь: paired / free; направление: bidirectional или нет (явно).
- Дверь/окно enclosure: редактор всегда пишет **пару** записей (снаружи и внутри).
  Телепорт — free, не обязан совпадать геометрически.
- Vis сквозь проём и walk через проём — разные флаги (окно: видеть, не всегда лезть).
- Открытый проём = vis-портал в сетку другого пространства, не дырка на одной сетке.
- Таблица проёмов на пространстве обязательна (target, области, vis/walk, open/closed).
- В клетке occupancy — `portalId` (**u8**, `0` = нет). Все клетки одного порога — один id.
  255 — число **записей** (дверей/окон), не клеток и не камари. Сетка vis = `occupancyCell`,
  не `SceneResolution`.
- Штамп дома на родительской сетке: footprint как непрозрачный объём, затем вырез порогов.
  Пустая «середина дома» на сетке поляны запрещена (коробка с интерьером).
  Кольцо стен без другой карты — не заливать середину.
- Смена `spaceId`+xy, когда **центр** токена пересекает плоскость порога. Vis и атака
  через открытый проём работают **без** этой смены (стоя на улице бьёшь в зал и наоборот).
- Цепочка vis-порталов — **бюджет** DDA/рендера (ориентир 2–4), не правило мира.
- **Картинка:** чужое пространство рисуется только в силуэте проёма (stencil/scissor),
  не весь этаж поверх дома и не «только вкладка». Токены и мебель того пространства
  рисуются в том же вырезе, тем же world-pass, что и на вкладке этого пространства.
  Глубина картинки = глубина vis (ориентир 2–4). В вырезе окна на лес — LOD/cull
  по frustum проёма, не второй полный проход 40k деревьев.
  Несколько проёмов в одно пространство: **один** pass, stencil = объединение
  силуэтов. Вложенный проём — рекурсия с тем же правилом.
  Закрытый проём = глухая стена: нет vis, нет stencil. Стекло (видеть закрытым) —
  не первый срез, только open/closed.
  Сверху в полёте: видна крыша-опора, не комнаты. Люк/разрушенная крыша — проём.
  Расчёт vis и картинка совпадают: луч прошёл — в дырке видно то пространство.

## Полёт

- В первой поставке (сопартиец-летун).
- 1 ОД = 1 взмах; за взмах до шага по горизонтали и до шага по вертикали сразу.
- Число взмахов: `max(ceil(Δh/шаг), ceil(Δv/шаг))`.
- Высота опоры: default типа + override; крыша = сумма этажей enclosure.
- Datum пространства: земля = 0.
- В воздухе: `supportId` пустой, `altitude` свободный. Посадка выравнивает высоту.
- Сквозь объём дома и плиту моста нельзя; в окно — проём.
- UI полёта — клик по карте, не 3D-курсор.

## Координаты и две сетки

- `SceneResolution` на `GameScene`, default `2^-6` ипари — точные координаты.
  При default: `1 ипари = 64` единицы; шаг `−1` = 32; `1↓5` = 2.
- Не абсолютный предел правил: сцена может быть мельче (например `2^-7`).
- `occupancyCell` отдельно, default **¼ ипари** — vis, свет, cover.
- Ход и коллизия — точные круги/footprint, не ячейки occupancy.
- Потолок числа клеток occupancy (ориентир ≤1024²), иначе ячейка укрупняется.
- Типичная карта ~40×40; 200×200 — жёсткий запас; ~200 актёров.

## Occupancy-столбик

- Ячейка: до **двух** непрозрачных интервалов + одна крона `[lo,hi]` + illumination.
- Границы интервалов — **u8** (256 квантов). Datum и потолок Z — у каждого
  `SceneSpace`. Если высота не влезает — укрупнить `zQuantum` этой сетки, не u16.
- Квант Z столбика = `occupancyCell`, пока не задан отдельно.
- Окно: подоконник + перемычка. Закрытая дверь: один интервал на всю высоту.
- Открытая дверь/окно: патч столбика + тот же `portalId`; лес не перештамповывать.
- Штамп vis: клетка закрыта, если overlap с геометрией ≥½ ширины **или** ≥½ высоты
  клетки. Круг — vs эта клетка, не AABB всего дерева.
- Несколько объектов: max низ, кроны сливаются.
- Один blob на пространство, один и тот же на клиенте и сервере, штамп при save.
- Клетка **8 байт**: solid0 lo/hi, solid1 lo/hi, крона lo/hi, illumination, portalId.
  `lo=hi=0` — слота нет (нулевой толщины нет; пол хотя бы `0,1` кванта).
  Illumination: 255 ярко по умолчанию, патч факела/тьмы. Cover в клетке нет.
- Header blob (один на пространство): magic, **version раскладки** (сейчас 1, не
  `sceneVersion`), width/height в клетках, origin и размер клетки в единицах сцены,
  zQuantum; клетки little-endian, `index = y * width + x`. Таблица проёмов не в blob.
- Факел/дверь — патч куска, не перештамповка леса.

## Видимость, свет, укрытие (цель vs срез)

- `mapVis = LOS(столбики, высота) ∧ (illumination ∨ чувство_игнорирует_свет)`.
- Fog/explored: не имя «Зрение», а LOS-чувство с **лучшим радиусом** у персонажа
  (точное значение чувства, не мод Внимательности).
- Прочие чувства (слух, нюх, …): не красят карту; позже только обнаружение токенов.
- Нет токена выбранного персонажа на `current` сцене → нет динамической vis.
- Illumination по умолчанию везде светло. Поле в сетке есть сразу.
- Cover: позже доля силуэта с той же сетки; сейчас **0 с сервера**, не с клиента.
- Первый срез: без UI факелов и без расчёта cover. Формат сетки не ломать.
- Не плодить второй формат «сцена без сетки».
- Клиент рисует fog (GPU/WASM, ключи вдоль своего маршрута, бюджет ≤100 мс).
- Сервер фильтрует токены и считает LOS атаки. Не visibility polygon как канон.
- PHP: не fog 60 FPS, не 40k кругов, не лес в SSE. На ход — сотни DDA по акторам.
- Глобальный visibility graph на всех стволах не строить.
- Пошагово: почти всегда один движущийся; чужой ход не пересобирает лес.
- Области: `visible` / `explored` / `unknown`. Knowledge per player.
- `lastSeen` — ghost позиции без identity; GM hide снимает lastSeen.
- Ручной override ведущего: всем / только GM / выбранным игрокам / открытая область.
- HTTP команды + SSE события; optimistic `sceneVersion`.

## Лес и масштаб

- ~40k деревьев, ~10 прототипов — `InstanceLayer`, не `Token[]`.
- Рендер: instancing + LOD (на полном отъезде не 40k спрайтов).
- Анимация кроны: время + фаза instance, не 40k таймеров.
- Кисть леса в редакторе.
- Путь: иерархический A* / навмеш при save + воронка; проверка точным кругом.
- Круги не отменяем.

## Дерево, местность, пресеты

- Ствол непроходим, режет LOS если луч попал (точная геометрия хода).
- Крона — плита: по земле ход обычный; сквозь листву полёт/`climb` — difficult.
- Луч целиком под кроной крону игнорирует; пересекающий плиту — блок.
- Река: полилиния, ширина/глубина в вершинах, течение; мост — настил, walk с берега.
- Озеро: водное тело, течение 0.
- Стол/стойка: вырез из земли + верх + climb по периметру.
- Забор: blocksMovement без blocksVision. Занавес — наоборот.
- `TerrainArea`: грязь, лёд, щебень, трава (не путать с vis-столбиком).
- Яма/люк: проём вниз. Приставная лестница: climb без смены пространства.
- Колодец/яма без нижней карты: непроходимая яма на этой сетке, **без** vis-портала.
  Погреб — только если ведущий завёл space и связал люк.
- Лестница в доме: difficult + opening между пространствами.
- Причал/зубцы: настилы. Дом на дереве: enclosure/опора с высотой.
- Обрыв: вверх walk нет, вниз drop.
- Корабль-в-движении, подводный бой — BACKLOG.
- Cover calculator и Foundry-light — BACKLOG; слоты в сетке уже есть.

## Бой

- Exact spatial distance с сцены, не клиентский `distanceIpari: number`.
- Дверь/окно: дальность — прямой 3D-отрезок в укладке enclosure в родителя, если
  отрезок пересекает проём. Стену навылет нет (нет LOS). Телепорт: сумма до A + от B.
- LOS-block в релизе; cover=0.
- `flank` per strike, defender facing; `flank`+`rear` → combat `flank=true`.
- Wide: все цели или отказ целиком. `max_strikes` ≠ `max_targets`.
- Процедура боя не доверяет вручную введённым дистанции/укрытию/флангу, если сцена есть.

## Вертикальный срез готовности

1. Открыть игру с сохранённым battleground.
2. Видеть доступные пространства и токены.
3. Выбрать своего персонажа.
4. Переместить его с корректным ОД (в т.ч. опора/проём).
5. Атака: дистанция, LOS, фланг из сцены.
6. Последствия в оверлее и чате.
7. Reload без потери позиции и knowledge.

## Явно не цель сейчас

- Произвольный polygon стен.
- Совместное редактирование, realtime-курсор.
- Секретные тайлы подложки.
- Воксельный occupancy, плоский «бит кроны».
- vis = перебор кругов в радиусе чувства.
- Гибрид SVG+WebGL на карте.
- UI факелов, расчёт cover, обнаружение токенами слухом/нюхом.
- Корабль-платформа, подводный бой, шаринг шаблонов.
