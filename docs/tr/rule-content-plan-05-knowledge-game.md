## 1. Runtime-канон (узкая выжимка)

Ситуация запуска: **тип** (`fieldCode`) + **слоты ситуации** (код и/или текст) + **полоса 1–3** + **базовая сложность** (мастер).

```text
уровень = max(точный матч, близкий вид); иначе 0
нехватка = max(0, полоса − уровень)
сложность' = та же база, size увеличен на нехватка
```

Точный матч: тот же тип; если **хотя бы у одной** стороны слота есть код — только код с кодом; иначе trim текста. Код vs голый текст — не точный матч и не близость. Близость на точный матч не вешать (−1 только чужой вид). Точный слабый не бьёт более сильный близкий (`max` по экземплярам).

Близкий вид только у слота `species` (`physiology`, `diseases` и ворота практики по виду): оба **кода** вида есть, у карт общий keyword из `BODY_TYPE_KNOWLEDGE_KEYWORDS` → уровень экземпляра − 1 (не ниже 0). Свободный текст не шарится. Регион не шарится.

Пул — **Память**. Override характеристики **запрещён**. Уровни знания пул не трогают. Жетон концентрации на Интеллект уже матчится — не дублировать.

Нет листа / нет экземпляров → уровень 0, нехватка = полоса.

### 1.1 Полнота ответа (не выдумывать «критическую 6»)

Канон: успех при нехватке > 0 — неполный ответ, «пока не выпала 6 по правилу 6 и 1».

В движке `six_one_rule`: **1 → +успех, грань 6 → −успех**. Грань 6 успех не улучшает. Кодировать `hadSix === полный ответ` **нельзя**.

В этом срезе:

| Бросок | Нехватка | Итог |
| --- | --- | --- |
| провал | любая | провал (не «неполный успех») |
| успех | 0 | полный |
| успех | > 0 | неполный |

«Внезапный полный ответ с грани 6» — OPEN, не этот код. После среза строка канона в плане-04 не переписывается, пока не решите иначе.

Болезни: при **успехе**, если эффективная `physiology` цели < 1 — ответ неполный (название без посадки в тело), даже при нехватке полосы 0.

### 1.2 Сложность'

`{ base, size: size + shortage }`. Не `DimensionalNumber.withSize`: он пересчитывает базу и `{2|0}` → `{1|1}` **не** тяжелее. `{2|0}` + 1 размер = `{2|1}`.

## 2. Границы

Входят:

1. Сервис эффективного уровня / нехватки / ворот практики / бонуса защиты.
2. Карточка `check-knowledge`.
3. Запуск соло в `CheckLaunchDialog` + дочерний UI ситуации; подсказка уровня, сложности', полноты.
4. `zaschita-ot-zakona`: ситуационный `check_advantage` величиной **уровень навыка**, если тип `laws` и регион ситуации точно совпал с экземпляром `znanie`/`laws`.
5. Покупка защиты: `parent_knowledge_field` реально фильтрует родителя.
6. Ворота практики **как функция** + тесты. Кнопок ухода/хирургии/варки/сбора/питания нет.
7. `contentNote` шаблонов и защиты сузить, когда запуск работает.

Не входят: `5.3` раны; перевязка/зажим как действия; таблицы операций и фармации; книжный червь; PHP; новый `Requirement.has_knowledge` на покупке практики; Hit/SpellCast; освещение; pairwise-знание; `smertonosnye-udary`; `obnaruzhenie-dobavok` / `chtenie-sledov`.

Перевязка / первая помощь / спорая в `practiceApplies` **не перечислять** (ворота им не нужны). Не возвращать `true` «на всякий случай».

## 3. Этапы

### A — матч (Character)

Класс рядом с `KnowledgeInstanceService` (например `KnowledgeCheckService`), синглтон + реэкспорт `init.ts`.

Ситуация — plain DTO: `fieldCode`, слоты, полоса, опционально вид цели для болезней/практики и регион места.

- `effectiveLevel(abilities, fieldCode, slots, rules)` → 0..3;
- `shortage(level, band)`;
- `raisedDifficulty(base, shortage)` — §1.2;
- `answerCompleteness({ success, shortage, fieldCode, physiologyLevel })` → `fail | full | incomplete`;
- `lawDefenseDelta(abilities, fieldCode, regionSlot)` → 0 или уровень `zaschita-ot-zakona`;
- `practiceApplies(code, abilities, situation, rules)` только для `ukhod`, `khirurgiya`, `farmatsiya`, `poisk-trav`, `pitanie` (иной код → `false`):
  - уход / хирургия / питание — `physiology` цели ≥ 1 (близкий вид — да);
  - сбор — `plants` региона ≥ 1;
  - фармация — **оба**: `physiology` пациента ≥ 1 **и** `plants` региона ингредиента ≥ 1.
  Именованный курс ухода / варка «под болезнь» (`diseases` или назначение) в эту функцию **не** входят.

Близкий вид: keyword карт `type: 'species'`, пересечение с `BODY_TYPE_KNOWLEDGE_KEYWORDS`.

Тесты на сервис, без mount UI.

### B — карточка проверки (Rule)

`check-knowledge` в `mockChecks`: родитель `check-simple`, `characteristic_code: 'memory'`, `allow_characteristic_override` не ставить (пул зафиксирован), `difficulty_input: ask`, **`allowed_modes: 'solo'`** (канон — против DC, не совместная). Код в `CHECK_CODES`. Id свободный (не 9001–9039).

`CheckLaunchService` подхватит сам: любой `type: 'check'` кроме удара/инициативы/увечья.

### C — запуск (Game)

Только если **код запуска** — `check-knowledge` (дети появятся позже: тогда «в предках есть `check-knowledge`»). Не на корне `check-simple`.

Дочерний компонент полей: тип + слот (те же справочники листа), полоса 1–3 (дефолт 1). Мастер задаёт **базу** DC в `askBase`/`askSize`; в бросок уходит сложность'. Не вводить уже поднятую DC в поля — иначе двойной подъём.

Это не `check-intellect` (голый пул Интеллекта без ситуации) и не `check-memory` без слотов. Карточка знания — отдельный код.

Бонус защиты — в список преимуществ запуска (как гранты `check_advantage`), не руками в `.vue`.

После броска: полнота из `result.check.passed` + нехватка (+ физиология для болезней), в текст чата.

Диалог и так большой: логика DC/уровня/бонуса — сервис, не computed-простыня в setup.

### D — защита от закона

Не вечный грант на все проверки. `lawDefenseDelta` → `check_advantage` amount = уровень, `source_code` карточки защиты, только эта ситуация.

Редактор **и** `CharacterBuildService.setAbilityLevel`: синтезированный родитель `znanie` **и** `parent_knowledge_field` (есть экземпляр с `fieldCode: 'laws'`). Сейчас `has_ability znanie` смотрит `abilityLevels` без типа — любая физиология проходит. Не размазывать фильтр по `RequirementEvaluator.has_ability`. `parent_ability_code: 'znanie'` не убирать: дерево в «Развитии», не multiple-домен.

Навык защиты **не** multiple: один уровень на персонажа, якоря — экземпляры `znanie`/`laws`.

### E — ворота практики без кнопок

Только §A `practiceApplies` + тесты. Медицинская строка очереди не закрывается.

## 4. Тестовый минимум

- точный код вида; trim текстов; код vs текст без кода — не матч; разные типы на одном виде не суммируются;
- близкий `humanoid` −1; без кода вида — 0 близости; регион не шарится; точный матч без −1;
- `{2|0}` + нехватка 1 → `{2|1}`, не `{1|1}`;
- провал + нехватка → провал; успех + нехватка 0 → полный; успех + нехватка > 0 → неполный;
- болезни: успех, physiology 0 → неполный;
- защита: +уровень только `laws` + известный регион;
- `practiceApplies('ukhod')` без physiology → false; `farmatsiya` без растений региона → false; коды перевязки в функции нет;
- покупка `zaschita-ot-zakona` при одном `znanie`/`physiology` закрыта; при `laws` открыта.
