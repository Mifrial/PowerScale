# План Game 21 — инициатива

**Статус:** инициатива в PHP сделана. `BACKEND_OPEN`. Suite `game` по `GameInitiativeMysqlTest` зелёный. Нарезка — [`game-roadmap.md`](game-roadmap.md) G21. Канон отсутствия экземпляра — [`rule-system.md`](rule-system.md). Признак — [`rule-plan-04.md`](rule-plan-04.md): JSON-ключ `initiative`, геттер `CheckSpec::isInitiative()`; каталог карточек не наполнен; две карточки с истиной в одном срезе Rule не запрещает. Проверка — [`game-plan-18.md`](game-plan-18.md): срез ревизии, `CheckSpec`, `IMechanicRolls` через `GameCheckRoll::throwCheck`. Бой — [`game-plan-12.md`](game-plan-12.md): строка `game_battle` текущей сессии; `endBattle` удаляет эту строку и сессию не останавливает. Границы — [`architecture.md`](architecture.md). Стандарты — [`php-coding-standards.md`](php-coding-standards.md).

Цель: один заход. У открытого боя появляется порядок хода. Game в срезе ревизии игры находит живые `CheckSpec` с `isInitiative()`. Ровно одна такая карточка считается тем же путём, что G18, по разу на каждого участника состава этого боя. Ноль или больше одной — отказ, порядок не пишется. Код карточки в Game не зашивается. Клиент готовый порядок не присылает. Порядок хранит бой, не лист и не таблица сессии. `endBattle` порядок снимает вместе со строкой боя и сессию не останавливает.

Зависимость — G12, G18 и шаг 15 Rule. Признак в коде есть: `CheckSpec::isInitiative()`. Свой бросок и строка кода правила не заводятся. Запись урона в лист, C11, G22, DOT, каст и сцена не входят.

## Физическая схема

Новой таблицы нет. На `game_battle` появляется один необязательный `JsonField` `turn_order`. Обязательное поле сломало бы `GameBattleRepository::add`: он пишет только `session_id` и `state_version`. `null` — порядок ещё не записан. Записанное значение — список участников в порядке хода. У кого был `throwCheck`: `type`, `id`, `difficulty`, `roll`, `success`, `rating`. Один новый, вставленный сменой состава без броска, хранит `type` и `id`, а эти четыре поля — `null`. Кода правила в колонке нет. Лист, `game_session`, `game_check` и `game_process` колонками не растут.

`endBattle` по-прежнему удаляет строку боя. Отдельного снятия JSON не требуется: строки нет — порядка нет. Журнал идемпотентности — уже существующая `game_battle_command` и `GameBattleCommandRepository`. У пары (`game_id`, ключ) unique один на старт, состав, конец и эту команду. Stop сессии по-прежнему удаляет бои этой сессии и тем же удалением снимает порядок. Отдельной миграции нет: тесты ставят схему через `GameBattleSchema::install`.

## Сверка G12 и G18

- `GameBattleTable` сейчас: `session_id`, `state_version`. Состава и порядка в строке боя нет. Состав — `game_battle_participant`.
- `GameBattles` уже держит шесть зависимостей конструктора. Седьмая запрещена. `IGameSessionRoster` используется только в `mutator()`. `start` и `end` подписи не меняют и бросок не вызывают. `setRoster` подпись HTTP не меняет; при уже записанном порядке бросок новых участников идёт внутри его текущей транзакции.
- `GameBattleMutator::end` удаляет бой после сверки `expectedVersion`. Сессию не трогает. Этот метод проверку не вызывает.
- `GameBattleMutator::setRoster` заменяет состав целиком и увеличивает версию. Отдельной команды «добавить участника» нет. Порядок метод сейчас не читает. Сравнение старого и нового списков — в этом заходе.
- `ICharacterRuleSlices::get(GameRecord::getSpaceId(), GameRecord::getRulesRevision())` уже отдаёт срез. `getLiveRules()` — живые правила в порядке состава. `findLive` и tombstone G21 для перебора не подменяют список: снятый code в `getLiveRules()` не входит.
- `GameCheckRoll::throwCheck` уже считает трудность, бросок и успех. Кубы — `IMechanicRolls::roll`, успех — `IMechanicRolls::rate`. Второй вызов порта и своя формула кубов не пишутся.
- `GameCheckRoll::checkOf` живой `CheckSpec` с `isInitiative()` не отвергает: отказ «чужого шага» — `isHitCheck`, `isConcentrationToken`, `isWillpower`, `isUnstableCheck` и вид `from_state`. Признак инициативы в этот фильтр не добавляется.
- `declareCheck` и `proposeCheck` этот шаг не вызываются. Строка `game_check` и process не открываются.
- `ICharacterActualMutations::apply` и `GameNpcRepository::replaceVersion` не вызываются. Character модуль Game не импортирует.
- Поле `initiative` спеки характеристики — другой тип. G21 его не читает.

## Зафиксировано (модель и права)

**Поиск карточки.** Метод на `GameCheckRoll`: срез уже лежит в этом классе. Отдельный `ICharacterRuleSlices` в фасаде инициативы раздул бы конструктор сверх шести зависимостей. Берутся элементы `getLiveRules()`, у которых spec не битая и `getSpec()` — `CheckSpec` с `isInitiative() === true`. Битая версия и чужой тип в счёт не входят. Ровно одна — её `getCode()` уходит в `throwCheck`. Ноль или две и больше — `GAME_INVALID` до броска, `turn_order` остаётся пустым, версия боя не растёт. Строка `check-initiative` и любой другой литерал кода правила в PHP не появляются.

**Кого считать.** Участники текущего состава этого боя, в порядке строк состава. Персонаж снимка сессии и NPC этой игры — те же границы, что у старта боя. Пустой состав — `GAME_INVALID`, порядок не пишется. Чужой id в составе к этому шагу уже не доходит: его отсекает запись состава.

**Тот же путь.** На каждого участника один `GameCheckRoll::throwCheck` с потоком `solo`, листом этого участника и `$asked = null`. Персонаж — `GameCheckRoll::characterSheet`. NPC — `GameNpcRepository::getById`, затем массив `sheet` внутри `getVersion()`: `characterSheet` NPC не читает, это делает `GameChecks` у проверки. Режим карточки, вид трудности и пул остаются правилами `throwCheck`: `solo` или `both`; вид `none`. Карточка `joint`, `ask`, `from_state` или с признаком удара, каста, жетона, воли, неустойчивости даёт `GAME_INVALID` из того же метода. Отказ любого участника откатывает команду: порядок не пишется, лист прежний. Трудность и кубы клиент не присылает.

**Порядок.** После всех бросков список сортируется по убыванию `roll.base` итога `throwCheck`. Равные успехи сохраняют порядок состава. Это не второй расчёт и не сравнение с защитой. `success` и `rating` в запись попадают как вернул `throwCheck`, на место в списке не влияют.

**Запись.** В той же транзакции, что команда: JSON в строку этого боя и `state_version` на 1. Повторная команда с новым ключом заменяет уже записанный порядок и снова увеличивает версию. Чужой `expectedVersion` — `GameBattleConflictException` (`GAME_CONFLICT`), бросок не сохраняется. Повтор с тем же ключом и тем же телом возвращает итог из `game_battle_command` и `throwCheck` второй раз не вызывает. Тот же ключ с другим телом — тот же `GAME_CONFLICT`. Сверка версии идёт до `throwCheck`.

**Смена состава при уже записанном порядке.** `setBattleRoster` по-прежнему присылает весь новый список. Сервер сравнивает его с текущим составом. Кто остался, сохраняет взаимный порядок. Кого в новом списке нет, из порядка вычёркивается, место схлопывается. Кто появился, в том числе после выхода, идёт в конец; старое место не возвращается. Один новый ставится в конец без броска: в его записи нет итога проверки. Ответ `game.setBattleRoster` при этом дописывает уже собранный `order` к текущему `{ battleId, version, ended }`. Пока колонка была пуста, ключ `order` в ответ не добавляется: тест `GameBattleMysqlTest` сверяет `version` и `battleId`, форма `opened()` остаётся прежней. Двое и больше новых проходят `throwCheck` только между собой, тем же поиском одной карточки `isInitiative()`. Их кусок сортируется как полный порядок и целиком ставится в конец. Ноль карточек или больше одной, либо отказ `throwCheck` у любого нового, откатывает команду: ни состав, ни порядок не меняются. Пока `turn_order` пуст, смена состава список только заменяет и никого не проверяет.

**Конец боя.** `endBattle` сессию не останавливает. Порядок исчезает, потому что удаляется строка боя. Соседний бой той же сессии свой `turn_order` не теряет. Новый бой порядок предыдущего не копирует: колонка у новой строки пустая, пока команда инициативы её не запишет.

**Чего шаг не делает.** Не передаёт ход и не продолжает шкалу после `endBattle`. Не пишет лист, `game_check` и process. Не меняет ответ `game.getBattleSheets`. Не заводит механику: кубы уже считает `IMechanicRolls` внутри `throwCheck`. Не считает урон, DOT, каст и сцену. Не наполняет каталог карточек. Не читает запасную инициативу характеристики.

## Что даёт этот заход

Команда инициативы открытого боя возвращает `battleId`, новую версию боя и порядок участников. У каждой записи — итог той же проверки, что считает G18. Лист и сессия не меняются. `endBattle` снимает бой вместе с порядком и оставляет сессию запущенной.

## Что не закрыто

- Запись урона в лист, C11 и G22.
- Передача хода и продолжение той же шкалы после `endBattle`. Вставка в конец через смену состава — этот заход.
- DOT, каст, сцена.
- Наполнение каталога карточек и чтение `initiative` спеки характеристики.
- `personalNotes`.

## Точки кода

Старые планы не переписываются. Новых портов нет. `GameBattles::start` и `GameBattles::end`, `declareCheck`, `proposeCheck`, `GameCheckRoll::throwCheck` и `isLaterStep` не меняются. `GameBattles::setRoster` передаёт старый и новый состав в запись порядка: без этого уже записанный порядок не узнает, кто вышел и кто встал в конец. Пишет это `GameBattleMutator`: у него пять зависимостей, шестая — тот же расчёт, что у команды инициативы. `IGameSessionRoster` в конструкторе `GameBattles` только ради mutator; фабрика собирает mutator снаружи и этот аргумент заменяет, чтобы у `GameBattles` не стало семь зависимостей. `IGameBattles` и `GameBattleHttp` не растут. Character Game не импортирует.

- `GameBattleTable` — необязательная колонка `turn_order`. Без неё бой порядок не хранит: ни лист, ни `game_session` этой колонкой не становятся.
- `GameBattleRepository` — чтение и запись этой колонки у уже открытой строки. `add` ключ не передаёт: поле необязательное, у новой строки `null`.
- `GameBattleRecord::fromNormalized` — `null` или массив. Геттер нужен, иначе фасад читает колонку мимо Record. Сейчас метод знает только `id`, `session_id`, `state_version`.
- `GameCheckRoll` — публичный поиск одной карточки с `isInitiative()` по уже хранимому срезу. `throwCheck` остаётся броском.
- `GameMysqlFixture` ставит ту же `GameBattleSchema`. Отдельный install не заводится.

Сборка команды — новый фасад, его HTTP-сценарий, input, action и строка `game.rollInitiative` в `module.config.php` (`csrf: true`, как у `game.endBattle`). Метод сборки — на `GameBattlePortFactory`, не новый `create*` у `GamePortFactory`. В конструктор `GameBattles` фасад не добавляется: там уже шесть зависимостей. Репозитории боя, NPC и команд фасад создаёт из шлюза, как `GameBattles`. В конструктор снаружи входят шлюз, `IGames`, `GameCardAccess`, `GameMemberRepository`, `GameSessionRepository` и `GameCheckRoll`.

## Модуль

Нового порта Game нет. `events` остаётся `[]`. Новый код ошибки не заводится.

| Ситуация | Код |
|---|---|
| ноль или больше одной живой `CheckSpec` с `isInitiative()` | `GAME_INVALID`, порядок не пишется |
| пустой состав | `GAME_INVALID` |
| `throwCheck` отверг карточку или пул участника | `GAME_INVALID`, транзакция без порядка |
| чужая `expectedVersion` | `GAME_CONFLICT` |
| тот же ключ, другое тело | `GAME_CONFLICT` |
| во входе порядок, код правила, бросок, успех или трудность | `INVALID_PARAMS` |
| нет боя, нет сессии, игра `completed` | как у `endBattle` |

`RULE_INVALID` и `CHARACTER_INVALID` наружу не выпускаются: их уже прячет путь G18.

## Фасад

`IGameBattles` не растёт. Отдельный фасад инициативы. Видимость карточки и отказ `player` — как `GameBattles::assertWriter`: владелец, gm или `game.edit_all`. Отдельного ключа права у `game.endBattle` нет. Идемпотентность — `GameBattleCommandRepository` в той же транзакции шлюза. Поиск — метод `GameCheckRoll`. Бросок — только `throwCheck`, после сверки версии. Успех отдаёт `version`, как `GameBattleMutator` для старта и состава, не отдельное имя `stateVersion`.

## HTTP

Новое действие `game.rollInitiative`. Право — владелец, gm или `game.edit_all`, как у `game.endBattle`.

| Действие | Вход | Успех |
|---|---|---|
| `game.rollInitiative` | `{ gameId, battleId, idempotencyKey, expectedVersion }` | `{ battleId, version, order[] }` |

`order[]` — `{ type, id, difficulty, roll, success, rating }` в порядке хода. `ruleCode` в ответе нет. Готовый порядок и код правила во входе — `INVALID_PARAMS`.

## Тесты

Suite `game`. Suite `rule` и `character` не расширяются. Фикстура правила — документ `check` с `initiative: true` в срезе игры. Литерал кода в утверждении поиска не служит признаком: признак читается геттером. Вторая карточка с тем же признаком и срез без признака дают `GAME_INVALID` и пустой `turn_order`.

Mysql порядок. Два участника. В `order` две записи, больший `roll.base` стоит раньше. Лист и `game_session.state_version` те же. `game_check` не пишется. Повтор ключа возвращает тот же порядок и ту же `version`. Новый ключ заменяет порядок и увеличивает `version`.

Mysql отказа. Во входе массив порядка — `INVALID_PARAMS`, строки порядка нет. Чужая версия боя порядок не пишет.

Mysql состава. Порядок уже записан. Уход вычёркивает участника и сдвигает хвост. Один новый встаёт в конец без второй полной команды. Двое новых занимают хвост в порядке их собственных `roll.base`. Вернувшийся после ухода снова встаёт в конец. Пока `turn_order` пуст, смена состава бросок не делает. Нет единственной карточки инициативы при двух новых — состав и порядок прежние.

Mysql конца. `endBattle` удаляет бой, сессия остаётся, `sessionRunning` истинен. Второй бой той же сессии свой порядок не теряет, если он уже был записан. Новый `startBattle` приходит с пустым `turn_order`.

## Acceptance G21

- Game находит проверку по `CheckSpec::isInitiative()` в срезе ревизии игры. Код карточки не зашит.
- Ровно одна живая карточка считается путём G18 для участников этого боя. Ноль или больше одной — отказ, порядок не пишется.
- Своего броска нет: кубы и успех даёт `GameCheckRoll::throwCheck`.
- Порядок лежит на строке боя. Клиент готовый порядок не присылает. Лист и таблица сессии порядок не хранят.
- `endBattle` порядок снимает и сессию не останавливает.
- Уже записанный порядок при `setBattleRoster` сохраняет оставшихся и ставит новых в конец. Двое и больше новых считаются через `throwCheck` только между собой. Пустой порядок смена состава не бросает.
- Запись урона, C11, G22, DOT, каст и сцена не появляются.
- Character не импортирует Game.
