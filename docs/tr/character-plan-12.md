# План Character — проекция боевых слоёв

**Статус:** сделан, 2026-10-07. Порт `ICharacterCombatLayers` и базовая
projection готовы (`BACKEND_OPEN`). C10 и порт мутации actual не заменяет.
Они разблокировали базовый resistance path `game-plan-28`; полная block-ветка
и P1 ещё не закрыты.

Канон — [`combat-layers-prerequisite.md`](combat-layers-prerequisite.md), §3 и §4. Стандарты — [`php-coding-standards.md`](php-coding-standards.md).

## Порт

Новый порт чтения. Интерфейс, реализация и фабрика регистрируются в `Character/module.config.php` так же, как `ICharacterFormulaContexts`. `ICharacterActualMutations` остаётся как есть. У `ICharacterFormulaContexts::build` второй необязательный аргумент — карта параметров. Порт лист не пишет.

**Вход**

- `spaceId`, `rulesRevision`;
- документ `sheet` и документ `choices`. Одного `sheet` мало: `equippedModifiers` хранит код предмета, штраф, потолок ловкости и лимиты (`CharacterEquippedModifier`), слотов и модификаторов там нет;
- строка без `ruleCode` — custom. Слоёв от неё нет, даже если она надета. Отказ только когда код предмета или модификатора заявлен и не находится.
- строка `choices.inventory` — экземпляр. Её `id` на фронте — число `InventoryItem.id`. В PHP белый список `CharacterSaveKeys::INVENTORY` этого ключа не содержит, поэтому save с `id` сейчас получает `INVALID_PARAMS`. `CharacterChoiceAssembler` по-прежнему собирает `CharacterInventoryChoice` только из `ruleCode`, `equipped` и `quantity`: проекция читает сырой документ `choices`, как уже лежит `modifiers`, и выбор для валидатора не расширяется. Шаг добавляет необязательный int `id` в `INVENTORY`, чтобы документ мог его хранить. Нет ключа у старой строки — строка без `id`. Код правила остаётся типом предмета;
- коды модификаторов этой строки лежат в `choices.inventory[].modifiers`. Ключ уже в белом списке, выбор его не читает. Шаг читает существующий ключ. Frontend зовёт то же поле `modifierRuleCodes` и кладёт туда коды правил, не числовые id; при сохранении это один список, не второй экземпляр;
- Character таблицу NPC не читает. Game передаёт уже загруженные `sheet` и `choices` версии NPC;
- optional `id` строки инвентаря выбранного блока. Не код правила. Строка должна быть надета. После `apply` у предмета должно быть `ItemSpec::getBlockProfile()`: это одно поле предмета из [`rule-plan-10.md`](rule-plan-10.md), не профиль внутри оружия или щита. Нет строки, строка не надета, профиля нет или id повторяется — отказ. Две строки с одним `ruleCode` различаются id.

**Выход**

Typed DTO списка слоёв. Поля слоя:

- вид: защита или сопротивление;
- пара значения;
- `durability`: `?int`, как `DefenseSlot::getDurability()` и `ResistanceSlot::getDurability()` после [`rule-plan-08.md`](rule-plan-08.md). Нет ключа в spec — null. Защита `BlockProfile` своего ключа не имеет, у её слоя тоже null;
- `sourceCode`: копия из spec, либо source блокирования «От блокирования», если слой пришёл из блока и своего source не было;
- код типа урона или его отсутствие.

DTO в лист, в бой и в ревизию не сохраняется.

## Откуда слои

- Слои брони не читаются из `equippedModifiers`: там нет слотов и нет `modifiers` строки. Их даёт каждая надетая строка `choices.inventory`, у предмета которой после `apply` есть блок брони. Нет ключа `armor` или пустые `defense_slots` и `resistance_slots` — у строки нет слоёв брони. Битый список слотов — отказ проекции.
- Слоты блока читаются только у строки, чей `id` передан, и только из `getBlockProfile()` уже изменённого spec. `defense` профиля — слой защиты с порогом null. `resistances` того же профиля — слои сопротивления со своим `durability`. Эффективность профиля слоем не является.
- Перед чтением слотов строки вызывается `ItemModifierOperations::apply`. Нет ключа `modifiers` или он пуст — применять нечего, это не ошибка: ревизия может вообще не содержать модификаторов. Код из списка, которого нет среди живых правил ревизии или у которого spec не `ItemModifierSpec`, — отказ проекции. Вход `apply` — живой `ItemSpec`, уже разобранные spec найденных кодов и `CharacterResolvedRule::getKeywordCodes()` предмета. Срез уже перевёл `keywordIds` в коды. Пустой список кодов условие `when` не выполняет. Character режимы op не интерпретирует. Слоты берутся из возвращённого spec. Битый spec правила (`isSpecBroken`) — отказ, не пустые слоты.
- Пустой `source_code` слоя, который вошёл из блока, до отдачи DTO заполняется строкой «От блокирования». Указанный в слоте source сохраняется. Это значение ключа source для общего сложения, не поиск правила по литералу кода.
- Гранты `resistance` способностей из `sheet.abilityLevels`. Уровень блока не выше купленного: тот же отбор, что `CharacterDonorGrants::getForLevel`. Обязательный `source_code` гранта копируется. У `ResistanceGrant` нет `durability`, у слоя гранта порог null. `DimensionalNumber` копируется парой. `DimensionalFormula` считается `IFormulaEvaluations::evaluateDimensional`. `ScalarFormula`, включая `parameter`, считается `evaluateScalar`; пара слоя — `DimensionalNumber` с этой базой и размером 0. Узел `parameter` в каталоге «Сопротивление магии» — скаляр `x * per_unit`, не размерная формула. Характеристики и уровни по-прежнему читает `ICharacterFormulaContexts::build` из `sheet`. У `build` второй аргумент — карта код → int, по умолчанию пустая: `FormulaContext` нельзя дополнить после конструктора, а в `sheet.abilityLevels` параметров нет. Проекция берёт пары из `choices.abilities` этой способности и кладёт в карту `DimensionalNumber::toInteger()`. `buildStored` и вызов `build` без второго аргумента параметры не получают. Нет параметра, который узел требует, — отказ `IFormulaEvaluations`, не ноль. Отдельный обход каталога расы не нужен: способность уже в `abilityLevels`.
- `ItemSpec.innate` слоем не является.

Игрок и NPC проходят один метод. Отличие только в том, кто достал документ. Отказ проекции — `CharacterInvalidException`, как у битого документа инвентаря.

## Транзакция

Вызов внутри транзакции закрытия удара, после проверки ожидаемой версии листа, до mutation. Порт не открывает свою запись. Конфликт версии остаётся на вызывающем.

## Зависимости

- C10: контекст формулы по документу листа. У `build` появляется необязательная карта параметров. `buildStored` не меняется.
- [`rule-plan-09.md`](rule-plan-09.md), [`rule-plan-08.md`](rule-plan-08.md) и [`rule-plan-10.md`](rule-plan-10.md) уже сделаны. Проекция вызывает `ItemModifierOperations::apply`, читает `?int` и `getBlockProfile()`.
- Не зависит от [`mechanic-plan-07.md`](mechanic-plan-07.md): срез применяет Game к уже построенному списку.

## Приёмка

- Одинаковые документы `sheet` и `choices` у игрока и NPC дают одинаковый список. Слоты зависят и от `modifiers` строки, не только от кода в `sheet`.
- Ненадетый инвентарь кода в проекцию не добавляет.
- Грант с формулой даёт число через `IFormulaEvaluations`. Характеристики и уровни — контекст этого `sheet`. Параметр формулы — из `choices.abilities` этой способности, не из копии на листе.
- Предмет блока вне надетого — отказ.
- Порт не вызывает mutation и не пишет строку персонажа. Проверка версии листа остаётся на Game.
- DTO не содержит полного листа.

## Тесты

| Случай | Ожидание |
| --- | --- |
| В `choices.inventory` нет надетой брони | Нет слоёв брони, даже если в `sheet` есть `equippedModifiers` |
| Надет предмет без брони | Его слотов нет |
| Надета броня | Слоты из spec ревизии, не из листа |
| Ненадетый код только в inventory | В проекции нет |
| Грант `resistance` на листе, в том числе тело | Слой с его `sourceCode` |
| Формула гранта `parameter` | Число из `evaluateScalar`: параметр — `toInteger()` пары в `choices.abilities`, не ноль при отсутствии |
| Те же `sheet` и `choices` у NPC и персонажа | Тот же список |
| `id` блока нет среди надетых или у предмета нет `getBlockProfile()` | Отказ |
| Две надетые строки с одним `ruleCode` и разными `modifiers` | Слоты строки с переданным `id` |
| Повтор `id` в инвентаре | Отказ |
| Ключа `modifiers` нет или список пуст | Слоты базового spec, не отказ |
| Код в `modifiers` не найден в ревизии | Отказ |
| Блок надет, у слота свой source | Этот source сохраняется |
| Блок надет, source пуст | Source «От блокирования» уже в DTO |
| Вызов по документам | Строка персонажа не пишется |

Game actions, Rule parser и Mechanic этим шагом не меняются.
