# План Mechanic — capability среза надёжности

**Статус:** сделан, 2026-10-07. Метод `IMechanicEngine::hasReliabilityCut`
и marker `IReliabilityCut` готовы как `BACKEND_OPEN`. Production handler/content
для реального среза этим планом не добавлены. [`mechanic-roadmap.md`](mechanic-roadmap.md)
включает сессию 5. `game-plan-28` закрыт только частично.

Канон развилки — [`combat-layers-prerequisite.md`](combat-layers-prerequisite.md), §2. Стандарты — [`php-coding-standards.md`](php-coding-standards.md).

## Зачем

Game должен узнать, применяет ли атака срез надёжности, не сравнивая код механики, не читая boolean клиента и не выводя ответ из типа урона или из `pay_sr`.

## Вход

- Живое правило типа урона ревизии игры. Код типа приходит из профиля оружия как данные.
- Строки привязки механик этого правила (`mechanic_id` версии правила).
- Каталог Mechanic: id → `getCode()` и `getHandlerVersion()`. Отдельного `getVersion()` у `MechanicRecord` нет. Реестр ищет ключ `code@version` через `MechanicHandlerRegistry::resolve`.

## Выход

Метод `IMechanicEngine`, без нового порта и без нового HTTP. `module.config.php` не меняется: движок уже зарегистрирован.

- на входе binding, каталог и `ResolveActiveOptions`, как у `resolveActive`;
- на выходе bool: среди уже резолвленных хендлеров есть срез или нет.

Срез — пустой маркерный интерфейс рядом с `IMechanicHandler`. Хендлер, который срезает надёжность слоёв с threshold, реализует оба. Остальные хендлеры, включая `PurchaseSurchargeHandler`, маркер не реализуют. Порт вызывает существующий `resolveActive` и отвечает `true`, если `getHandler() instanceof` этого маркера. Второй резолв и сравнение `getCode()` со строкой не делаются. Game и Rule маркер не объявляют.

Два разных исхода:

- В ревизии нет правила и нет привязки с этой capability. Среза нет. Пространство из-за этого не битое. Ответ явно «capability нет», срез под включённый не маскируется. Это ответ на вопрос «умеет ли ревизия», не выполнение команды. Команда «примени срез» при отсутствии capability — ошибка вызывающего: он не должен был её слать. Тот же раскол у инициативы. Вопрос «есть ли карточка» при пустой ревизии — скрытый блок и info в консоли, не битое пространство. Команда «брось инициативу», когда бросать нечего, — ошибка бэкенда: фронт показал кнопку, хотя должен был остановиться на info. `findInitiativeCode` на такой команде уже кидает `GameInvalidException`. Менять этот бросок на тихий пропуск не нужно. Две живые карточки с одним marker — тоже ошибка: ревизия ссылается сама на себя неоднозначно.
- Правило ссылается на механику, а хендлера `code@version` в реестре нет. Это ошибка резолва, везде. Срез не считается выключенным. `MechanicEngine::pushBinding` сейчас такую привязку молча выбрасывает. Этот план так не делает: тихий пропуск ссылки — дефект текущего движка, не образец.

Порт этого шага на вопрос «есть ли capability» без такой привязки исключение не бросает. Ошибку кидает будущая команда, которая применила срез без capability. Её этот шаг не пишет.

Тот же отказ нужен в существующем `MechanicEngine::pushBinding`. Сейчас запрошенная привязка без хендлера выпадает из списка. Тест `MechanicEngineTest::testResolveActiveSkipsBindingWithoutHandler` это фиксирует. Этот шаг заменяет пропуск на `MechanicInvalidException`. Фильтр `includeCodes`, который сознательно не спрашивает часть семейства, ошибкой не является. `mechanic_id === null` тоже не ошибка: `findListedMechanic` уже не считает такую строку привязкой, и `testResolveActiveMapsMechanicIdToCodeVersion` оставляет её вне списка. Ошибка — привязка с id, для которой строки каталога или хендлера `code@version` нет.

## Зависимости

- Каталог и `resolveActive` сессий 2–3.
- Не зависит от проекции Character и от nullable `durability`.
- Rule новые поля `DamageTypeSpec` не добавляет. Привязка уже лежит в `RuleVersionBody::getMechanics()`: список `{mechanic_id, mechanic_payload}`. Отдельной колонки `mechanic_id` после `FoldRuleMechanicColumnsStep` нет.
- Game этот план не реализует и флаг во вход удара не кладёт.

## Приёмка

- Механика без capability среза не включает срез.
- Механика с маркером включает срез. Тест регистрирует хендлер с маркером и читает bool, а не сравнивает `getCode()` со строкой.
- Две привязки, одна с capability, дают срез.
- Привязка без хендлера в реестре — ошибка. Привязки нет — capability нет, без исключения и без подстановки среза.
- Penetration профиля этим портом не считается.

## Тесты

| Случай | Ожидание |
| --- | --- |
| Пустой список механик типа | Capability нет |
| Хендлер без маркера | false |
| Хендлер реализует маркер | true |
| Нет хендлера на `code@version` | Отказ резолва |
| Тест Mechanic | Ответ bool с маркера, `getCode()` со строкой не сравнивается |

Character, Rule parser и Game этим шагом не меняются. Тест Game, что удар не сравнивает код механики, остаётся на `game-plan-28`.
