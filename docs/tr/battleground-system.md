# Система battleground

**Статус:** `documentStatus: REQUIREMENT`, 2026-08-31. `implementationStatus: NOT_IMPLEMENTED`.
Источник: согласованный дизайн [`docs/specs/battlegroundLockedDecisions.md`](../specs/battlegroundLockedDecisions.md). Не текущий frontend/domain канон. Код и тесты battleground отсутствуют.

Абстрактное движение (action/process, `ISpatialResolver` без координат сцены) остаётся в [`game-system.md`](game-system.md) (`DEC-026`). Этот документ — пространственная сцена и её связь с боем.

Физическая схема, URL, PHP-классы — `OPEN`. PHP сцены не начинать до серверного Core (конвейер запроса, Auth/User, SmartTable, файлы). Глаголы домена ниже — не REST.

## Назначение

Battleground — источник пространственного контекста боя: позиция, маршрут, дистанция, LOS, фланг. Не декоративная картинка и не полноценный VTT.

Порядок реализации после принятия этого канона: серверный Core → persistence сцены по этой логике → frontend против того же контракта (mock совместим с портом).

## Статусы фрагментов

- `REQUIREMENT` — инвариант принят, реализации нет.
- `OPEN` — persistence, endpoints, точный список методов порта, HTTP/SSE mapping. Раскладка occupancy-клетки (8 байт, header version 1) уже `REQUIREMENT`.
- `BACKLOG` — сознательно позже: polygon стен, UI факелов, расчёт cover, стекло, шаринг шаблонов, корабль-платформа, подводный бой, обнаружение токенов слухом/нюхом, совместное редактирование, секретные тайлы подложки.

Illumination в occupancy и формула `mapVis` — `REQUIREMENT`, даже если в срезе свет везде 255.

## Шаблоны и игровые сцены

- `SceneTemplate` принадлежит автору; в первом релизе не шарится. Токены шаблона — декор и служебные, без PC/NPC.
- `GameScene` — независимый snapshot шаблона в игре, не live-ссылка. Дубль — новые ID токенов; ссылки на акторов сохраняются.
- У игры несколько сцен enabled/disabled и ровно одна `current`.
- `BattlemapView` — полноэкранный режим, не сущность хранения.
- Состояние сцены живёт с игрой; reload без потери позиций и player knowledge.

## Права и версия

- Геометрию и состав сцены правит только ведущий (включая `current`).
- Игрок двигает своего персонажа и действует за разрешённого. Жест карты порождает доменную команду, не единственный drag.
- Авторизация на сервере. Fog на клиенте не защита скрытых данных.
- Ход игрока и правка ведущего заранее не блокируют друг друга.
- Мутация несёт `sceneVersion`; stale — отказ, повторное чтение, повтор с явным UI.

## Пространства и опоры

- `SceneSpace` — 2D-карта со своими координатами, подложкой и occupancy. Этаж дома — отдельное пространство, не номер слоя всей локации.
- `Enclosure` — только если внутри **другая карта** (дом на поляне → этажи интерьера). Двор, кольцо частокола, атриум: стены на **том же** space, середина проходима, пятно не заливать как непрозрачный объём.
- `SupportSurface` — земля, мост, крыша, верх стойки. Крыша и мост — опоры родителя, не вкладки.
- Позиция токена: `{spaceId, x, y, supportId, altitude}`. Настил — сплошная плита (не проваливаться на дешёвый путь под мостом). Сквозь объём стойки по полу нельзя.
- Вкладки UI — пространства, не каждый настил.
- Рёбра опор: `walk` / `climb` / `vault` / `drop`. Нет ребра — нельзя. Объекты порождают рёбра. Неоднозначный клик — выбор (по мосту / под мостом; приземлиться / пролететь).

## Координаты

- Целые единицы `SceneResolution` на `GameScene`, default `2^-6` ипари (`1` ипари = 64). Не float JS. Не `DimensionalNumber.toNumber()` для пространства.
- Шаг, размер токена и footprint независимы. Footprint: круг, эллипс, прямоугольник. Polygon стен — `BACKLOG`.
- Дистанция на одной сетке — евклид. Visual grid — помощь вводу.
- Facing: 0–359°, 0 = вверх экрана, по часовой. Front/rear защитника ±45°, иначе flank.

`occupancyCell` (default ¼ ипари) — vis, свет, слот cover. Ход и коллизия — точная геометрия, не клетки occupancy. Потолок клеток ориентир ≤1024², иначе укрупнять ячейку. Запас карты 200×200 ипари, типичная ~40×40; ~200 актёров.

## Occupancy

Один blob на пространство, один и тот же у клиента и сервера, штамп при save. Таблица проёмов **не** внутри blob.

Клетка 8 байт: два непрозрачных интервала u8 lo/hi, крона lo/hi, illumination, `portalId`. `lo=hi=0` — слота нет. Окно: подоконник + перемычка (два интервала). Закрытая дверь: один интервал на всю высоту. Illumination default 255. Cover в клетке нет (в срезе cover=0 с сервера).

Header: magic, version **раскладки** (сейчас 1, не `sceneVersion`), width/height, origin и размер клетки в единицах сцены, zQuantum (по умолчанию равен `occupancyCell`); little-endian, `index = y * width + x`. Datum Z у каждого space. Если высота >255 квантов — укрупнить `zQuantum` этой сетки.

Штамп vis: overlap ≥½ ширины **или** ≥½ высоты клетки. Круг против этой клетки. Факел/дверь — патч куска, не перештамповка леса.

Коробка enclosure на родителе: footprint как непрозрачный объём, затем вырез порогов. Кольцо стен без другой карты — не заливать середину.

## Проёмы

Проём — **закрываемый блокер** (`open`/`closed`): закрыт — непрозрачный интервал и нет хода; открыт — патч столбика и навмеша.

**Портал** (смена сетки vis/walk) — только если цель — другое пространство. Калитка двора: блокер, `portalId = 0`. Дверь таверны: блокер **и** парные записи портала.

Дверь/окно enclosure: редактор пишет пару записей. Телепорт — free, геометрия не обязана совпадать. Vis и walk — независимые флаги. Окно: vis да, walk нет. Стекло (видеть закрытым) — `BACKLOG`.

`portalId` u8 в клетке: 0 = нет; все клетки одного порога — один id. 255 — число **записей** на пространство, не клеток. Сетка vis ≠ `SceneResolution`.

Смена `spaceId`+xy, когда **центр** пересекает плоскость порога. Vis и атака через открытый портал **без** этой смены.

Цепочка vis-порталов — бюджет DDA/рендера (ориентир 2–4), не правило мира.

Колодец без нижней карты: непроходимая яма, без vis-портала. Погреб — только если ведущий завёл space и связал люк.

## Движение на сцене

Клик — конечная позиция. На save: навмеш на каждую опору. Поиск: иерархический A* + воронка → полилиния в единицах сцены. Сервер: та же полилиния + точный круг vs препятствия.

Squeeze — режим, без навыка. `freeTurn` ≤90° после успешного движения; иначе отдельный `turn`. Итоговый facing — последний сегмент.

Полёт в поставке: 1 ОД = 1 взмах, сразу горизонталь и вертикаль до шага; число взмахов `max(ceil(Δh/шаг), ceil(Δv/шаг))`. Высота опоры: default типа + override; крыша = сумма этажей enclosure, если не задана. В воздухе `supportId` пустой. Collision с частичным проходом: положительная дистанция сохраняется, ОД не возвращаются.

Движение стыкуется с уже существующим action/process (`front+up`), не отдельным контуром ОД.

## Видимость

```text
mapVis = LOS(столбики, высота) ∧ (illumination ∨ чувство_игнорирует_свет)
```

Fog/explored — LOS-чувство с лучшим радиусом у выбранного активного персонажа (точное значение чувства, не мод Внимательности). Нет токена на `current` — нет динамической vis.

Слух/нюх карту не красят (`BACKLOG`: обнаружение токенов).

Состояния: `visible` / `explored` / `unknown`. Knowledge per player. `lastSeen` — ghost без identity; GM hide снимает lastSeen. Override ведущего: всем / только GM / выбранным / открытая область.

Клиент рисует fog. Сервер фильтрует токены и LOS атаки. PHP: не fog 60 FPS, не 40k кругов, не лес в SSE. Подложка не секрет.

Картинка через портал: чужое пространство только в силуэте проёма; глубина как vis; несколько проёмов в одно пространство — один pass, stencil = объединение. Закрытый проём — глухая стена. Сверху в полёте — крыша, не комнаты.

## Бой со сценой

Если сцена есть, процедура не доверяет клиентским дистанции/укрытию/флангу.

- Дверь/окно: дальность — прямой 3D-отрезок в укладке enclosure в родителя, если отрезок пересекает проём. Стену навылет нет.
- Телепорт: сумма до проёма A + от проёма B.
- LOS-block; cover=0 до расчёта силуэта с той же сетки (`BACKLOG`).
- `flank` per strike от facing защитника; `flank`+`rear` → боевой `flank=true`.
- Wide: все цели или отказ; `max_strikes` ≠ `max_targets`.

Атака — глагол Game/combat, не POST сцены. Сцена отдаёт spatial context.

## Объекты

- Река — полилиния русла; озеро — тело, течение 0. Мост — настил, walk с берега.
- Дерево: ствол непроходим (точная коллизия и LOS); крона — плита (по земле ход обычный; сквозь листву difficult; луч под кроной крону игнорирует).
- Лес масштаба ~40k / ~10 прототипов — `InstanceLayer`, не `Token[]`.
- Стол/стойка: вырез + верх + climb по периметру.
- Забор: `blocksMovement` без `blocksVision`; занавес — наоборот.
- `TerrainArea` — ход (грязь, лёд, …), не vis-столбик.
- Ground cover (трава/песок/доски) — визуал пола, не occupancy и не TerrainArea; кисть материалов не первый срез.
- Лестница в доме: difficult + проём между пространствами. Приставная: climb без смены space.
- Причал/зубцы — настилы. Дом на дереве — enclosure или опора с высотой. Обрыв: walk вверх нет, вниз drop.

## Assets и realtime

Подложка — shared immutable `assetId` с привязкой к логическим координатам пространства; пиксели ≠ ипари. Копия сцены копирует ссылки. Удаление — archive.

Транспорт: HTTP-команды + SSE; optimistic `sceneVersion`. Не слать лес в SSE. Точные пути и события — `OPEN`.

Mock не использует data URL картинок как контракт хранения.

## Поверхности UI (`REQUIREMENT` поверхностей, не рецепт виджетов)

Библиотека личных шаблонов; список сцен игры (enable/`current`); полноэкранный battlemap: мир карты WebGL, оболочка Vue (чат, панель, вкладки пространств). SVG мира карты нет. Детали gizmos — implementation plan.

## Доменные глаголы (не HTTP)

Чтение: шаблоны; GM-сцена; `PlayerSceneProjection` от активного персонажа.

Ведущий: template CRUD и copy-into-game; scene duplicate / enable / setCurrent; правка space/enclosure/support/opening/obstacle/воды/terrain/instance-layer/декор-токенов; upload подложки; stamp occupancy+navmesh; visibility override; add/remove actor token; setOpeningOpen (патч блокера и при наличии портала).

Игра: `move` (полилиния, режим squeeze/flight/climb); `turn`.

SSE: смена version, token, opening, current, knowledge — не 40k instances.

Полный порт `IBattlegroundApi` — `OPEN` до проектирования сервера (после Core).

## Вертикальный срез готовности

Открыть игру с сохранённой сценой → видеть доступное → выбрать персонажа → переместить с ОД (опора/проём) → атака берёт дистанцию/LOS/фланг со сцены → оверлей и чат → reload без потери позиции и knowledge.
