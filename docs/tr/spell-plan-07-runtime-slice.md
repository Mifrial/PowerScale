**Статус:** DONE, 2026-09-10. Родительская нарезка — [`spell-roadmap.md`](spell-roadmap.md). Контракт — [`spell-plan-03-contract.md`](spell-plan-03-contract.md). Правила фронта — [`draft-front_1.2ds/frontend-rules.md`](../../draft-front_1.2ds/frontend-rules.md).

## Цель

После M6 в бою есть только бросок **проверки на сотворение**. M7 подключает заклинание как действие: **списать компоненты**, доставить эффект среза через существующие атаку/урон, не изобретая второй engine.

Representative: **Разряд** (`discharge`) — instant, 4 ОД, касание, электрический урон. Второй режим доставки в том же срезе: **Удар молнии** (`hit_resolution: auto`, фиксированный РУ) — без броска попадания.

После M7:

- ОД = **max**(ОД заклинания, ОД выбранной атаки касания), списаны **до** check;
- касание — выбранная ближняя атака (`check-hit` + профиль оружия);
- цель касания ≠ цель заклинания (resistance / обязательность);
- успех доставки заклинания → электричество через `AttackDamageService`; попадание атакой → отдельный физический apply;
- чат: броски hit + сотворение + сообщение урона или молока.

Это не M8 (duration / `spell_upgrade` / persist activation) и не M9 (отклонение, дестабилизация, мана).

## Порядок cast (канон)

Инвентарь: объявление → **время/компоненты** → проверка сотворения → успех/провал.

1. Игрок объявляет заклинание, source, path, мощь (как в M6), **атаку касания** (если `hit_resolution: attack`) и при необходимости **цель заклинания**. Недостаточно ОД (`max` заклинания и атаки) — не начинать.
2. **Компоненты до успешности сотворения:** списать ОД = `max(actionOdCost(spell), odCost выбранной атаки касания)`. Соматика в M7 — «есть в спеке», без `occupy_hands`.
3. **Две цели.** Цель касания — куда идёт атака и (у Разряда) урон заклинания. Цель заклинания — для сопротивления магии и обязательности сотворения. Они независимы.
4. Касание — **та же ближняя атака**, что обычный удар: выбранные действие + профиль оружия (`HitRollService` + `check-hit`). Рука, кинжал, меч — все ближние профили; свойство «Проводник магии» в M7 **игнорировать**. Не второй hit после успеха сотворения.
5. У цели касания **всегда есть адресат**: персонаж **или воздух**. Каст стартует и без персонажа на конце: атака/промах «в воздух», ресурсы тратятся, проверка сотворения идёт. Промах по персонажу — то же: успешное сотворение возможно, эффект **в молоко**. Сопротивление магии **цели касания** сложность **не** увеличивает.
6. **Цель заклинания** (флаг/селект «направлен на цель»): её сопротивление магии увеличивает сложность. Если цель заклинания **обязательна и не выбрана** — попытка **автопровал** (не молоко). В M7: ОД/касание уже потрачены, check неуспешен, без отклонения/аркана (M9).
7. **0 РУ атаки** — не молоко (`passed === true`, `rating === 0`). Физический урон **самой атаки** остаётся 0 РУ. Эффект касания заклинания — `sr = 1`.
8. Проверка сотворения — `check-spell-cast`; пул — стат пути. Skip `{0|-1}` — бросок check не звать, компоненты уже потрачены. Автопровал (нет обязательной цели заклинания) — попытка **уже начата**: ОД и касание потрачены; check не успешен (без броска или синтетический провал). Отклонение / аркан (M9) не вызывать. РУ сотворения **не** в урон (SR-162).
9. Успех сотворения (или skip) **и** попадание касания (не воздух/не промах) / auto → электричество на цель касания (Разряд) или цель доставки auto. Физический урон выбранной атаки — при попадании по персонажу **даже если** сотворение потом провалилось или эффект заклинания в молоко. Провал сотворения → электричества нет. Молоко → электричества на персонажа нет.

Автолуч (`lightning-strike`): hit-броска нет; `sr` = `hit_resolution.rating`. ОД и соматика — всё равно до check. Falloff уже есть в [`SpellDamageService.applyFalloff`](../../draft-front_1.2ds/src/modules/Roleplay/Rule/Service/SpellDamageService.ts): в M7 всегда звать его; если дистанции в диалоге нет — передать `0` ипари (бесплатный порог, урон не режется). Не оставлять falloff «неисполненным».

## Сверка с кодом

1. **ОД.** У spell они уже в том же поле, что у action: `action_components` (`resource` / `action-points`). Отдельного места нет. `actionOdCost` как раз это поле и суммирует. `asActionAbilitySpec` — type guard `type === 'action'` для списка ударов; для spell он null **намеренно**, чтобы Разряд не попал в `listAttackActions`. ОД заклинания: `actionOdCost` по `action_components` спеки. ОД касания — то же у выбранной атаки. Итог **`Math.max`**. `chosen` пропускается. Нехватка max — не стартовать. Воздух касания и пустая цель заклинания у Разряда — стартовать.

2. **Касание = выбранная ближняя атака.** Не синтетический `{3|0}` и не запрет меча. Список как у удара: профили `strike` с overview (рука, кинжал, фехтовальный меч Торвина — все). `HitRollInput.attack` — accuracy/reach/falloff **этого** профиля; мастерство — `weaponMasteryForAttack` по выбранному оружию. «Проводник магии» не фильтровать. Физический урон атаки — обычный apply этой атаки (у «Простого касания» урона нет). Эффект заклинания — отдельно, `sr` касания с правилом 0→1. `reaction: 'ignore'` в UI M7 можно оставить упрощением; это не отменяет выбор оружия. Не тащить процесс/широкий удар.

3. **Простое касание.** Mock `simple-touch`: 3 ОД, без урона оружия, **+1 РУ** (рейтинг, не accuracy). Типа `ActionEffect` «+N РУ» нет — union в M7 не расширять. Союзник или воздух: без contested `check-hit`, исход `rating = 1`. Враг: обычный hit, затем +1 к РУ атаки. Правило 0→1 для эффекта заклинания — **после** этого +1.

4. **Цель касания vs цель заклинания.** Пустой селект у Разряда = не направлен, resistance 0, не auto-fail. Удар молнии: цель доставки = цель заклинания; пусто = auto-fail после ОД. Электричество Разряда — по цели касания. Resistance только с цели заклинания.

5. **Два apply.** Попадание оружием: физический урон отдельным `applyAttackDamage`. Электричество — второй apply при успехе и не-молоке. DN не сливать.

6. **Урон заклинания — `spellDamageService`.** `x` = `parameterPower`. Опыт: новый Character-сервис (класс + Instance + `Character/init`); перенести расчёт стоимости из `experienceOf`, не naive поле cost. Редактор `derivedAbilityLevels` зовёт его. Game не берёт опыт через `characterEditorService` и не копирует сумму.

7. **Оркестрация.** Списать max ОД → касание (+ физический apply при попадании) → check или auto-fail → молоко / электричество / fail. Max ОД — метод оркестратора, не Utils. `SpellCastService.rollForSpell` — чистый бросок.

8. **Диалог / чат / слои.** Не копировать HitLaunch. Чат: hit, физический урон если был, check/auto-fail, электричество/молоко/fail. Генератор и Цепную не исполнять.

## Гейт M7

- Недостаточно `max(ОД заклинания, ОД атаки касания)` → каст не стартует. Воздух как цель касания — стартует.
- ОД списаны до hit и до check (молоко, skip, auto-fail).
- Промах / воздух → нет **электричества** на персонажа; check сотворения был (не auto-fail).
- Удар молнии без цели доставки → auto-fail после ОД; Разряд без цели заклинания — не fail.
- Попадание атакой: физический урон даже при fail/молоке заклинания; электричество только успех + не молоко.
- `simple-touch` по союзнику: без contested hit, РУ 1.
- 0 РУ hit: физический урон атаки не идёт; `sr` электричества 1.
- Опыт keyword — Character-сервис из `init`; редактор на нём же.
- Касание берёт accuracy выбранного ближнего профиля.
- Успех + попадание: электричество через `AttackDamageService` (`defenseIgnored` / `maxSuccessRating`; Шок с истощения); `x` = `parameterPower`.
- Auto: нет `check-hit`; `sr` из rating; без цели — auto-fail после ОД.
- Vue без `modifyDiffTo` / формулы мощи.
- Нет отклонения и нет `spell_upgrade`.
- format / lint / `vue-tsc` / полный `npm run test`.
