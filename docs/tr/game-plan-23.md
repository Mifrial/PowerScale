# План Game 23 — сопротивление цели одного удара

**Статус:** сопротивление цели в PHP сделано. `BACKEND_OPEN`. Suite `game` по `GameStrikeMysqlTest` и `GameWideStrikeMysqlTest` зелёный. В [`game-roadmap.md`](game-roadmap.md) шаг не вписывается. Попадание — [`game-plan-22.md`](game-plan-22.md): `success` — рейтинг единственной живой карточки `isHitCheck()`, `damage` — число формулы урона профиля. Закрытие читает формулу урона и не читает защиту — [`game-plan-20.md`](game-plan-20.md). Канон слоя — [`rule-content-plan-12-dodge-benefit.md`](rule-content-plan-12-dodge-benefit.md): сопротивление вычитается из урона оружия до умножения на РУ; само S этот шаг не считает. Отсутствие экземпляра — [`rule-system.md`](rule-system.md). Стандарты — [`php-coding-standards.md`](php-coding-standards.md).

Цель: один заход. При закрытии уже открытого удара `1 → 1` и `1 → N` из надетых кодов цели и типа урона профиля собирается одно целое сопротивление. В лист оно не пишется, новый ключ `sheet` не заводится. `success` и `damage` остаются как в G22. Код карточки брони и тип урона в Game не зашиваются. Смягчение S, повреждение, `putState` и список операций не входят. Запись исхода из нарезки G22 не пишется.

Сверка до плана. `sheet.equippedModifiers` хранит `ruleCode`, `strengthPenalty`, `maxAgility` и `characteristicLimits`. Числа сопротивления в снимке нет. `GameStrikeRules::item` по коду уже отдаёт живой `ItemSpec`. `ItemSpec::getArmor()` отдаёт `ArmorBlock` или `null`. `ArmorBlock::getResistanceSlots()` отдаёт `ResistanceSlot[]`: тип `getDamageTypeCode()`, значение `DimensionalNumber`, прочность и источник. У удара тип есть: профиль, который уже читает `evaluateDamage`, несёт `WeaponDamage::getDamageTypeCode()`. Связь «надетый код → слоты брони» в срезе есть, поэтому план — сборка одного числа из этих входов.

Зависимость — G22. Rule и Character этим шагом не меняются. Хендлеры `injury_efficiency`, `exhaustion_wound` и `state_write` в Mechanic не ставятся.

## Физическая схема

Новых таблиц и колонок нет. Рядом с `success` и `damage` в JSON итога уже существующих `game_strike_command` и `game_wide_strike_command` появляется `resistance`. В строки удара и целей колонка не пишется. Строка `game_check` и process не открываются. Ключ `sheet` не растёт.

## Сверка входов

- `CharacterSheetDocument::equipped` пишет в снимок только код предмета, штраф силы, потолок ловкости и лимиты. Слоты брони туда не копируются. Закрытие не дописывает их в лист и не заводит ключ.
- `GameStrikeRules::item` берёт `findLive`, отбрасывает битую spec и требует `ItemSpec`. Тот же разбор годится для кода из `equippedModifiers` цели. Своего среза у удара нет.
- `evaluateDamage` уже поднимает `WeaponProfile` и считает `getDamage()->getFormula()`. Тип урона — `getDamage()->getDamageTypeCode()` того же профиля. Второй поиск профиля не пишется. Реакции `ignore`, `dodge` и `block` тип не подменяют.
- Слоты защиты `ArmorBlock::getDefenseSlots()` закрытие по-прежнему не читает. Сопротивления `BlockProfile` щита этот заход не читает: в сборку входят только слоты брони надетого предмета.
- `GameStrikeRules` держит пять зависимостей. Шестая не добавляется. Конструкторы `GameStrikes` и `GameWideStrikes` не растут.
- `ICharacterActualMutations::apply` и `GameNpcRepository::replaceVersion` не вызываются. Character модуль Game не импортирует. Rule не меняется. `operations()` остаётся пустым списком.

## Зафиксировано (модель и права)

**Откуда код.** Цель удара. Персонаж — `ICharacters::get`, тот же объект, что у `characterVersion`: у него есть `getSheet()`. NPC — `getVersion()['sheet']`, как `GameStrikes::attackerSheet`. У `1 → 1` снимок NPC читает `GameStrikes`. У `1 → N` его читает `GameWideStrikeResults`: репозиторий NPC там уже есть, в `GameStrikeRules` он не добавляется. Берутся строки `sheet.equippedModifiers`. У строки читается только `ruleCode`. `strengthPenalty`, `maxAgility` и `characteristicLimits` в число не входят. Нет ключа или список пуст — надетых кодов нет, это ноль, не отказ. Ключ есть, но это не список, строка не объект или `ruleCode` не непустая строка — `GAME_INVALID`, удар не закрывается. Фикстура NPC в `GameStrikeMysqlTest` хранит `sheet` как `['hp' => 1]`: ключа нет, закрытие с таким листом даёт `0`.

**Один слот.** Для каждого кода `item` поднимает живой `ItemSpec`. `getArmor()` равен `null` — у этого предмета слота нет, строка даёт ноль и закрытие идёт дальше. Иначе обходятся `getResistanceSlots()`. В сумму входит слот, чей `getDamageTypeCode()` — непустая строка и равен типу урона профиля. Равенство строковое. Код брони и код типа в PHP не появляются. `null` у типа удара или у слота совпадением не считается. Прочность и `sourceCode` не читаются. Число слота — `DimensionalNumber::toInteger()`. Несколько совпавших слотов одного предмета и нескольких надетых предметов складываются в одно целое.

**Нет подходящего слота.** Явное нулевое сопротивление. Удар закрывается. Ноль — нет брони, броня без слота этого типа, либо у профиля `getDamageTypeCode()` равен `null`. Это не отказ среза: безоружная цель и удар без типа остаются закрываемыми. Обычный отказ сюда не выбирается.

**Нет экземпляра.** Код из `equippedModifiers` не живой, spec битая или это не `ItemSpec` — обычный отказ этого среза, `GAME_INVALID`. Запасной код брони не подставляется. Удар остаётся открытым, версия боя не растёт. У `1 → N` это отказ всего закрытия, не `code` одной цели: карточки в срезе нет. `RULE_INVALID` и `CHARACTER_INVALID` наружу не выпускаются.

**Куда пишется.** Поле `resistance` итога. `damage` остаётся числом формулы урона. `success` остаётся рейтингом попадания. Вычитание из урона, умножение на РУ и смягчение S не выполняются. У `1 → 1` поле рядом с `success` и `damage`. У `1 → N` число своё у каждой принятой цели: урон и рейтинг по-прежнему общие на атаку, сопротивление читается с её листа. Отказ одной цели пишет `success`, `damage` и `resistance` как `null`, ключи на месте, как сейчас `null` у первых двух в `row`. `sheetVersion` и `code` принятой цели остаются `null`.

**Порядок.** Поиск карточки попадания и `evaluateDamage` не меняют свой порядок. Чужая версия боя — `GameBattleConflictException`, сборка не вызывается. У `1 → 1` сборка стоит после `assertSheet` и до `rateOf`: чужой `expectedSheetVersion` и мёртвый надетый код не вызывают `roll`. У `1 → N` `rateOf` уже вызван в `GameWideStrikes` до `commitClose`. Сборка — в `GameWideStrikeResults::one`, когда `refusal` вернул `null`, и снаружи `try` этого метода: `refusal` ловит `GameInvalidException` и пишет его в `code` одной цели, а мёртвый код брони должен сорвать всё закрытие. Чужая версия листа одной цели по-прежнему не отменяет удар: у этой цели слоты пустые, сборка для неё не вызывается. Отказ среза на другой цели откатывает транзакцию. Команда не пишется, повтор закрытия вызывает `roll` снова. Повтор уже сохранённого итога возвращает JSON команды как есть и слоты второй раз не читает. Тот же ключ с другим телом — `GAME_CONFLICT`.

**Чего шаг не делает.** Не пишет лист и не заводит ключ `sheet`. Не меняет `success` и `damage`. Не считает S, повреждение и `(урон − сопротивление) × РУ`. Не наполняет список операций. Не зовёт `putState`. Не читает защиту и сопротивления блока щита. Не ставит хендлеры ранения. Не начинает запись исхода роадмапа. Не считает `N → 1`, `N → N`, DOT, каст и сцену.

## Что даёт этот заход

Закрытие возвращает прежние `success` и `damage` и новое `resistance`: сумма `toInteger()` слотов брони цели, чей тип урона равен типу профиля. Нет подходящего слота — явное `0`, удар закрывается. Нет живого предмета по надетому коду — удар остаётся открытым. Лист не меняется.

## Что не закрыто

- Вычитание сопротивления из урона, умножение на РУ, смягчение S, повреждение.
- Запись числа в лист, C11 и G22 роадмапа.
- `putState` и список операций.
- Хендлеры `injury_efficiency`, `exhaustion_wound`, `state_write`.
- Сопротивления блока щита и слоты защиты.
- `N → 1`, `N → N`, DOT, каст, сцена.
- `personalNotes`.

## Точки кода

Старые планы не переписываются. Новых портов, action и ключей прав нет. `declareStrike` и `declareWideStrike` не меняются. Character Game не импортирует. Rule не меняется.

- `GameStrikeRules` — метод рядом с `evaluateDamage`. Вход: уже найденный профиль или те же предмет, вид и индекс, лист цели. Выход: одно целое. Конструктор не растёт. `operations` остаётся пустым.
- `GameStrikes::close` — после сверки листа цели пишет `resistance` в итог команды. `success` и `damage` не переприсваиваются.
- `GameWideStrikeResults` — после `refusal() === null` и вне его `try` считает сопротивление и передаёт его в `row`. Отказ цели — `resistance: null`. Исключение не превращается в `code` одной цели. `build` получает `item_rule_code`, `profile_type` и `profile_index` строки `game_wide_strike`: в `commitClose` их сейчас нет, у строки цели этих колонок нет. `GameWideStrikes` конструктор не растит: `rateOf` остаётся до `commitClose`.

## Фасад

`IGameStrikes` и `IGameWideStrikes` не растут. Закрытия после сверки листа зовут сборку. Объявление число не считает.

## HTTP

Новых action нет. `game.resolveStrike` по-прежнему отдаёт `success` и `damage` и добавляет `resistance`. `game.resolveWideStrike` заполняет `resistance` у принятой цели. Ключи входа те же. `success` — рейтинг попадания. `damage` — число формулы урона. `resistance` — собранное целое, не поле листа.

## Тесты

Suite `game`. Suite `rule`, `character` и `mechanic` не расширяются.

Mysql `1 → 1`. В срез мира удара добавляется живой предмет-броня со слотом: `damage_type_code` равен типу урона профиля меча, `value` — размерное число с известным `toInteger()`. На листе цели в `equippedModifiers` только `ruleCode` этой брони, без числа сопротивления. После закрытия `damage` и `success` те же, что до шага, `resistance` равен `toInteger()` слота. `apply` не вызывается. Повтор ключа возвращает то же `resistance` и слоты второй раз не читает.

Mysql нуля. Цель без ключа `equippedModifiers`, пустой список, надетый предмет без `getArmor()`, броня со слотом другого типа и профиль с `getDamageTypeCode() === null` закрывают удар с `resistance` `0`. `damage` не уменьшается.

Mysql отказа. Надетый код отсутствует в срезе, spec битая или правило не предмет — удар открыт, версии боя и листа те же. Литерал кода брони в утверждении поиска не служит признаком: признак — совпадение `getDamageTypeCode()` слота и профиля.

Mysql `1 → N`. Две принятые цели с разной бронёй получают разные `resistance` при общих `success` и `damage`. Чужая версия листа одной цели оставляет у неё три слота пустыми и не затирает `resistance` второй. Код брони, которого нет в срезе, не закрывает удар целиком.

Mysql листа. Ключ `sheet` после закрытия тот же. `operations()` пуст.
