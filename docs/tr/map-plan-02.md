# Карты: фронтенд-срез

**Статус:** ~В РАБОТЕ~, 2026-11-08 — распознавание объектов по подложке, группы областей, границы и производительность на 6000+ объектах; ждёт ручной проверки.
**Реализация:** ~VUE~ — готово, ~PHP~ — [`map-plan-01.md`](map-plan-01.md), ~МОК~ — свой mock.
**Опираться на:** ~PHP~ (контракт `map.*`), ~МОК~ (свой mock).

Просмотрщик и редактор карт без SVG-парсера, Leaflet и PixiJS. Подложка —
растровое изображение из `Core/File`; оверлеи — Canvas 2D.

## Страницы

- `/maps` — список карт: название, видимость, обновление, кнопка «Новая карта».
  Фильтры: `q`, архив.
- `/maps/:id` — карта: «Просмотр», «Редактор», «Маршрут».

## Черновик

Редактор не пишет на сервер по действию. Он работает с полным снимком карты в
памяти и публикует его одной кнопкой.

- **Загрузка**: `map.get` один раз на открытие страницы.
- **Правки**: места, размещения, области, ленты, варианты, поля карты — только
  в локальном снимке.
- **Dirty**: снимок сравнивается с загруженным; «Сохранить» активна только при
  изменениях.
- **Публикация**: `map.save` с `expectedVersion`. Успех — клиент принимает
  ответный снимок как новый эталон, `dirty` сбрасывается.
- **Ошибка сохранения**: черновик остаётся, показывается путь к полю; карта не
  перезагружается. «Повторить» есть только у ошибки загрузки.
- **Уход со страницы**: `beforeunload` и router-guard при `dirty`.
- **Границы мира**: точка прижимается к `width × height`; объект целиком
  останавливается, когда до края доходит любая его точка. Ручки Безье и ширина
  не прижимаются — это смещения.
- **История**: до 50 шагов и не больше 16 МБ снимков; на карте с тысячами
  областей старые шаги вытесняются по объёму, но минимум 5 остаётся.
- **Группы**: `map.groups` — ярлык для массовых правок; `area.groupId`
  указывает на группу снимка. Создание пачки областей — один шаг истории.

### Распознавание по подложке

Инструмент «Объекты по подложке» создаёт однотипные области по цвету.

1. **Образцы.** «Взять цвет» + клик по подложке; 2–8 оттенков. Повторный клик
   по пятну в режиме превью исключает его из создания.
2. **Поиск.** Маска по цвету → эрозия маски как семена → водораздел по исходной
   маске (каждый пиксель достаётся ближайшему семени) → контур по границам
   пикселей → упрощение Дугласом — Пекером → аппроксимация плавных участков
   дугами Безье. Внутренние дворы заливаются, самопересечения разрезаются по
   узлу, тонкие полоски отбрасываются. Водораздел режет перемычки по средней
   линии и сохраняет исходный силуэт: геометрический offset, который давал шипы
   на почти коллинеарных вершинах дуг, убран.
3. **Настройки.** Допуск цвета, игнор яркости (тени), минимальная и
   максимальная площадь, **разделение перемычек** (`1–2 px` разделяют слипшиеся
   пятна по средней линии), допуск упрощения (по умолчанию `1 px`),
   **жёсткий потолок углов** (24, ползунок 8–48) и **сглаживание дуг**
   (по умолчанию включено). Разделение включено по умолчанию (`1 px`).
   Сглаживание ищет углы (поворот круче ~35°) и заменяет плавные участки
   дугами Безье: полукруг собирается из двух сегментов, полный круг — из
   четырёх. Углы зданий остаются острыми (ручки = 0), стык «дуга → угол»
   использует раздельные `in`/`out`. Кривая проверяется по сырому контуру:
   если она уходит от исходной границы больше чем на 2,5 px (шумная подложка,
   выемка), участок остаётся прямым. Переключатель «Сглаживать дуги» позволяет
   сравнить оба режима.
4. **Превью.** Маска и контуры рисуются в динамическом слое canvas; в панели —
   число пятен, отброшенных мелких/крупных/тонких и среднее/максимальное число
   углов. Клик по контуру **или по самому пятну** исключает его и возвращает
   обратно (попадание с допуском 8 экранных px — по тонкой линии на мелком
   масштабе тоже работает); исключённые заливаются серым. Кнопки «Исключить
   все» и «Вернуть все» позволяют начать с пустого набора и дотыкать нужные
   пятна.
5. **Создание.** Слой, цвет, скорость, подпись, плотность заливки, граница
   (цвет + толщина) и имя группы задаются до создания. По умолчанию граница
   включена, её цвет — заливка, затемнённая на 35 %; её можно выключить.
   Пачка объектов и группа пишутся одним шагом истории.

Поиск синхронный и укладывается в доли секунды на подложке 1280×1258
(≈ 2900 объектов — около 0,5 с). Для 4K подложек обработка уменьшается до
стороны 2560 px; координаты контуров пересчитываются в мир.

### Группы

- Сайдбар показывает группы свёрнутыми; участники рендерятся только при
  раскрытии и не больше 100 за раз («Показать все»).
- Карточка группы меняет только тронутые поля участников: цвет, границу
  (включение, цвет, толщина), скорость, подпись, набор декора и свою плотность
  заливки. Правка — один шаг undo.
- «Вывести из группы» ставит `groupId = null`; сама область остаётся.
- Группировать можно и вручную созданные области: выбор группы есть в карточке
  области.
- Сгруппированные области не дублируются в списках «Объекты» и «Поверхности»:
  они живут внутри группы.

### Конфликт версий

`map.save` вернул `MAP_VERSION_CONFLICT` — диалог с тремя исходами:

1. **Перезаписать** — повторный `map.save` с `force = true`.
2. **Продолжить редактирование** — черновик остаётся как есть.
3. **Сохранить копией** — `map.save` без `id`, имя «‹название› (копия)»,
   видимость `private`.

## Модель на карте

- **Место** — видимая точка с информацией. Клик по точке или по площадному месту
  открывает сведения.
- **Площадное место** — область с `nodeId`; маркер в центроиде не рисуется, но
  невидимый якорь остаётся для выбора.
- **Поверхность** — полигон с цветом, скоростью и ручками Безье на вершинах.
- **Объект** — полигон с цветом, скоростью и ручками Безье; `0` блокирует,
  `10000` открывает воду под мостом или воротами.
- **Лента** — река, ручей, дорога или мост. У каждого сегмента свои скорость и
  цвет; брод — это сегмент, а не тип. Границы цветов могут быть резкими или
  плавными (`colorBlend`), у воды включаются глубина русла (`decor.depth`) и
  декоративное течение (`decor.flow`).
- **Плотность заливки** — общая для карты (`fillOpacity`, по умолчанию 55 %);
  каждая лента или область может переопределить её в своём `decor.fillOpacity`.
  Это только вид: подложка и нижние объекты просвечивают сильнее или слабее.
- **Декор области** — набор символов (`decor.set`): трава, кроны, ели, жнивьё,
  луг, смешанный лес. Символы рассыпаются детерминированно и могут выходить за
  контур, поэтому край не выглядит обрезанным. Это только вид и повод для
  атмосферы, не игровая механика.
- **Маршрут** — A* по проходимой зоне между двумя кликами; на экране путь
  сглажен, цифры считаются по исходной сетке.

## Инструменты

| инструмент | действие |
|---|---|
| Выбор и панорама | клик — выбор; drag — перенос; Shift+рамка — массовое выделение объектов; Shift+клик — добавить или убрать из выделения; Ctrl+A — все объекты; Delete — удалить выбранное (одним шагом); пустое место — панорама; колесо — зум |
| Место | клик — новая видимая точка с информацией |
| Полигон | клики по вершинам, двойной клик/Enter — замкнуть; вершины и ручки Безье тянутся |
| Прямоугольник | два клика — область-прямоугольник |
| Лента | клики по осевой линии; Enter — завершить; вершины, ручки Безье и ширина |
| Маршрут | клик начала и конца на карте |
| Линейка | клики по произвольным точкам; расстояние по масштабу |
| Калибровка | отрезок по шкале + метры → `millimetersPerPixel` |
| Объекты по подложке | образец цвета → поиск пятен → превью → создание областей и группы |

### Порядок

`sort_order` у области и ленты; больше — выше. В панели выделенного объекта есть
«Выше» и «Ниже», работают клавиши `[` и `]`. Alt+клик перебирает все объекты под
курсором, если они перекрываются. Слои рисуются так: поверхности → ленты →
объекты; внутри слоя — по `sort_order`.

### Карточка области

- Шаблон: дом, стена, ворота, прилавок, мост, башня, луг, смешанный лес,
  ельник, роща, поле, гора, площадь, песок, болото, озеро. Шаблон задаёт только
  стартовые значения.
- Слой, цвет, скорость (0–100, `0` — непроходимо), подпись. Пресет не запрещает
  потом поменять цвет, подпись или скорость.
- «Граница»: отдельный от заливки цвет `#rrggbb` и толщина 1–8 экранных
  пикселей; переключатель выключает её полностью (`stroke = ''`). По умолчанию
  включена, цвет — затемнённая заливка.
- «Своя плотность заливки»: без переключателя область наследует плотность
  карты, с ним — задаёт 0–100 в `decor.fillOpacity`.
- «Рассыпать символы по области»: набор, плотность (символов на 10 000 px²),
  размер (40–250 %), разброс позиции и зерно. Смена набора подставляет его
  стартовые значения; поле, плотность, цвет и подпись остаются редактируемыми.
  Пресеты «Луг», «Смешанный лес», «Ельник», «Роща» и «Поле» включают декор сразу.
- Секция «Это место с информацией»: имя, короткая/публичная/GM-информация,
  иконка, связанная карта. Площадное место не создаёт маркер в центроиде.

У выбранной области видны вершины и ручки Безье: контур замкнутый, ручки
активной вершины показываются направляющими-заглушками даже на прямой, `Alt`
разрывает симметрию. Двойной клик по ребру вставляет вершину с делением кривой
без потери формы; удаление вершины убирает и её ручки. Для отрисовки,
hit-теста, центроида подписи и растрирования маршрута контур разворачивается
одной и той же функцией `flattenContour` (12 сэмплов на сегмент).

### Карточка ленты

- Шаблон: глубокая река, спокойная река, река, ручей, брод, грунтовая дорога,
  каменная дорога, тропа. Шаблон задаёт только стартовые значения.
- «Спокойная река» — пресет для реки с включённым течением: цвет, скорость и
  ширина подбираются под спокойное русло, `colorBlend` = 16, `decor.depth` и
  `decor.flow` включены, ширина глубины 85 %. После выбора все поля правятся
  вручную.
- Цвет и скорость ленты; у каждого сегмента — свои скорость и цвет либо выбор
  из частых стилей (река, мелководье, брод, дорога). «Ко всему» копирует
  базовый стиль на все сегменты.
- Плавные переходы: переключатель «Плавные переходы цвета» и ширина в
  пикселях подложки. По умолчанию 16; `0` — резкая граница. Переход строится
  линейным градиентом вдоль осевой и не длиннее половины соседних участков.
- «Своя плотность заливки»: без переключателя лента наследует плотность карты,
  с ним — задаёт 0–100 в `decor.fillOpacity`; `0` оставляет только контур.
- «Глубина русла»: 0–100 в `decor.depth`. `0` — плоская лента; больше — центр
  темнее, у берегов появляется светлое мелководье. Работает и на дорогах, но
  пресеты дорог оставляют 0.
- «Ширина глубины»: 20–100 % в `decor.depthWidth`, по умолчанию 85. Профиль
  занимает эту часть полной ширины, остаток у кромок — мелководье.
- Течение воды: переключатель «Течение воды», скорость (px/с), плотность
  (0–100), непрозрачность бликов (0–100), цвет бликов и зерно. По умолчанию
  выключено; включается вручную у конкретной ленты. Плотность задаёт, сколько
  бликов на единицу длины: от редких крупных до частой мелкой ряби. На маршрут и
  стоимость не влияет.
- Ширина: поле «Ширина линии» и «Применить ко всем»; в панели — «Ширина всех
  точек». `Shift` + перетаскивание ромба ширины масштабирует все точки
  пропорционально. Для новой ленты ширина задаёт стартовое значение.
- Шкала скорости в карточках — 0–100: обычная земля 50, грунтовая дорога 70,
  каменная 100, лес 20, брод 10, река 4. В снимке хранится в сотых.

Новая лента сразу сглажена; «Угол» возвращает прямые сегменты. У активной
вершины ручки Безье показываются направляющими-заглушками, даже если кривизны
ещё нет: потяните за них, `Alt` разрывает симметрию. «Сгладить» расставляет
ручки автоматически. «Ответвить» создаёт новую ленту из выбранной точки с теми же цветом,
скоростью и шириной. Края ленты строятся с ограничением митры.

### Отрисовка ленты

- Лента разворачивается в полилинию один раз; края с митрой считаются на весь
  контур, а не на каждый сегмент. Поэтому на стыках одинакового цвета нет
  клиньев и линий поперёк.
- Заливка идёт участками одинакового эффективного цвета
  (`segments[i].color ?? line.color`). Участки берут общие краевые точки, поэтому
  стыки совпадают; обводятся только левый и правый край, без торцевых сечений.
- На границе разных цветов при `colorBlend > 0` участки отступают на половину
  ширины перехода, а освободившаяся полоса заливается линейным градиентом.
- Плотность заливки берётся из `decor.fillOpacity`, иначе из `fillOpacity` карты
  (по умолчанию 55 %). Области используют то же правило. Контур берега рисуется
  непрозрачным и затемняется на 12 % от цвета заливки, поэтому остаётся виден
  даже при плотности 100 %.
- Глубина русла — подслои поверх заливки: 4 вложенные полосы от центра к
  `decor.depthWidth` (по умолчанию 85 % ширины) и мелководье в оставшейся полосе
  у кромок. Центр темнеет композитом `multiply` прохладным серым, а не чёрной
  плашкой; мелководье светлеет `screen`. Ширина полос — доля локальной ширины,
  поэтому широкие плёсы выглядят глубже. Границы полос почти не видны из-за
  малой альфы; на узких лентах (средняя ширина < 6 px) профиль пропускается.
  Подслои лежат в статичном слое; при почти прозрачной заливке профиль гаснет.
- Течение рисуется внутри клипа ленты как мягкая рябь. Каждый блик — изогнутая
  полоса с тающими концами: кромки повторяют дугу русла, толщина идёт по
  `sin(πs)`, поэтому на поворотах блик не превращается в прямую хорду.
- Касательные берутся из производной кубической кривой и интерполируются между
  сэмплами: направление блика меняется непрерывно, без «щелчков» на стыках.
- Цвет блика — смесь цвета воды под ним и `decor.flow.color`; поверх основной
  полосы лежит широкий бледный ореол, поэтому края мягкие, а не как у наклейки.
- Раскладка детерминирована `seed`: частицы распределены по дуге и ширине
  (чаще ближе к берегам), у каждой своя длина, толщина, цвет и множитель
  скорости — центр русла течёт быстрее берегов.
- Блики медленно едут вдоль осевой (направление — по порядку точек или против)
  и независимо мерцают: плавно гаснут и проступают. У берегов и на концах русла
  альфа уходит в ноль, чтобы блик не обрубался береговой линией и не «прыгал»
  с конца в начало.
- Анимация идёт до ~60 fps, останавливается, когда вкладка скрыта; при
  `prefers-reduced-motion` блики статичны.
- Течение не меняет hit-тест, ширину, маршрут и цифры расстояния/стоимости.

### Декор области

- Раскладка детерминирована зерном (`decor.seed`, `0` — id области) и полигоном:
  сетка с шагом из площади полигона, каждая точка сдвигается на долю шага
  (`decor.jitter`), точки вне полигона отбрасываются. Кэш ключуется id области,
  хешем пути и полями декора, поэтому пан и зум раскладку не пересчитывают.
- Набор — список слоёв с долями: `mixed` — 70 % травы, по 15 % елей и крон;
  `meadow` — 85 % травы и 15 % крон. Символ выбирается тем же генератором, что и
  сдвиг, поэтому смесь стабильна между перерисовками.
- Символы рисуются без клипа по полигону и без отступа от края: точка лежит
  внутри, но крона или куст могут выходить наружу. Так контур не «съедает»
  половину дерева.
- Декор непрозрачный и не наследует `fillOpacity` области или карты: при любой
  плотности заливки дерево остаётся плотным пятном. Иначе перекрытия
  полупрозрачных крон разных оттенков дают светлые кольца — «эффект Олафа».
- Цвет выводится из цвета области: трава — три оттенка, кроны и ели — четыре.
  Разброс по светлоте заметный, иначе ряд одинаковых кружков читается как сетка.
- Кроны и ели рисуются единым рядом по глубине: больший `y` ближе к зрителю и
  наносится позже, поэтому ближнее дерево перекрывает дальнее. Порядок точный
  всегда, без полос: внутри полосы ель с меньшим `y` могла оказаться поверх
  ближнего дерева. Стоимость — два вызова canvas на дерево; на плотном лесу
  (около 450 деревьев) это единицы миллисекунд.
- Трава и жнивьё — плоские символы и всегда лежат под деревьями.
- Декор поверхностей ложится поверх русел и дорог: крона у берега целиком
  свисает над водой и полотном, а не обрезается их краем. Точки, чьё основание
  попало в русло или в объект, не рисуются — лес не растёт из воды и из стен.
- Объекты рисуются поверх декора и полупрозрачны, поэтому из слоя декора
  вырезаются их полигоны (`destination-out`). Прямой клип не годится — на
  пересечении двух масок правило even-odd снова открывает дырку.
- При отдалении размер символа не падает ниже ~3 экранных пикселей, поэтому лес
  остаётся пятном, а не исчезает.
- Декор не участвует в hit-тесте, маршруте, стоимости и проходимости. Он живёт
  только в карте и не претендует на роль декора боевой сцены: для батлграунда
  нужен отдельный слой с якорями и окклюзией.

### Статичный слой и производительность

- Фон, подложка, сетка, поверхности, заливка и берега лент, их декор, объекты и
  маршрут собираются в offscreen-canvas и блитятся как один слой. Он
  пересобирается только при смене варианта, ресайзе, правке данных или загрузке
  подложки.
- Геометрия и `Path2D` кэшируются **по области**: правка проверяется по ссылкам
  на `path`/`handles`, а мутаторы черновика заменяют массивы (copy-on-write).
  Перетаскивание пересобирает путь только у изменённого объекта; остальные
  пути складываются в батч через `addPath` (на 6000 объектах ~10 мс вместо
  ~300 мс пересборки).
- Холст работает с сырыми (`toRaw`) ссылками на карту и вариант: он всё равно
  перерисовывается по `revision`, а обход реактивных прокси на 6000 областях
  стоил десятки миллисекунд на кадр.
- Доступ к области идёт через индекс `Map<id, area>`, а не через `find` по
  списку. Правка черновика сообщает о себе счётчиком `revision`: глубокий watch
  по всей карте не обходит тысячи областей на каждый кадр.
- Области, декор и блокеры декора отсекаются по видимому прямоугольнику мира.
  Одинаково оформленные области рисуются одной пачкой `Path2D`: на 6000
  объектах это десятки миллисекунд вместо сотен.
- Hit-тест сначала отсекает области по рамке (вершины + концы ручек) и только
  потом разворачивает Безье. Кандидаты хранят сырую форму, поэтому клик по
  объекту на карте с 6000 объектами занимает ~20 мс, а не сотни.
- Раскладка декора и блокеры кэшируются в записи области; точки декора
  фильтруются по равномерной сетке блокеров, а не перебором всех полигонов.
- Пока тянут объект (область, ленту, вершину, ручку, ширину), статичный слой
  собран без него: первая правка пересобирает слой один раз, дальше двигающийся
  объект рисуется поверх. Внутри транзакции перетаскивания ревизия черновика не
  растёт на каждое движение — она меняется один раз в конце, поэтому кэши
  геометрии и `Path2D` не пересобираются на 6000 объектов каждый кадр.
  После отпускания слой собирается заново с объектом в новом положении.
- Маршрут больше не делает глубокий `watch` по всему черновику: на 6000
  объектах Vue обходил весь граф на каждое движение мыши (секунды на кадр).
  Сброс маршрута идёт по смене ссылки на карту, а правки в режиме маршрута
  невозможны.
- Пока тянут объект, анимация ряби останавливается: иначе она добавляет второй
  полный проход отрисовки на кадр. После отпускания рябь включается снова.
- Снимки истории сериализуются через `toRaw` (~33 мс на 6000 объектов вместо
  ~450 мс через прокси) и снимаются лениво — только при первой реальной правке,
  поэтому клик без сдвига историю не трогает. Флаг `dirty` — отдельный
  счётчик правок, а не сравнение JSON всего черновика (раньше ~1 с на кадр).
- Пока крутится колесо, показывается прошлый готовый слой, растянутый под новый
  масштаб; чёткая перерисовка приходит через ~120 мс после затишья. Панораму
  рисуем сразу — с отсечением это дёшево.
- Кадр анимации поверх статичного слоя рисует только рябь, подсветку выбора,
  места, ручки и черновики. Подписи областей лежат в отдельном экранном слое и
  пересобираются вместе со статичным.
- Подписи — с LOD: место (`nodeId`) и выделенная область подписаны всегда,
  остальные — когда область на экране не меньше 44 px. Кнопка «Подписи
  объектов» в тулбаре показывает все подписи независимо от масштаба.
- `MapRibbonService.layout` кэшируется по подписи геометрии, поэтому разворот
  ленты и края не пересчитываются каждый кадр.

### Маршрут

В режиме «Маршрут» клик задаёт начало, второй клик — конец. Путь рисуется на
канвасе; панель показывает координаты, расстояние и стоимость. Если точка попала
в блокер, она прижимается к ближайшей проходимой клетке. Кнопка «Сбросить»
очищает маршрут.

Перед отрисовкой путь упрощается (Дуглас — Пекер) и сглаживается схемой Чайкина;
концы остаются на месте. Это только вид: `distancePixels` и `costPixels`
приходят из несглаженной сетки.

## Компоненты

- `MapCanvas.vue` — единственный canvas: подложка, поверхности, ленты
  (непрерывные участки, градиенты, течение), объекты, места, маршрут, черновики,
  выделение, подписи областей.
- `MapToolbar.vue` — режим, инструмент, вариант, подложка, undo/redo, зум, fit,
  подписи объектов, «Сохранить», индикатор изменений, справка.
- `MapSidebar.vue` — места, группы, объекты, поверхности, ленты; фильтр «только
  именованные»; длинные списки режутся до 100 строк с «Показать все».
- `MapNodeDialog.vue` — точечное место: имя, `shortInfo`, `publicInfo`, `gmInfo`,
  `linkedMapId`, иконка.
- `MapAreaDialog.vue` — поверхность или объект: шаблон, слой, цвет, граница,
  скорость, подпись, информация места.
- `MapLineDialog.vue` — лента: шаблон (включая «Спокойную реку»), цвет, скорость,
  ширина (+ «Применить ко всем»), плавные переходы, течение, стили сегментов,
  подпись.
- `MapVariantDialog.vue` — вариант: label, `fromMinutes`, `sortOrder`, файл,
  масштаб, default.
- `MapRoutePanel.vue` — координаты начала и конца, расстояние, стоимость, сброс.
- `MapRecognitionPanel.vue` — образцы, настройки поиска, статистика, поля
  создаваемых объектов и кнопка создания.
- `MapGroupDialog.vue` — массовые свойства группы: название, цвет, граница,
  скорость, подпись, декор, плотность заливки.
- `MapHelpDialog.vue` — справка по инструментам, порядку и клавишам.
- `MapCreateDialog.vue` — имя, описание, видимость.
- `MapSettingsDialog.vue` — правка карты, архив.
- `MapCalibrationDialog.vue` — метры по откалиброванному отрезку.
- `MapConflictDialog.vue` — перезаписать / продолжить / копия.

## Сервисы

- `MapViewportService` — мир ↔ экран, zoom, pan, fit.
- `MapGeometryService` — длина, площадь/центроид, point-in-polygon, расстояние
  до отрезка, пересечение, попадание в ленту, разворот Безье, касательная,
  нормаль, деление кубического сегмента, разворот замкнутого контура, ручки
  контура, упрощение и сглаживание пути.
- `MapRibbonService` — разворот ленты с индексом сегмента, участки одинакового
  цвета, края с митрой, зоны градиентного перехода и частицы ряби течения с
  детерминированной раскладкой.
- `MapHitTestService` — место → объект → лента → поверхность; допуск ленты =
  `width / 2`.
- `MapDecorService` — детерминированная рассыпка символов по полигону области:
  набор, плотность, масштаб, разброс, зерно и кэш раскладки.
- `MapDecorPainter` — примитивы травы, крон, елей и жнивья; оттенки выводятся из
  цвета области, кроны и ели идут по глубине, без клипа по контуру. Вырезание
  масок лент и объектов делает canvas, а не painter: у него общий проход декора.
- `MapRenderService` — наследование плотности заливки и глубины от карты.
- `MapRecognitionService` — маска по образцам, эрозия как семена, водораздел по
  исходной маске, контуры, заливка дворов, упрощение с жёстким потолком вершин,
  аппроксимация плавных участков дугами Безье, ремонт самопересечений и
  статистика отсева.
- `MapRouteGrid` — растровая сетка и A* по черновику (зеркало серверного).
- `MapApi` — пять действий `map.*`; `MapApiError` с кодами и русскими
  подсказками.

## Композаблы

- `useMapList` — страница, поиск, архив, создание карты.
- `useMapDetail` — загрузка снимка, каталог, выбор варианта.
- `useMapDraft` — копия снимка, правки, `dirty`, публикация, конфликт, копия;
  история undo/redo и транзакции drag.
- `useMapEditor` — вид, инструмент, черновики, линейка, калибровка,
  перетаскивание объектов, вершин, ручек и ширины.
- `useMapRecognition` — загрузка подложки, образцы, настройки, превью,
  включение/исключение пятен и создание пачки с группой.
- `useMapRoute` — две точки, локальная сетка, маршрут и ошибка.

Логика — в классах `Service/` и композаблах, не в `.vue`. Canvas — единственное
место рисования.

## Следующие срезы

- **Атлас спрайтов.** Процедурные глифы закреплены как рабочий вариант; если
  понадобится рисованный вид, painter заменяется на спрайты из `Core/File`,
  а раскладка и контракт остаются теми же.
- **Гора и рельеф.** Отдельный слой декора с y-сортировкой, вертикальным
  смещением и тенью: гора «возвышается» над поверхностью. Текущий декор плоский
  и на рельеф не претендует.
- **Смеси по подзонам.** Сейчас набор один на область; если понадобится
  опушка из крон и ельник в глубине, это отдельные области с разными наборами,
  а не новый контракт.
- **Распознавание в воркере.** Сейчас поиск идёт синхронно в основном потоке;
  на 4K-подложках его стоит унести в Web Worker.
- **История по областям.** На 6000 объектах один снимок — ~2,2 млн символов,
  поэтому лимит объёма оставляет около 5 шагов undo. Снимок только изменённой
  области даст десятки шагов, но требует отдельного контракта истории и пока
  отложен.
- **Правка группы на карте.** Массовые свойства меняются в карточке; выделение
  всей группы кликом по её участнику — следующий шаг.
