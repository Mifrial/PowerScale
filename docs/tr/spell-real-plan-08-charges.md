`spell.charge` (выдача, `state_code`, `default_cap`, `spend`), кап из
«Накопления зарядов» по опыту электромансии, трата заряда сопутствующим

M6 довёл поддержание до конца, но «Генератор молний» остался декоративным:
его `spell.charge` сервер не читает. M8 оживляет карточку: заряд выдаётся
при сотворении и обновлении поддержания, тратится сопутствующим действием
на известное заклинание электромансии.

## 1. Границы

Входят:

- чтение `spell.charge` из живой карточки: `state_code`, `grant`,
  `default_cap`, `spend` (`amount`, `action_points`, `keyword_code`,
  `creation_max`, `exclude_duration_types`);
- выдача заряда при успешном сотворении и при каждом обновлении
  поддержания, не выше капа;
- кап: `default_cap`, а при выученном улучшении с `charge_cap` — база и
  ступени по опыту признака (`experience_keyword_code`);
- трата: `chargeSpellId` в теле каста, цена — `spend.action_points` вместо
  ОД создания цели, заряд −1;
- проверки траты: строка этого кастера и боя, заряд не ниже `amount`, у
  цели есть `spend.keyword_code`, её длительность не в
  `exclude_duration_types`, Создание не выше лимита ОД на ход при
  `creation_max: turn_ap`, источник и путь совпадают с Генератором;
  мощь цели проверяется обычным кастом (потолок характеристики), а не
  мощью поддержания Генератора;
- каст с зарядом не занимает источник повторно: источник уже занят самим
  Генератором, и это разрешённая пара;
- заряд — состояние листа с привязкой `boundSourceKey` (один источник — одно
  заклинание M6); обрыв, потеря источника и трата до нуля снимают строку
  состояния;
- чат: выдача и трата заряда;
- real-фронт: плитка «Сотворить» у состояния и у строки поддержания,
  фильтр целей, `chargeSpellId` в запросе.

Не входят:

- «одно активное волшебство на кастера» — M11;
- стабильность, дестабилизация и drop по силе — M7;
- накопители, мана и несколько источников — M10;
- новые карточки с `spell.charge` — контент.

## 2. Решения

1. Хранение заряда — состояние листа `state_code` из карточки с
   `boundSourceKey` источника поддержания. Отдельной колонки в
   `game_active_spell` нет: карточка называет заряд состоянием, а один
   источник — одно заклинание (M6). Привязка по источнику, а не по id
   строки, позволяет писать выдачу в той же транзакции, что и каст.
2. Создание всегда заменяет прежнюю строку заряда на этом источнике:
   устаревший заряд прошлого боя не суммируется с новым.
3. Обновление поддержания добавляет `grant` и клампит по капу.
4. Трата до нуля удаляет строку состояния; ноль в листе не висит.
5. Кап считается на сервере: улучшение ищется по `spell_upgrade.charge_cap`
   и `parent_ability_code` равному коду заклинания, опыт — по
   `experience_keyword_code`; код заклинания и признаки не зашиваются.
6. Цена траты заменяет только ресурс хода; прочие компоненты карточки
   остаются. Для касания действует существующее слияние трат удара
   (`maxSpends`), новых правил не вводим.
7. Привязка заряда к источнику означает, что после конца боя без обрыва
   состояние может остаться в листе. Это известный долг: чистится при
   следующем создании на том же источнике и при обрыве/потере источника;
   отдельная уборка на конце боя — после M8.
8. Каст через заряд — сопутствующее действие того же источника, а не
   второй каст: при `chargeSpellId` занятость источника не проверяется.
   Переводить «Генератор» с `sustained` на `refreshable` не требуется;
   `refreshable` — отдельная длительность со своим рантаймом (сейчас
   поддержаны только `instant` и `sustained`).

## 3. Срезы

### 3.1. Rule → Game чтение

- `GameSpellCharge` (Game): карточка → `SpellCharge`, кап по улучшению,
  строки состояния на источнике, операции выдачи/траты/снятия.
- Кап: `CharacterKeywordExperience::experience` с уровнями листа.
- Лимит ОД на ход: `resources` листа по коду ресурса хода.

### 3.2. Выдача

- Обычный каст: операции заряда входят в запись каста; строка создаётся,
  только если каст успешен и длительность `sustained`.
- Касание: то же в `GameSpellTouchFinish`.
- Поддержание: `GameActiveSpellSustain` пишет `+grant` вместе с ценой тика.
- Чат о выдаче — в тред хода.

### 3.3. Трата

- `GameSpellCastBody`/`CastGameSpellInput` и блок касания принимают
  `chargeSpellId`.
- `GameSpellCastFacts::prepare`: загрузка строки, проверки, замена траты
  ресурса хода на `spend.action_points`, признак `chargeSpend` в подготовке.
- `GameSpellCast`/`GameSpellTouchFacts`: занятость источника не проверяется,
  если каст идёт через заряд.
- `GameSpellCast`/`GameSpellTouchFinish`: операция `patchState`/`removeState`
  в той же записи листа; при неуспешной проверке сотворения заряд всё равно
  тратится (каст состоялся).
- Чат о трате — в сообщении каста.

### 3.4. Снятие

- `GameActiveSpellDrop` и потеря источника на входе хода снимают строки
  состояния, привязанные к источнику.
- Смена состава и конец боя снимают строки поддержания (M6); заряд
  остаётся долгом 2.7.7.

### 3.5. Фронт

- `ActiveSpell` → состояние заряда ищется по `boundSourceKey`, если нет
  `boundSustainId` (real-ветка).
- `CombatProcessListService`: строка поддержания показывает заряд и
  «Сотворить».
- `CombatCardPanel`: плитка состояния с зарядом открывает каст через
  заряд; детали состояния не называют заряд «Ядром».
- `SpellCastDialog`: `chargeSpellId` в запросах каста и касания; фильтр
  целей по спецификации; моковая запись заряда остаётся только в моке.

## 4. Тесты

- кап: `default_cap`, улучшение `base`, ступени `cap` и `per_experience`;
- выдача при создании и при обновлении поддержания, кламп по капу;
- трата: цена 2 ОД, заряд −1, строка при нуле снимается;
- отказы: нет заряда, чужой кастер, другая длительность, нет признака,
  Создание выше лимита, источник/путь не от Генератора; мощь цели
  ограничивает только обычный каст;
- касание: тот же каст через удар;
- replay не дублирует выдачу и трату;
- обрыв и потеря источника снимают заряд.
