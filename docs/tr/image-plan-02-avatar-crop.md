# План Image 2 — выбор кружка аватара и показ по сайту

**Статус:** ~СДЕЛАНО~

**Реализация:** ~PHP~, ~VUE~

**Опираться на:** ~PHP~ (`Image`, `File`, `User`), `image-plan-01.md`

Первый заход (`image-plan-01.md`) дал аватару центр-кроп 512×512 и показ
только в профиле. Этого мало: пользователь не выбирает, что попадёт в круг,
оригинал нельзя перекропить без повторной загрузки, а остальные места сайта
продолжают рисовать инициалы.

Этот план чинит четыре вещи:

1. при выборе картинки открывается кроппер: круг по центру, картинку двигаем
   и зумим;
2. сервер хранит выбранный прямоугольник и режет производную по нему;
3. источник аватара можно переиспользовать: «Мои изображения» показывают уже
   загруженные файлы, выбор старого оригинала возвращает его в работу;
4. аватар показывается везде, где нарисован пользователь: меню, чат, группы,
   участники и заявки игры.

## 1. Решения

- **Кроппер — фиксированный круг.** Как в Telegram/VK: круг всегда по центру,
  картинка таскается мышью/пальцем и зумится слайдером или колесом. Так проще
  гарантировать, что картинка покрывает круг без пустых краёв, и меньше
  валидации на сервере.
- **Кроп в пикселях исходника.** `user_avatar` хранит `source_file_id`,
  `crop_x`, `crop_y`, `crop_size` (сторона квадрата). Координаты — в
  ориентированной картинке: браузер уже применил EXIF, а `Core/Image`
  применяет `orient()` до кропа.
- **Производная нужна.** Оригинал остаётся у пользователя для повторного
  кропа, но отдавать его в каждый аватар нельзя: это мегабайты на каждую
  строку списка. Производная — квадрат выбранного кружка, 256×256 webp q90:
  этого хватает на 120 px профиля при 2× DPR, и она весит десятки килобайт.
  Число живёт в `Core/User`; `Core/Image` про аватары не знает.
- **Источник — обычный файл пользователя.** Никакой отдельной загрузки
  «только для аватара»: `file.upload` → `file.findOwnImages` → `user.setAvatar`.
  Старые оригиналы остаются в списке, поэтому переключение на прежнюю
  картинку не требует повторной загрузки.
- **История кропов не хранится.** При выборе старого оригинала круг
  сбрасывается в центр, пользователь поправляет. Точное восстановление
  прошлого кропа — отдельная задача, если появится запрос.
- **Показ — один компонент.** `UserAvatar` в `Core/User` рисует либо
  производную через `FileImage`, либо инициалы. Все места сайта используют
  его, а не собственные `v-avatar`.

## 2. Контракты

### 2.1 Image

`Dto/ImageCrop`: `x`, `y`, `width`, `height` в пикселях исходника.
`ImageTransformSpec` получает необязательный `crop`; порядок операций —
`decode` → `orient` → `crop` → `fit` → `encode`. Кроп вне границ после
ориентации — `IMAGE_SPEC_INVALID`.

### 2.2 File

`file.findOwnImages` (`csrf: true`) — страница неархивных картинок текущего
актора, без права `file.view`:

```php
public function findOwnImages(FindOwnImagesInput $input): array;
// { items: FileEntry[], total: int }, фильтр: owner = actor, is_archived = false,
//   is_derived = false, mime LIKE image/%
```

`is_derived` — новый признак строки `file`: производные (`storeDerived`) не
должны попадать в список источников аватара. `FileRepository::findOwnImagePage(ownerId, limit, offset)`
— тот же порядок `created_at desc, id desc`, что у админской страницы.

### 2.3 User

`user_avatar` получает nullable-колонки:

```
source_file_id IntField  nullable, indexed
crop_x         IntField  nullable, min 0
crop_y         IntField  nullable, min 0
crop_size      IntField  nullable, min 1
```

Старые строки остаются валидными: `source_file_id = null` — источник
неизвестен, аватар показывается, но «Изменить» предложит выбрать файл.

`user.getAvatar` → `{ avatar: string|null, source: { publicId, originalName,
width, height }|null, crop: { x, y, size }|null }`.

`user.setAvatar` — плоский вход (вложенный DTO биндер не гидрирует):

```php
filePublicId: string|null
cropX: int|null
cropY: int|null
cropSize: int|null   // квадрат
```

`filePublicId = null` снимает аватар. Если кроп не передан, Image делает
центр-кроп сам (`cover` без `ImageCrop`). Переданный кроп проверяется
адаптером после `orient()`; наружу это `USER_INVALID`.

Порядок: проверка владельца → проверка политики файла → `copyOwnedTo` →
`Image::transform` с кропом → `storeDerived` → upsert `user_avatar` →
архив старой производной. Исходник не трогаем.

### 2.4 JSON Member группы

`userGroup.getMembers` добавляет `avatar` (`public_id` производной или
`null`), собирается тем же `IUserViews::assembleMany`, что и User, — без N+1
на членов.

## 3. Фронтенд

- `UserAvatar.vue` — кружок: `FileImage` при `user.avatar`, иначе инициалы.
- `AvatarCropStage.vue` — чистый кроппер: фиксированная сцена, картинка
  позиционируется и масштабируется, круг вырезан box-shadow. Математика
  вынесена в `Service/AvatarCropMath.ts` и покрыта vitest.
- `UserAvatarDialog.vue` — два шага: выбор источника (загрузить / «Мои
  изображения») и кроп. Ошибки сервера показываются как есть.
- `UserAvatarField.vue` — аватар, «Изменить» и «Снять». Подсказка про
  2 МБ/512 px убрана.
- `useAvatarUpload` — загрузка и `user.setAvatar(publicId, crop)`.
- `useAvatarEditor` — состояние диалога: текущий источник/кроп из
  `user.getAvatar`, список своих картинок.
- Показ: `SideBar`, профиль, слайдер, `GroupDetailPage`, чат
  (`ChatListItem`, `ChatMessageRow`), участники/заявки/приглашения игры.

## 4. Срезы

- **A1 — Image.** `ImageCrop`, кроп в спецификации, тесты на координаты и

- **A2 — File.** `findOwnImages` + репозиторий + тест на «только свои и

- **A3 — User.** Колонки, `UserAvatarRecord`, `getAvatar`, кроп в

## 5. Тесты

- Image: кроп левой/правой половины даёт ожидаемый цвет и размер; кроп за
  границей — `IMAGE_SPEC_INVALID`.
- File: `findOwnImages` возвращает только свои неархивные картинки, чужой
  файл и не-картинка не попадают.
- User: `setAvatar` с кропом; повторный вызов с тем же источником меняет
  производную; `getAvatar` отдаёт источник и кроп; кроп за границей —
  `USER_INVALID`; снятие чистит строку.
- Фронт: математика кроппера (roundtrip, клампы), mock `getAvatar`/
  `setAvatar`, store обновляет `currentUser`.

## 6. Риски

- **EXIF.** Координаты кропа — в ориентированной картинке. Браузер и Imagick
  применяют ориентацию одинаково; хранимые `file.width/height` могут быть
  неориентированными, поэтому границы кропа проверяет Image после `orient()`,
  а не User по строке файла.
- **Память.** Кроп не отменяет лимиты Image: 40M пикселей и 20 000 px.
  Потребитель дополнительно режет сторону источника до 4096.
- **Сироты.** Каждый перекроп создаёт новую производную; старая архивируется.
  Уборка архивных файлов — по-прежнему отдельная задача.
- **Миниатюры «Моих изображений».** Список показывает оригиналы; при
  десятках больших картинок это заметная загрузка. Отдельные превью —
  следующий шаг File, не блокер аватара.
