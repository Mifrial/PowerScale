# Реестр claims миграции ТР

**Статус:** claim-level реестр, 2026-08-30.

Источник всех legacy claims — [`history/TR-legacy-2026-08.md`](history/TR-legacy-2026-08.md). Поля каждой записи: legacy range, atomic claim, canonicalOwner, destination, evidence, source status, implementation status и disposition. Если одна строка содержит несколько осей, это временная parent-запись; дочерние claims должны иметь независимые статусы и evidence.

Статусы:

- `CURRENT` — подтверждено кодом/тестами и переносится в текущий документ;
- `DECISION` — закреплено решением;
- `REQUIREMENT` — требование старого ТР сохраняется, но реализация не подтверждена;
- `OPEN` — нужен backend/архитектурный контракт или вопрос Андрею;
- `BACKLOG` — решение есть, реализации нет;
- `HISTORICAL` — заменено более новым решением;
- `DEFERRED` — сознательно отложено.
