# План M16 — эффекты заклинаний и «Восприятие магии»

**Статус:** ~СДЕЛАНО~, 2026-11-16. Срезы 16.1–16.4 готовы: `spell.effects`
разбирается Rule, временные чувства входят в пересчёт листа, Game считает
эффект из активной строки, ревизия 58 добавила эффект `magic-perception`,
ревизия 59 — цену создания в ходах (`count: 1`). Ручная проверка в бою и
полный прогон пройдены.

**Реализация:** ~PHP~. Мок-путь чувства не берём за эталон: сервер считает
эффект из активной строки заклинания. Фронт ничего не дублирует.

**Опираться на:** ~PHP~ (`SpellSpec`, `SpellSpecs`, `AbilitySpellSpec`,
`CharacterSheets`, `CharacterSheetLive`, `CharacterLiveSenses`,
`CharacterLiveCharacteristics`, `GameActiveSpellRepository`,
`GameCharacterProjection`, `GameNpcProjection`, `GameSpellCastFacts`),
контент (`magic-perception`, `magic-sensation`).

**Родитель:** [`spell-real-roadmap.md`](spell-real-roadmap.md), шаг M16.

## 1. Границы

- Только чувства. Состояния, характеристики, проверки и урон через эффекты
  не добавляются: для них нет контента, а форма должна родиться из карточек.
- Только поддерживаемые заклинания. Эффект живёт, пока существует строка
  `game_active_spell`; мгновенные эффекты — отдельный срез.
- «Предел постижения магии» не моделируется: по
  `magic-content-plan-03-arcanist-advanced.md` его нет ни в `SenseSpec`, ни в
  значении чувства. Он вернётся вместе с анализом структур (M14, отложен).
- `time-conversion`, анализ и не боевой режим не входят.

## 2. Решения

1. **Эффект — форма спеки, не код карточки.** `spell.effects` — список
   объектов с дискриминатором `type`. Механика читает только форму; кода
   `magic-perception` в Game нет.
2. **Эффект не пишется в лист.** Источник истины — строка
   `game_active_spell`. Проекция листа пересчитывает чувства на чтении и
   добавляет эффект, пока строка жива. Прекращение поддержания, обрыв и
   конец боя удаляют строку — эффект исчезает сам, без отдельной операции
   листа и без рассинхронизации версий.
3. **Форма `sense`:**
   ```json
   {
     "type": "sense",
     "sense_code": "magic-sensation",
     "status": "imprecise",
     "radius": {"from": "sustain_power"},
     "value": {"from": "control", "reference": {"base": 4, "size": 1}}
   }
   ```
   `status` необязателен: без него берётся статус из `SenseSpec`.
4. **Источники значений** (`from`): `power` (мощь сотворения), `sustain_power`
   (текущая мощь поддержания), `control` (Контроль пути кастера) и
   `parameter` (`parameter_code` из активационных параметров). Неизвестный
   источник — отказ, а не приблизительное исполнение.
5. **Значение чувства.** Для размерного источника с `reference` значение
   равно разнице в пунктах шкалы характеристик:
   `source.characteristicDiffTo(reference)`. При `magic-control = {4|0}` и
   `reference = {4|1}` это `−3`. Без `reference` размерный источник даёт
   `value = 0` (явно, а не «как получится»). Для `parameter` значение — само
   число параметра.
6. **Радиус чувства.** Для `power`/`sustain_power`/`control` радиус — та же
   размерная пара, что и источник; для `parameter` — `{base: значение, size: 0}`.
   Радиус трактуется как ипари, как и остальные дистанции.
7. **Слияние с чувствами листа.** Проекция передаёт вычисленные строки в
   пересчёт листа (`CharacterSheets::compute(..., $runtimeSenses)`).
   `CharacterLiveSenses` добавляет их к грантам; при совпадении кода значения
   складываются, статус берётся сильнейший. Это же значение участвует в
   выборе лучшего бонуса к Внимательности, поэтому чувство честно меняет
   Внимательность, а не только список чувств.
8. **Только поддерживаемые.** Если у карточки есть `spell.effects`, а
   длительность не `sustained`, каст отвергается: молчаливой пустышки быть
   не должно. Активная строка у нас одна на источник, и это `sustained`.
9. **Контент — ревизия 59.** 58 добавила `magic-perception` `spell.effects` из
   решения 3, 59 заменила `chosen` на `limit` в компоненте создания. Новых
   правил не добавляем: `magic-sensation` уже есть в БД.
10. **Чат и карточка боя.** Отдельной строки в чате в первом срезе нет:
    эффект виден в листе (попап Внимательности) на время поддержания.
    Если ручная проверка покажет, что этого мало, добавим строку объявления
    эффекта в итерации.
11. **Компонент «N ходов».** Создание карточки измеряется ходами, а ход —
    полный лимит ресурса хода (у ОД — лимит ОД персонажа). Это не выбор
    игрока, поэтому `chosen` здесь неверен. Введена форма количества
    ресурса `amount: {"type": "turn", "count": N}`: сервер берёт `N ×
    лимит` из листа (база строки плюс вклады), а не текущее значение.
    Для 1 хода `count: 1`, для 2 ходов — `2`, для минуты (10 ходов) — `10`;
    меняется только число, механика та же. Фронт показывает тот же лимит.
    Тела каста не принимают `chosenAmounts`: сумма целиком серверная.
    Цена маны при поддержании — мощь × `count`, потому что
    `GameSpellMana` делит потраченное на лимит хода.

## 3. Срезы

### 16.1. Rule: форма `spell.effects`

- `SpellEffect` (интерфейс) и `SenseSpellEffect`;
- `SpellSpec::getEffects()`, разбор в `SpellSpecs::effects()`;
- тесты формы: пустой список, `sense`, неизвестный `type`, неизвестный
  `from`, отсутствующий `sense_code`, `parameter` без кода.

### 16.2. Character: временные чувства в пересчёте листа

- `ICharacterSheets::compute(..., array $runtimeSenses = [])`;
- `CharacterSheetLive`, `CharacterLiveCharacteristics`, `CharacterLiveSenses`
  принимают и сливают временные строки;
- тест: чувство появляется в `sheet.senses`, лучший бонус меняет
  Внимательность, снятие строки возвращает исходное значение.

### 16.3. Game: вычисление эффекта из активной строки

- `GameActiveSpellRepository::findForGameCaster()`;
- `GameSpellEffect` — вычисляет строки чувств из карточки и активной строки
  (мощь поддержания, Контроль пути, параметры);
- `GameSpellCastFacts` отвергает эффекты у не-поддерживаемых заклинаний;
- `GameCharacterProjection::sheet` и `GameNpcProjection::sheet` добавляют
  временные чувства в пересчёт;
- тесты: юнит на вычисление (мощь/контроль/параметр), MySQL/HTTP — каст
  «Восприятия магии», чувство в листе, смена мощи поддержания меняет радиус,
  drop убирает чувство.

### 16.4. Контент и ручная проверка

- `tools/rule-migrate-58.php`: `magic-perception` + `spell.effects`;
- `tools/rule-migrate-59.php`: компонент создания `amount: {type: turn, count: 1}`;
- публикация ревизий 58–59, ручная проверка в бою: каст, лист, Внимательность,
  поддержание с другой мощью, прекращение.

### 16.5. Гейт и документы

- `composer stan`, `composer test:unit`, профильные MySQL/vitest;
- `docs-check`, `maps-check`;
- полный `bash tools/test-full.sh` — после ручной проверки и подтверждения.

## 5. Осталось

- Многоходовое сотворение (`count` ≥ 2): каст не уходит в долг, поэтому
  заклинание на 2+ хода отвергается, если текущего ресурса меньше
  `count × лимит`. Это не про форму спеки — нужно решение, как платить
  по ходам (долг, растяжка сотворения, отказ); см. открытое решение 10
  роудмапа. Сейчас такой карточки в контенте нет.
- Мгновенные эффекты (не на время поддержания) — отдельный срез.
- Другие типы эффектов: состояние, характеристика, проверка — только вместе
  с карточками, которые их требуют.
- «Предел постижения магии» — вместе с анализом структур (M14 отложен).
