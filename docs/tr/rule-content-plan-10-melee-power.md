# C2 — аудит и посадка ветки ближнего боя «Сила»

**Статус:** `IN_PROGRESS`, 2026-09-17. Срезы A–H в коде: слоты, Удвоенная мощь, Яростный рывок.  
**Родитель:** [`rule-content-roadmap.md`](rule-content-roadmap.md).  
**Очередь:** [`rule-content-queue.md`](rule-content-queue.md).  
**Предыдущая ветка:** [`rule-content-plan-09-melee-speed.md`](rule-content-plan-09-melee-speed.md).

Цель — посадить базу ветки «Сила» через уже существующие атаки, `ActionEffectService`, состояния и профили оружия. Не городить сервис на каждую карточку. Улучшения (`yarostnyy-ryvok`, `udvoennaya-mosch`) не открывать, пока не сидит база.

Коды ниже — идентификаторы текущего снимка каталога, не имена тестов.

## 1. Границы

### База (эта ветка)

1. `razmashistyy-udar` — Размашистый удар;
2. базовый **Толчок** (карточки нет; авто-действие как `simple-melee-attack`);
3. `tolkayuschiy-udar` — Толкающий удар (через базовый Толчок);
4. `silovoy-udar` — Силовой удар;
5. `shirokiy-udar` — Широкий удар.

Плюс состояния, без которых Толчок не живёт: **Неустойчивость**, **Лежачее положение**.

### Не входит в базу A–G

- дети Размашистого: Яростный рывок, Удвоенная мощь — срез H после слотов рук (§14);
- Количество / Точность / Манёвры;
- `podgotovka`, `oboerukaya-ataka`;
- перк «толкать произвольным оружием»;
- карта / adjacency / facing / размер цели;
- PHP;
- unit-тесты на конкретные коды правил из БД.

## 2. Порядок посадки

```text
A. Размашистый (спека почти сидит — проверка pending)
B. Лежачее положение + «Лечь или встать» (state + action_codes)
```

## 3. Что уже есть в коде

- `ActionEffectService`: `current_action_attack_characteristic_modifier`, `current_action_check_modifier` (источник **обстоятельства**), pending `after_action_until_resource_spent_check_modifier`. Pending вешается на **инициатора** (`HitLaunchDialog` / `ActionLaunchDialog`).
- HitLaunch: pending атакующего → `attackerAdvantageModifiers`; pending цели → `defenderAdvantageModifiers`. Игнор: защиты нет, `ignoreDefense` ближнего `{0|-1}` (0 маленьких).
- `stateRuntimeEffectsService.checkAdvantageFromStates(..., { kind: 'hit' })` уже суммируется и в `attackerAdv`, и в `defenderAdv`.
- `attackAtDistance(..., actionCharacteristicModifier)` пересчитывает урон от временной Силы.
- Wide: `attack_mode: 'wide'`, `max_targets: 3`. HitLaunch сейчас даёт **`+(n−1)`** ко всем целям — знак наоборот.
- Авто-действия: зона `automatic` + keyword 71.
- `check-hit`, `check-strength`, `check-dexterity` есть. Отдельного `check-push` нет.
- `ActionEffect.apply_state` в DTO уже есть.
- Состояния: `check_advantage` + `includes_hit` + `per_unit` (увечье). `action_codes` → кнопки на карточке (`CombatCardModelService.linkedStateActions`, эталон раны: `perevyazat` / `zazhat`).
- `stand-up` («Лечь или встать»): `automatic`, 3ОД, операция `posture: standing_or_prone`. **State нет, −6 к Ловкости нет.**
- `ruka` — врождённый strike. У щитов strike в `shield.weapon_profiles`. `shield-any_tolchki_i_shchiti` — преимущество к Силе на толчки, не разрешение толкать.
- Источник «Действие»: `ADVANTAGE_SOURCE_ACTION`.

## 4. Размашистый удар

Карточка уже сажает текущий удар: +2 Силы (`hit_count: 1`), −2 `check-hit` обстоятельства, pending −2 до 2 ОД.

Pending на владельце. Сам бьёт — помеха в его броске. Его бьют и он уклоняется/блокирует — помеха в защите. **Игнор не зеркалим.**

Посадка A: убедиться, что выбранное действие Размашистого реально читает эти эффекты; тесты на синтетическом Rule (атака владельца / его блок / игнор по нему без зеркала). Правка Game только если дырка подтвердится.

## 5. Лежачее положение и «Лечь или встать»

Новый `state`, флаг. Эффект: Ловкость `characteristic_modify` **−6** от состояния.

**Действие `stand-up` ставит или снимает этот state** (лечь / встать), не только `posture`.

**У состояния в спеке `action_codes: ['stand-up']`** — кнопка на карточке персонажа, тот же паттерн что у раны. Действие остаётся и в общем списке авто-действий.

Снятие лежачего автоматом снимает Неустойчивость.

## 6. Неустойчивость

Новый `state`, `value_type: number`, `aggregation: sum`. Потолка силы нет.

- Помехи на попадание в обе стороны: `check_advantage` `includes_hit` `per_unit` amount −1, **clamp `min(сила, 3)`**. HitLaunch уже читает states на обеих сторонах; игнор не зеркалим.
- На **каждое получение и каждое увеличение** — `check-dexterity` против **текущей** силы (после прироста). Провал → повесить Лежачее (и снять Неустойчивость). Образец хода — `ExhaustionCheckService`, не копия в `.vue`.
- Снятие: **не** «любые потраченные 2 ОД» (иначе удар сам сбросит состояние). Отдельное действие ~2 ОД + `action_codes` на состоянии.
- Автоснятие при Лежачем.

## 7. Базовый Толчок

У всех. **3 ОД.** Авто-действие в списке атак.

Оружие: по умолчанию `ruka` (мастерство с профиля). Щиты можно. Прочее — не в селекторе, пока нет перка.

Цель без facing / шага / размера.

**Пол толчка** = `вес.modify(−6)`. Только для **Силы**, не для попадания.

| Реакция | ОД | Ход |
| --- | --- | --- |
| Игнор | 0 | Нет попадания. Атакующий бросает Силу против пола. РУ = успехи − пол. |
| Блок | 2 | Совместная Сила. У цели успехи ≥ пола. РУ = результат. Попадания нет. |
| Избегать | 1 | Обычный `check-hit`, пол **0 маленьких**. Не попали — толчок сорван, Силы нет. Попали — как игнор. |

РУ ≤ 0 — нет урона / неустойчивости / отброса.

Успех:

1. Дробящий урон = сырые успехи Силы толкающего `.modify(−3)`, не РУ.
2. Неустойчивость `+=` РУ (sum).
3. Отброс `РУ.modify(−6)` ипари — строка хроники.

Не втискивать Силу в `HitRollService.ignoreDefense`. Отдельный класс-сервис толчка (ветка реакций + пол + урон + состояния). HitLaunch можно переиспользовать только для ветки «избегать».

`Толкающий удар` — 4 ОД, спека `push`: пул чистого урона оружия, урон профиля × РУ, профили рубящий/дробящий strike. Рубящий: `⌊РУ/2⌋` только на отброс и Неустойчивость. Помехи на попадание нет. Базовый Толчок остаётся Силой / руки и щит.

## 8. Силовой удар

Согласовано:

```text
бонус Силы для урона = min(⌊РУ атаки / 2⌋, 3), источник «Действие»
```

Не в пул попадания. После РУ: `attackAtDistance` + текущий ход урона.

Новый `ActionEffect` «модификатор характеристики удара от РУ» (`floor_div`, `cap`, source `action`). Карточка сейчас без `action_effects`, текст «+[РУ]↓ … обстоятельства» правим вместе с посадкой.

Не отдельный сервис на карточку.

## 9. Широкий удар

Согласовано. Один штраф на всю атаку: `−(число целей − 1)` к попаданию каждого удара. Соседство не проверяем.

В HitLaunch инвертировать `+(n−1)`. Источник — обстоятельства, как карточка. `spatialResolver` не обязателен. `contentNote` снять, когда знак верный.

## 11. Тесты

Синтетический `Rule`. Инварианты:

- Размашистый: pending в атаке владельца и в его блоке/уклоне; игнор по нему без зеркала;
- лежачее: `stand-up` вешает/снимает state; кнопка из `action_codes`;
- игнор толчка: пол = вес −2 размера; блок с тем же полом; РУ ≤ 0 — нет эффекта;
- избегание: `check-hit` пол 0 маленьких; промах — без Силы; попадание — Сила против пола;
- урон толчка от сырых успехов Силы −1 размер;
- Неустойчивость: `min(сила, 3)` помех; рост → Ловкость; лежачее снимает;
- Силовой: `min(⌊РУ/2⌋, 3)` в урон, не в пул;
- wide: n целей → `−(n−1)`.

Не искать `silovoy-udar` в моке как оракл Game.

## 14. Слоты рук и дети Размашистого

Размашистый раньше назывался Силовым. **Удвоенная мощь** — к Размашистому, не к нынешнему `silovoy-udar`. В карточке заменить «действием Силовой удар» на Размашистый.

### Слоты рук (до мощи)

На предмете: `min` / `max` слотов и при необходимости занятость **на действии** (лук: покой 1, выстрел 2). Экип ставит минимум. Если `max > min` — на карточке предмета можно выбрать число в диапазоне. Сумма слотов экипа ≤ число рук (человек: 2; лишние — когда будет Множество рук). Не влезает — не экипируется.

Примеры: кинжал 1; лук покой 1 / действие 2; двуручный меч 1–2; посох 1–4.

Удержание этого оружия:

- 2 руки: +2 к Силе удара и +2 к Силе vs мин. сила оружия;
- 4 руки: +3 к тому же;
- 1 рука: без бонуса; 3 руки пока как 2 (+2).

Не в пул попадания. Считать в обзоре атаки / `attackAtDistance`.

### Удвоенная мощь

Размашистый + рубящий или дробящий + на оружии ≥ 2 слотов → ещё +1 Силы удара поверх бонуса удержания.

### Яростный рывок

Опция на Размашистом. После удара: `check-willpower` vs 3. Успех — себе `[Сила удара]↓` внутреннего дробящего и не вешать pending-помеху Размашистого. От слотов не зависит.

Порядок: слоты и бонус 2/4 → мощь → рывок. Многорукие атаки — потребители слотов, не этот срез.

## 12. Перепроверка (2026-09-16)

Канон Толчка/Размашистого/Силового/Широкого стыкуется с кодом. Дырки посадки:

1. **Размашистый** почти посажен спекой; риск только «действие не доходит до HitLaunch».
2. **Толчок** — главный объём: нет действия, нет ветки Силы, нет фильтра щит/руки.
3. **Широкий** уже multi-target, но **бонус** вместо помехи — правка одной формулы + источник.
4. **Силовой** — нет эффекта в спеке; нужен тип от РУ, не фиксированный `delta: 2`.
5. **Лежачее / Неустойчивость** отсутствуют; `stand-up` не трогает states; кнопки `action_codes` уже рисуются.
6. Помехи Неустойчивости HitLaunch уже умеет читать; нужен только clamp 3 (в расчёте Game или поле спеки — без хардкода кода карточки в тесте).
7. `apply_state` в DTO есть — использовать для толчка, не плодить параллельный канал.

Открытых продуктовых развилок по базе нет, кроме уточнения имени/стоимости действия снятия Неустойчивости (2ОД, кнопка на карточке).
