# Рендерер локаций сцен

**Статус:** ~В РАБОТЕ~, 2026-11-12 — просмотр и редактор на PixiJS готовы; материалы террейна, кромка, рваные границы, вода, трава и декор-спрайты сделаны, акторы — в работе; инстансинг, LOD и fog — в плане.
**Реализация:** ~VUE~ — M2/M3 и T2.1–T2.3 готовы (слои, камера, hit-test, context loss, протяжка фигур, перемещение, паттерны, вода-mesh, декор, превью), ~PHP~ — не участвует, ~МОК~ — fixtures для smoke.
**Опираться на:** [`scene-system.md`](scene-system.md), [`battleground-system.md`](battleground-system.md) (WebGL, слои, fog hooks), ~МОК~ (render fixtures).

Документ фиксирует renderer авторской библиотеки локаций. Один и тот же
renderer позже используется в игровом battlemap; редактор и runtime не должны
получить два разных пайплайна мира.

## Стек

- **PixiJS v8**, бэкенд выбирается константой `SCENE_RENDERER_PREFERENCE`:
  по умолчанию WebGL, опционально WebGPU с автоматическим откатом на WebGL.
  Внутри одного адаптера `PixiSceneRenderer`, без второго пайплайна.
- Импорты деревошейкатся: `Application`, `Container`, `Sprite`, `Graphics`,
  `Text`/`BitmapText`, `Assets`, `Texture`, `ParticleContainer`. Полный
  `pixi.js/full` не подключать.
- `pixi.js` — зависимость фронтенда, не бэкенда. Домен и DTO от библиотеки не
  зависят.

## Архитектура

```text
Vue / draft store
  └── SceneRenderModel (DTO)
        └── ISceneRenderer
              └── PixiSceneRenderer
                    ├── Pixi Application
                    ├── layer containers
                    └── SceneCamera
```

- `ISceneRenderer` — граница: `attach`, `detach`, `resize`, `setViewport`,
  `setScene`, `setSelection`, `setVertexFocus`, `setDraft`, `render`, `destroy`.
  T2 добавляет `setWaterAnimation(enabled)`.
- `PixiSceneRenderer` — единственная реализация первого среза.
- `setDraft` рисует предварительную фигуру во время протяжки (прямоугольник,
  круг, стену, полигон, ленту) в слое `gizmos`; после отпускания превью
  снимается и создаётся элемент.
- `setVertexFocus` показывает ручки Безье активной вершины полигона или ленты:
  направляющие-заглушки у прямых сегментов, настоящие ручки у изогнутых и ромб
  ширины у ленты.
- `polygon` flatten-ится по ручкам в контур, `path` — в ленту: осевая кривая,
  ширина по вершинам и два края по нормали. Для текстуры террейна маска
  строится тем же контуром или лентой.
- Кривые разворачиваются адаптивно: сегмент дробится, пока отклонение от хорды
  больше допуска. Допуск задаётся в пикселях экрана (`0.4 px`, переводится в
  единицы сцены через зум), касательные — аналитические (`cubicTangent`), а не
  по соседним сэмплам. Поэтому кривая гладкая на любом масштабе, а точек не
  больше, чем нужно. На заметной смене зума (×2) геометрия пересобирается.
- T2: террейн рисует `SceneShapePainter` через `SceneTerrainPainter` — материал
  поверхности и кромки, заливка паттерном, вода-лента как `Mesh`. Текстуры
  паттернов готовит `SceneTerrainPatternService` и кэширует по виду террейна.
- T2: `SceneRibbonService` отдаёт не только края для `Graphics`, но и геометрию
  ленты с UV для `Mesh`: так вода течёт вдоль осевой, а не поперёк экрана.
- Бэкенд Pixi задаётся константой `SCENE_RENDERER_PREFERENCE` (`webgl` по
  умолчанию, `webgpu` — с автоматическим откатом на WebGL). Переключение не
  требует правок рендерера: граница `ISceneRenderer` и адаптер `PixiSceneRenderer`
  уже отделяют Pixi от домена.
- Renderer не хранит доменное состояние, не вызывает API, не мутирует draft и
  не знает про права. Он получает готовую модель и рисует. Позиция активной
  вершины — исключение: это UI-фокус, а не доменное состояние.
- `SceneRenderModel` — активное поле, поля, элементы, вложения, выделение,
  режим `edit | preview | play`.
- Компоненты Vue владеют только оболочкой: canvas, toolbar, панели, диалоги.

## Слои

Порядок снизу вверх фиксирован:

| Слой | Содержимое | Первый срез |
|---|---|---|
| `backdrop` | Подложка активного поля | да |
| `grid` | Визуальная сетка | да |
| `terrain` | Террейн: грязь, лёд, вода, трава | да |
| `supports` | Настилы, крыши, стойки; мост рисуется в `ground` | да |
| `obstacles` | Стены, стволы, мебель | да |
| `openings` | Двери, окна, ворота, лестницы | да |
| `waterPlane` | Плоскость воды: рябь, блики и пена, под декором | да |
| `ground` | Мосты и съезды: пол над водой | да |
| `decor` | Декор, полосы ковра, высокие пучки травы и акторы | да |
| `overlay` | Стоимость клеток предпросмотра: авторская подсказка поверх мира | да |
| `fog` | Туман видимости предпросмотра: маска скрытых клеток над миром | да |
| `route` | Маршрут выбранного актора предпросмотра | да |
| `selection` | Подсветка выбранного, вершины, ручки Безье и ширина ленты | да |
| `gizmos` | Направляющие, измерения, превью протяжки и рамка поля | да |
| `tokens` | PC/NPC и служебные токены игры | резерв |
| `path` | Маршрут и стрелки движения игры | резерв |

Активное поле рендерится одно. Остальные поля доступны через вкладки; их
содержимое не держится в сцене одновременно, если это не нужно для enclosure
на родителе.

Слои содержимого (`terrain`, `supports`, `obstacles`, `openings`, `waterPlane`,
`ground`, `decor`, `overlay`, `fog`, `route`) обрезаются маской по границам поля. `selection` и `gizmos` не обрезаются:
ручки вершины у края должны оставаться доступными.

## Материалы террейна

- Основные материалы (`grass`, `dirt`, `stone`, `sand`, `mud`) — бесшовные
  CC0-текстуры Poly Haven 512×512 из `Roleplay/Scene/Asset/Terrain/`
  (источники и лицензии — в README рядом). Они грузятся один раз на рендерер
  (`SceneTerrainTextureService`) и получают `addressMode: repeat`, мипмапы и
  анизотропию: при отдалении карты текстура не мерцает и не даёт сетку.
- `ice` и аварийный путь для незагруженных материалов — процедурный шаблон
  256×256 (`SceneTerrainPatternService`), тоже бесшовный и с мипмапами.
- Поверх фотоматериала идёт слой крупной вариации (`macro`) с тайлом около
  10 ипари: он сбивает сетку повторов, из-за которой одинаковые пятна
  читались штампом.
- Масштаб паттерна задаётся в единицах сцены, а не в пикселях фигуры: заливка
  идёт в `textureSpace: 'global'`, поэтому большой полигон не растягивает
  текстуру. Сдвиг паттерна на элемент детерминирован от `element.id`, чтобы
  одинаковые пятна не выглядели штампом.
- Если у элемента задан `assetPublicId`, загруженная картинка заменяет
  процедурный паттерн поверхности.
- Кромка (`shoreKind` / `shoreWidth`) рисуется под поверхностью: у ленты —
  расширенная лента, у замкнутой фигуры — наружная полоса по контуру. Материал
  кромки берётся из того же набора шаблонов; `none` выключает кромку. У воды
  поверх кромки идёт тонкая линия уреза.
- Граница типов ландшафта рваная: вдоль контура фигуры наружу идёт полоса того
  же материала (`SceneTerrainBlendService`). Шейдер семплит ту же текстуру и
  тот же сдвиг, что заливка, поэтому шва на краю нет; ширина языка гуляет
  крупным шумом, мелкий шум даёт зерно. Так песок неровно осыпается на траву, а
  не стыкуется с ней по линии заливки. У кромки воды полоса начинается от уреза
  и перекрывает саму кромку тем же материалом, поэтому мокрый край остаётся
  поверх. Если у элемента есть кромка, осыпь поверхности не рисуется: наружу
  уходит материал кромки.
- Порядок террейна: вода выше остальных шаблонов, остальные — по `sortOrder`,
  при равенстве по `id`. Так залитое позже поле не перекрывает реку.

## Трава

Трава делится на два слоя по роли, а не по плотности: ковёр — короткие пучки,
высокие пучки перекрывают то, что стоит на земле. Оба слоя участвуют в
Y-сортировке: ковёр режется на горизонтальные полосы.

- Основа — `grass.jpg` (CC0, ambientCG Grass004): бесшовный тайл 2 ипари. Поверх
  идут процедурные пятна разнотравья (10 ипари, `grassMacro`) и мелкая деталь из
  лезвий и зерна (1 ипари, `grassDetail`); общий тёмный `macro` у травы не
  используется.
- Атлас пучков (`SceneGrassTextureService`) — 8 процедурных вариантов: лезвия
  залиты зерном той же `grass.jpg`, у основания мягкая тень. Один атлас на оба
  слоя.
- Ковёр — короткие пучки 0.35–0.6 ипари с шагом 0.2 ипари. Собираются в
  мерженые меши (`SceneGrassMeshService`) по горизонтальным полосам
  `carpetBandIpari` (0.5 ипари): квады в мировых координатах, UV в атлас, тинт
  и точка основания в вершинных атрибутах. Полосы идут в `decor` и сортируются
  по нижней границе вместе с высокими пучками, декором и акторами: короткая
  трава может оказаться перед ногами, а высокий пучок — уйти за короткую траву,
  стоящую южнее. Шейдер общий, юниформы следа не дублируются.
- Ключ сортировки актора — низ footprint (`y + radius`), а не точка под ногами:
  трава, попавшая под круг, уходит за силуэт, а не растёт из середины тела.
- Движение оставляет временный след: `SceneGrassTrailService` ставит точки
  вдоль пути с шагом 0.25 ипари и упаковывает до 16 из них в юниформы шейдера
  (`x`, `y`, вектор потока). Вектор потока — направление движения, умноженное
  на оставшуюся силу; поэтому трава наклоняется по ходу актора, а не от его
  центра. Вес наклона растёт от основания пучка к верхушке квадратично
  (`pow(length(position − aOrigin) / uTrailSpan, 2)`), поэтому пучок гнётся, а
  не уезжает целиком. Влияние соседних точек не складывается: оно сливается в
  один поток и ограничивается сверху, иначе верхушка уезжала бы в несколько раз
  дальше своего роста.
- Точки гаснут за `trailRelaxMs` (2.4 с), и только тогда ковёр возвращается к
  исходному виду. Стоящий актор следа не оставляет: круг-аура не появляется,
  остаётся полоса позади идущего. Призраки следов не оставляют, высокие пучки
  на акторов не реагируют.
- Затухание живёт на общем тикере Pixi: пока есть точки, кадр рисуется каждый
  тик, поэтому след распрямляется и при выключенной анимации воды.
- Высокие пучки — 0.9–1.4 ипари с шагом ~1.2 ипари. Остаются спрайтами и
  сортируются по `y` вместе с декором и акторами: трава за деревом уходит под
  спрайт, трава перед деревом перекрывает низ ствола.
- Раскладка детерминирована: сетка с джиттером внутри травяных фигур. Точки,
  перекрытые более поздним террейном (песок, вода), его кромкой (`shoreWidth`) и
  осыпью, отбрасываются. Шаг задан в мировых единицах, а не в экранных: зум
  только масштабирует уже построенный луг, поэтому трава появляется сразу и не
  пропадает при отдалении. Общий потолок числа квадов и пучков сохраняется.
- Проверка перекрытий идёт по заранее тесселированным контурам и лентам, а не
  по исходным кривым на каждую точку; готовая раскладка кэшируется по полю,
  разрешению и форме элементов. Пересборка сцены из-за ассетов или декора не
  пересеивает луг и не морозит кадр.
- Пока тянется террейн, сцена не пересобирается: двигается только контур
  выделения, а вода, земля и трава собираются после отпускания. Иначе река
  перерисовывалась бы на каждое движение указателя.

## Мосты

- Мост — опора (`support`) с `props.kind = "bridge"`, съезд — с
  `props.kind = "ramp"`: прямоугольник настила, который рисуется не в слое
  опор, а в слое `ground` над водой. Это пол, по которому ходят, поэтому он
  лежит под оверлеями, декором и акторами, но перекрывает водную плоскость.
- Настил процедурный (`SceneBridgeService`): тень на воде, боковая грань,
  сваи с ватерлинией, чередование досок, торцевые балки, перила со столбиками.
  Ориентация определяется длинной стороной прямоугольника, поэтому мост
  растягивается вдоль дороги. Толщина линий переводится из экранных пикселей
  через зум.
- `props.elevation` — подъём настила над землёй/водой, `props.height` —
  толщина настила. У старых мостов без `elevation` высота над водой хранится
  в `height`, поэтому она используется как подъём. Съезд рисуется наклонным:
  ступени, сходящая на нет боковая грань и пороги на концах.
- Трава не прорастает на настиле: мост и съезд — более поздние элементы и
  попадают в проверку перекрытий раскладки, как песок и вода.
- Слои навигации «по мосту и под мостом» в этот срез не входят; это отдельный
  план [`scene-plan-05-bridge-deck.md`](scene-plan-05-bridge-deck.md).

## Оверлеи предпросмотра

- В `preview` доступны два переключателя: «Маршруты» и «Видимость». Они есть и
  на странице локации, и в предпросмотре редактора, в том числе в полноэкранном
  режиме.
- Стоимость клеток считает `SceneSurfaceService`, видимость —
  `SceneVisibilityService`, полосы заливки — `SceneOverlayService`. Рендерер
  получает готовый `SceneOverlayPaint` и не строит occupancy и LOS сам, как и
  требует контракт ниже.
- Стоимость идёт в слой `overlay` над декором и акторами: это авторская
  подсказка, и непроходимые клетки со скоростями должны читаться поверх травы
  и крон. Кроны она слегка подкрашивает — это осознанная цена читаемости.
- Туман видимости идёт в слой `fog` над декором и акторами: дерево и трава за
  пределами обзора темнеют вместе с землёй, а не светятся поверх маски.
  `SceneOverlayService` отдаёт маску с одним текселем на клетку, рендерер
  собирает из неё текстуру и растягивает с `scaleMode = 'linear'`. Поэтому
  ступеньки клеток на экране сглаживаются, а кольца мягкого края остаются
  данными маски. Контур тени всё равно квантован шагом `occupancyCell`
  (0.25 ипари); это свойство видимости, а не отрисовки.
- Маршруты: луг `100`, дорога и мост `150`, река `20`, `0` — непроходимо;
  непроходимые клетки красные. Соседние клетки одного цвета сливаются в
  горизонтальные полосы, поэтому 160×160 клеток не превращаются в десятки
  тысяч инструкций.
- Видимость: скрытые клетки затемняются, у границы обзора — два кольца мягкого
  перехода. Точка обзора — выбранный актор предпросмотра, радиус — из панели
  акторов; без акторов центр поля, радиус по умолчанию 16 ипари.
- Высота: луч идёт из глаз наблюдателя (1.55 ипари) к телу цели (0.9 ипари), и
  клетка перекрывает его только тогда, когда её силуэт начинается не выше луча.
  Ствол дерева закрывает токен, крона с низом выше глаз — нет. Низ силуэта
  задаётся в карточке декора (`sightBottom`, проценты ширины спрайта).
- Легенда живёт в существующей панели `?` и раскрывается сама при включении
  оверлея: тип поверхности, скорость и непроходимость.

## Акторы

- Актор — стендалка с якорем в ногах: спрайт, тень, кольцо footprint и стрелка
  facing на кольце. Кольцо и стрелка показывают, куда смотрит персонаж; сам
  спрайт не поворачивается, а отражается по горизонтали, когда facing смотрит
  влево.
- Контракт `SceneActor`: `x`, `y`, `facing` (0–359, 0 — вверх экрана, по
  часовой), радиус тела/кольца, тинт, подпись. Позиции и состояние принадлежат
  игре; рендерер только рисует.
- Радиус актора — это тело (`0.3` ипари, около 0.9 м в ширину при
  `1 ипари = 1,5 м`), а не зона контроля. По нему строятся кольцо, сортировка
  травы и навигационный зазор; зона контроля (reach, угрозы) — отдельная
  игровая величина и в рендерер не входит.
- Акторы живут в слое `decor` и вставляются по `y` между статичными детьми:
  дерево или высокий пучок за актором его скрывают, перед ним — перекрывают.
- Движение — интерполяция позиции, facing — по направлению движения; цикл
  ходьбы в первом срезе не нужен.
- Акторы предпросмотра — стендалки из маркеров `player_start` и `npc_spawn`;
  позиции и обзор живут в предпросмотре, а не в сцене. Выбранный актор
  подсвечивается кольцом, скрытый — призраком с пониженной прозрачностью.
- `SceneNavigationService` строит навигационную сетку булевыми операциями
  (`polygon-clipping`) и триангуляцией (`earcut`). Регион перед `earcut` режется
  сеткой `triangulationCellIpari` (4 ипари): длинный разрез, которым `earcut`
  сшивает вырез с внешним контуром, больше не работает «шоссе» через карту.
  A* идёт по направленным порталам: состояние — вход в треугольник через ребро,
  стоимость — расстояние между серединами порталов; оценка «центр-центр»
  делала вытянутый треугольник дешевле, чем он есть. Путь по коридору собирает
  funnel-алгоритм по порталам, а не середины общих рёбер. Кромка выреза
  считается проходимой в пределах допуска склейки, иначе путь вдоль обрезки
  стоил бы как сквозь препятствие.
- Зазор навигации — радиус тела (`agentRadiusIpari`, 0.3 ипари), а не кольцо
  и не зона контроля. Поэтому щель шириной 1 ипари проходима, а уже диаметра
  тела — нет; вокруг ствола маршрут идёт в ~1 клетке от красной зоны, а не в
  двух.
  Маршрут рисуется в слое `route` над миром и туманом: линия должна читаться
  поверх травы, деревьев и акторов, как тактическая подсказка.
- Ковёр хранит временный след движения (см. «Трава»): точки пути идут в
  юниформы, вершины наклоняются по ходу актора и распрямляются за 2.4 с.

## Вода

Вода рисуется в два уровня: тело и поверхность. Пена принадлежит поверхности.

| Уровень | Что в нём | Где |
|---|---|---|
| Тело | песок и галька сквозь воду, поглощение по глубине, каустика | `terrain`, под всем |
| Поверхность | нормали, преломление, блики, отражение неба, пена | `waterPlane`, под декором |

- Поверхность — это собственно вода: объект, стоящий выше неё, её перекрывает,
  поэтому по стволу дерева блики не ползут.
- Пена — тоже поверхность: она лежит на земле у кромки. Дерево на берегу
  перекрывает её, а не просвечивает сквозь неё. Тонкий урез, нарисованный
  поверх декора, читался бы как плёнка на кроне.

### Вода на шейдерах

Вода делится на два шейдерных пресета; замкнутая вода больше не остаётся на
текстурах.

- **Стоячая вода** (`SceneWaterBodyShader`, `SceneWaterSurfaceShader`): накат,
  мокрота, каустика, пена; меш — квад поля глубины, UV — мировые координаты.
  Подключена через `isShaderStill`: пруд больше не выглядит мёртвым.
- **Река** (`SceneRiverBodyShader`, `SceneRiverSurfaceShader`,
  `SCENE_WATER_RIVER`): наката на берег нет; дно — песок + галька, галька
  гаснет в песок у уреза; обе сетки каустики на 5 % и растянуты вдоль течения
  в 3 раза; мокрота широкая и пятнистая; пена — текстура `water_foam` вдоль
  уреза, рвётся шумовой маской; рябь — три направленные волны плюс два
  шумовых слоя с профилем скорости (центр быстрее, берега медленнее);
  широкая маска пятен модулирует и плёнку, и цвет тела; на теле она кипит,
  поэтому пятна меняются; блик Блинна-Фонга и мелкие искры в ячейках с
  независимой фазой; все слои сносятся вниз по течению, преломление дна —
  тем же градиентом.
- **Концы реки — не берег.** Поле глубины продлевает оба конца ленты, поэтому
  глубина у торца не выклинивается; если конец идёт к краю поля, геометрия и
  обводка продлеваются до края и торец уходит под обрезку. Конец в глубине поля
  (река в озеро) остаётся закрытым.
- Нормали реки считаются одним кодом (`SceneWaterShaderSource`) с одними
  юниформами: иначе дрожание дна разъехалось бы с бликами.
- Шум процедурный, в координатах русла: тайла нет, поэтому узор не повторяется
  на длинной реке. Свет — константа `SCENE_WATER_LIGHT`; день/ночь, вечер и
  дождь — далёкое будущее.
- Меш поверхности шире силуэта на `marginIpari` — запас под кромку и пену;
  лишнее отсекается полем глубины.

Пресеты воды и объекты в воде — [`scene-plan-02-water-shaders.md`](scene-plan-02-water-shaders.md).

### Поле глубины

`SceneWaterDepthService` запекает по фигуре поле расстояния до берега
(растровая маска → дистанционное преобразование Шама). Поле шире силуэта на
запас `MARGIN_IPARI`: кромке, пене и нормалям нужны данные и за урезом. Хранятся две
текстуры:

- **данные** — `R` знаковая дистанция до берега (плюс внутри, ноль на урезе),
  `G` силуэт; по ним шейдеры строят поглощение, преломление и кромку;
- **градиент** — готовая рампа глубины для замкнутой воды и старого пути.

Поле кэшируется по элементу и пересчитывается только при смене геометрии.

- Градиент непрерывный: никаких концентрических обводок и ступенек.
- В расстояние подмешан **низкочастотный** шум (длина волны — сотни единиц
  сцены), поэтому кромка мелководья гуляет вдоль берега длинными участками.
  Короткие волны давали гребешок из полос вдоль уреза — он читался как лёд.
- Поле — единственный источник правды о глубине: из него же берутся ширина
  мелководья, мокрый берег и **глубина под объектом**.
- Концы ленты поле продлевает всегда, поэтому у торца глубина не выклинивается;
  геометрия и обводка продлеваются только для концов, идущих к краю поля, —
  остальные остаются закрытыми (река в озеро). Шкала кодирования глубины
  ограничена сверху: иначе широкий водоём отдаёт весь 8-битный диапазон на
  глубину, которая уже утонула в цвете толщи.

### Погружение объекта

Объект считается стоящим в воде по своей **нижней точке** (у декора — якорь
`shape.x/y`, у фигур — низ ограничивающего прямоугольника):

- глубина `d` берётся из поля в этой точке; `d <= 0` — объект сухой, даже если
  его спрайт наложился на воду;
- иначе тонируется только низ спрайта на высоту `min(0.3·h, 0.6·d)`, через
  мягкую градиентную маску: уровень воды режет спрайт не линией, а полосой,
  и полной силы тон доходит на середине полосы;
- у берега `d` мало и низ едва мокрый, к середине погружение глубже;
- доля высоты ограничена: дерево в русле не тонет наполовину, даже если поле
  показывает большую глубину.

Летающие объекты требуют отдельного флага: по одной нижней точке они
считались бы стоящими в воде.

### Течение по руслу

У ленты UV задаёт не мир, а сама полоса: `u` — длина по осевой, `v` — смещение
поперёк. Поэтому текстура обтекает изгиб, а не режет его по прямой, и нет
накопления сдвига: движение вдоль русла — это сдвиг одной координаты.

- Начало координат `u` — начало кривой, поэтому вода течёт от первой вершины
  ленты к последней.
- На изломе полилинии край строится по митре соседних сегментов с пределом
  `2.5`, а совпадающие точки излома сводятся в одну вершину. Без этого
  оставался веер нулевой длины, внутренний край складывался в петлю, и
  текстура воды смазывалась.
- Масштаб тайла задаётся в ипари и переводится в единицы сцены; скорость тоже.
- Замкнутые водоёмы (прямоугольник, круг, многоугольник) остаются на мировых
  UV, но не сносятся линейно: у лужи нет течения. Вместо сноса — медленный
  вихрь вокруг центра водоёма (`SWIRL_RATE`), а плоскость тише (`POND_ALPHA`).
- Силуэт задаёт фигура, а не система координат текстуры; лента и замкнутая
  фигура (`earcut`) дают одинаковую картину.

### Пена

Пена — не обводка, а полоса по контуру с текстурой кружева:

- `SceneWaterMeshService.foamStrip` строит полосу по нормалям контура: ширина
  гуляет вдоль берега, а период текстуры подгоняется под целое число тайлов,
  иначе на замыкании контура был бы шов.
- Ширина идёт **пятнами с пропусками**: три октавы шума вдоль контура дают
  пропуски на 20–30 % берега. Ровная полоса постоянной толщины читается как
  лёд, особенно на луже.
- Полоса смещена в воду (`FOAM_WATER_SHARE`): сторону воды ищет поле глубины,
  поэтому пена не выползает на песок.
- Вдоль берега пена едет медленно вниз по течению (единицы сантиметров в
  секунду): оторванные клочья уносит, но конвейера нет.
- Основное движение — **накат поперёк**: кромка со стороны воды ходит к берегу
  и обратно (`lapFoam`). Фаза зависит от места вдоль контура, поэтому пятна
  наката вспыхивают в разных местах в разное время, а не бегут одной волной.
- Под пеной лежит градиент сырого берега (`wetsand` в несколько полос): урез
  не режет песок жёсткой линией.

### Анимация

- Шейдерные проходы реки обновляются одним временем `waterElapsed`: `uTime`
  в юниформах тела и поверхности. В редакторе анимации нет — только в
  `preview`/`play`.
- У замкнутой воды плоскость — `Mesh` со слоями текстуры; период и скорость
  задаются в ипари и переводятся в единицы сцены. Для широкой реки (десятки
  ипари) поверх идёт макро-слой множителем (`multiply`) с периодом 44 ипари —
  в кадр попадает меньше одного тайла, и сетка повторов не читается.
- Высокочастотные слои гаснут, когда их тайл на экране становится мелким
  (`MIN_TILE_PX`): в отдалении не появляется диагональная сетка.
- Каустика в реке — функция `waterCaustics` в шейдере тела: сетка Вороного с
  доменным искажением, без текстуры и тайла, поэтому узор не повторяется на
  длинной реке. У замкнутой воды остаётся текстура (`SceneWaterCausticsShader`
  только для ленты): там нет течения, а вихрь прячет узор.
- Кастомные шейдеры — у воды (тело, поверхность, каустика ленты); остальной
  визуальный слой — `Mesh` и texture fill. Для WebGPU понадобится WGSL-двойник
  (см. `scene-plan-02-water-shaders.md`).

## Декор

- Декор с `assetPublicId` рисуется спрайтом, а не точкой. Ассет вписывается в
  квадрат со стороной `1 ипари × scale%`, пропорции сохраняются, якорь —
  снизу по центру: ствол дерева стоит в точке элемента.
- `rotation` поворачивает спрайт вокруг якоря. `scale` — проценты от одного
  ипари, поэтому при смене `resolution` физический размер декора не меняется.
- Под декором рисуется мягкая тень (процедурная радиальная текстура); она не
  поворачивается и не входит в hit-test.
- Внутри слоя `decor` элементы сортируются по `y` якоря, затем по `sortOrder`
  и `id`: дерево ниже перекрывает дерево выше. Пучки травы
  (`SceneGrassService`) и акторы (`SceneActor`) попадают в тот же список: трава
  и деревья за актором рисуются до него, перед ним — после.
- Без ассета декор остаётся прежним маркером-точкой. Ошибка загрузки текстуры
  не роняет кадр.

## Камера и координаты

- Данные хранятся в целых единицах сцены. Float — только в камере и матрицах.
- `SceneCamera`: `x`, `y`, `zoom`, размеры viewport, `sceneToScreen`,
  `screenToScene`, `fit(bounds, padding)`, ограничения zoom.
- Начало координат поля — левый верхний угол; `x` вправо, `y` вниз.
- `resolution` локации переводит единицы сцены в ипари для интерфейса; рендерер
  работает в единицах сцены. Разрешение — степень двойки, поэтому UI показывает
  расстояния как `{base|size}` без дробей.
- Сетка: тонкие линии с шагом `gridStep`, жирные — каждые два шага (1 ипари по
  умолчанию). При отдалении тонкая сетка скрывается, жирная остаётся до порога.
- DPR: `application.renderer.resolution = devicePixelRatio`, `autoDensity: true`;
  размеры canvas — CSS-пиксели.
- При смене активного поля камера сбрасывается на `fit`.

## Рендер по требованию

- Тикер Pixi остановлен: `app.ticker.stop()`.
- Сеттеры (`setActors`, `setRoute`, `setOverlayPaint`, `setSelection` и другие)
  не рисуют сами: они зовут `requestFrame`, и кадр схлопывается в один
  `requestAnimationFrame`. Пачка обновлений за кадр даёт один `app.render()`.
- Если запущен тикер (вода или затухающий след травы), кадр рисует он:
  отдельный rAF не запрашивается, иначе сцена уходила бы в GPU дважды за кадр
  и движение дёргалось.
- `render()` — немедленный кадр: resize, восстановление WebGL-контекста и
  остановка тикера. В обычном потоке его никто не зовёт.
- Постоянный 60 fps в редакторе не крутится.
- Исключение — `preview`/`play` с включённой анимацией воды или живым следом
  травы: тикер обновляет UV/след и рисует кадр. Отключение галочки, `edit`,
  скрытие вкладки и `detach` останавливают тикер.
- Шаг времени воды ограничен 50 мс: долгий кадр не прокручивает анимацию
  разом, поэтому после подвисания картинка не дёргается.

## Превью

- Режим приходит в `SceneRenderModel.mode`: `edit | preview | play`.
- В редакторе есть переключатель `edit ↔ preview`; `Esc` возвращает в `edit`.
- В `preview` скрываются сетка, рамка поля, выделение, вершины и ручки; pan и
  zoom остаются. Вода анимируется, если включена настройка.
- В `preview` доступны оверлеи «Маршруты» и «Видимость» с легендой; при выходе
  из предпросмотра они снимаются.
- Страница просмотра открывает локацию в `preview`; редактор остаётся
  единственным местом, где видны gizmos.

## Hit-test

- Только CPU по той же геометрии, что и рендер. GPU-readback и per-object
  `eventMode` не используются.
- Одно событие указателя на canvas; камера переводит экран в единицы сцены.
- Порядок выбора: слой → `sort_order` → порядок в snapshot; Alt+клик перебирает
  перекрывающиеся элементы.
- Допуск попадания задаётся в экранных пикселях и переводится в единицы сцены.
- Hit-test обслуживает `SceneHitTestService`, не Vue-компонент.

## Текстуры и ассеты

- Подложка и декор — `Core/File`; URL просмотра отдаётся тем же origin.
- Текстуры кэшируются по `publicId`; при смене поля и `destroy()` освобождаются.
- Процедурные паттерны террейна живут в отдельном кэше по шаблону и не
  освобождаются при смене поля: это маленькие canvas-текстуры, общие для всех
  локаций.
- Пиксели изображения не являются единицами сцены. Подложка растягивается на
  `bound_width × bound_height`; несовпадение пропорций — предупреждение
  редактора, координаты не пересчитываются. Декор масштабируется от ипари, а
  не от пикселей файла.
- Data URL картинок не являются контрактом хранения.
- Ассеты декора — только CC0 или собственные; источник и лицензия фиксируются
  рядом с файлом в репозитории.

## Инстансинг и culling

- Декор и лес — `ParticleContainer` + атлас, не `SceneElement[]` на каждый
  спрайт и не DOM-узлы.
- Culling по прямоугольнику камеры; для больших массивов — LOD позже.
- Лес масштаба ~40k деревьев не превращается в 40k интерактивных объектов.
- Первый срез: обычный декор; `instance_layer` — следующий шаг.

## Текст

- Метки мира — `BitmapText`/атлас или `Text` с ограниченным разрешением.
- DOM-overlay допустим только для UI-подсказок, тултипов и измерений, не для
  объектов мира.
- SVG на карте не используется.

## Fog, LOS и runtime hooks

- Слои `tokens` и `path` резервируются с первого дня; маршрут предпросмотра
  живёт в слое `route`.
- `overlay` — стоимость клеток, `fog` — туман видимости предпросмотра. Оба
  авторские, а не игровые: игровой туман и освещение расширят тот же `fog`
  поверх декора, но в authoring-срезе не реализуются.
- Туман предпросмотра — маска-текстура поверх occupancy-сетки с линейной
  фильтрацией; игровой туман и освещение — отдельный shader/filter поверх той
  же сетки, в authoring-срезе не реализуются.
- Renderer не строит occupancy и не считает LOS. Он получает готовую маску или
  проекцию от Game.
- Никакого второго пайплайна: лес, токены, туман и гизмо — один GPU-мир.

## Context loss, resize, destroy

- `webglcontextlost` — остановить рендер, показать сообщение, дождаться
  `webglcontextrestored`, пересоздать ресурсы.
- Resize — `ResizeObserver`; обновить canvas и камеру без пересоздания сцены.
- `destroy()` освобождает текстуры, графику, контейнеры и app.
- Утечки между сменами поля и размонтированием страницы недопустимы.

## Производительность

Ориентиры первого среза:

- 40 000 декоративных спрайтов, pan/zoom без просадок ниже целевого порога на
  рабочей машине;
- 200 актёров — резерв runtime, не editor;
- 1024² occupancy — резерв runtime;
- нет DOM-узла и Pixi-события на каждый объект мира;
- нет постоянного тикера в редакторе; тикер воды — только в `preview`/`play`
  при включённой анимации;
- анимация воды не пересобирает геометрию и слои: только UV и один кадр.

Если порог не достигается, сначала culling и инстансинг, потом LOD. Ослаблять
требование «один GPU-мир» нельзя.

## Тесты

- Vitest: камера, `sceneToScreen`/`screenToScene`, hit-test, сборка
  `SceneRenderModel`, порядок слоёв, фильтрация активного поля.
- WebGL в jsdom не создаётся. Визуальная проверка — ручной smoke или puppeteer
  с software rendering; screenshot-baseline не обязателен в первом срезе.
- Renderer не тестируется через прямые мутации Pixi-контейнеров: только через
  публичный интерфейс и модель.

## Границы

- Нет бизнес-логики, API-вызовов, хранения и прямой мутации draft в renderer.
- Нет SVG и Canvas 2D для мира.
- Нет per-object DOM и per-object Pixi events.
- Нет второго пайплайна токенов/леса/тумана.
