**Статус:** план, 2026-09-11. Канон статусов — [`rule-system.md`](rule-system.md). Оси `contentStatus` / runtime — `DEC-053`…`DEC-055`. Фронт — [`../../draft-front_1.2ds/frontend-rules.md`](../../draft-front_1.2ds/frontend-rules.md). Очередь пропусков — [`rule-content-queue.md`](rule-content-queue.md). Магия как отдельная линия — [`spell-roadmap.md`](spell-roadmap.md).

Цель: пройти уже выгруженные правила так, чтобы карточке можно было верить (текст + spec), не подгоняя Game под сырой дамп и не объявляя «актуальным» то, что врёт.

Инструмент (`contentStatus`, `contentNote`, FilterBar, рамки) — сделан. Дальше — дисциплина прохода, не новые оси DTO.

## 0. Не смешивать

| Ось | Где живёт | Смысл |
| --- | --- | --- |
| Редакционный статус | `contentStatus` | можно ли показывать игрокам / врёт ли карточка |
| Комментарий разработки | `contentNote` | мысль на будущее, не игровой текст |
| Runtime Game | код Game + очередь | движок исполняет правило |
| Листы персонажей | приоритет, не источник истины | что чинить в Game первым |

`broken` — карточка вредна или бессмысленна. `needs_work` — смотрели, ещё не актуально. `ready` — редакционно можно показывать. Красный **не** значит «Game ещё не кастует».

Не сбрасывать каталог оптом в `broken`. По умолчанию в моках уже `needs_work`.

Моку **нельзя слепо верить**: сначала правка или пометка, потом runtime.

## 1. Порядок

```text
инструмент (DONE)
  → C1 пачки по 10: текст/spec
  → очередь пропусков (этот файл + queue.md)
  → C2 группы 3–5 из очереди: Game
  → PHP/бэкенд контракта, которым уже пользуются
  → новая большая выгрузка
```

Листы реальных персонажей входят в **C2** как фильтр приоритета, не как C1.
