# План Asset Library 1 — библиотека ассетов

**Статус:** ~СДЕЛАНО~, 2026-11-13 — PHP, Vue и mock готовы; полигон
использует общую коллекцию `decor`, B4.1 закрыт.

**Реализация:** ~PHP~, ~VUE~, ~МОК~.

**Опираться на:** ~PHP~ (`Core/File`, `Core/SmartTable`, `Core/User`,
`Core/Kernel`), ~VUE~ (`Core/File`, `Core/UI`).

Библиотека ассетов — общий склад картинок для редакторов: общая часть,
которую наполняет супер-админ, и личная часть пользователя. Первый
потребитель — `Roleplay/Scene`: декор и текстуры террейна. `Roleplay/Map` и
другие редакторы позже добавляют свои коллекции без правок библиотеки.

## 1. Место и роль

- Новая группа `Library`, модуль `Library/Asset`
  (`Mifrial\Library\Asset`, `www/mifrial/modules/Library/Asset`).
- Это **не Core**: ядро нужно любому проекту, а библиотека ассетов —
  прикладная инфраструктура редакторов.
- HTTP-загрузка идёт лениво: в `config/modules.php` добавляется слот
  `ILibraryAssetContainer` → `Library/Asset`. CLI setup грузит все модули с
  диска, ему каталог не нужен.
- `Core/File` остаётся владельцем байтов и метаданных файла. Библиотека не
  хранит байты, не дублирует `publicId` и не меняет `file`.
- Библиотека не знает слов `decor`, `terrain`, `background`. Назначение
  ассета задаёт модуль-потребитель своей коллекцией.
- Фронтенд — `draft-front_1.2ds/src/modules/Library/Asset`.

## 2. Границы ответственности

| Слой | Отвечает | Не отвечает |
|---|---|---|
| `Core/File` | байты, mime, размеры, SHA-256, выдача, архив файла | смысл файла, коллекции, общая/личная видимость |
| `Library/Asset` | коллекции, общие и личные ассеты, права, выдача, диалог выбора | конкретные виды ассетов, правила сцены, геометрию |
| `Roleplay/Scene` | коллекции `decor` и `terrain`, выбор ассета в настройках элемента | хранение файлов и общую механику библиотеки |
| `Roleplay/Map` | свои коллекции позже | изменения в `Library/Asset` |

## 3. Модель данных

### `asset_collection`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `IdField` | внутренний id |
| `module` | `StringField(64)` | владелец, например `Roleplay/Scene` |
| `code` | `StringField(64)` | код внутри модуля, например `decor` |
| `title` | `StringField(120)` | подпись для UI |
| `is_active` | `BoolField` | выключенная коллекция не выдаётся и не принимает новое |

- `UNIQUE(module, code)`.
- Строки создаёт модуль-потребитель, не библиотека.
- `module` не интерпретируется библиотекой: это метка владельца.

### `asset_item`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `IdField` | внутренний id |
| `collection_id` | `ReferenceField` → `asset_collection`, `restrict` | назначение |
| `file_id` | `FileReferenceField`, `restrict` | файл в `Core/File` |
| `is_shared` | `BoolField` | общая или личная |
| `owner_id` | `UserReferenceField`, nullable | владелец личной |
| `name` | `StringField(120)` | подпись в библиотеке |
| `is_archived` | `BoolField` | скрыта из выдачи; файл и ссылки сцен живут |
| `created_at` | `DateTimeField` | момент добавления |

Инварианты:

- `is_shared = true` ⇒ `owner_id = null`; `is_shared = false` ⇒ `owner_id`
  задан. Проверяет сервис, схема допускает `null` только ради общей части.
- `name` обрезается по краям, длина `1…120`; пустое имя берётся из
  `file.original_name` без расширения.
- Файл должен существовать, быть картинкой `image/png`, `image/jpeg` или
  `image/webp` и не быть архивным.
- `asset_item.is_archived` не трогает ни `file`, ни `publicId` в сценах.
- Жёсткого удаления нет: только архив. Дубликаты одного файла в одной
  коллекции в первом срезе не запрещаются — это задача кураторства, не
  целостности.

## 4. Коллекции потребителей

- `Roleplay/Scene` объявляет константы `SCENE_ASSET_COLLECTIONS`:
  `decor` — «Декор», `terrain` — «Текстуры террейна».
- Setup-шаг `SeedSceneAssetCollectionsStep` вызывает порт библиотеки
  `IAssetCollections::ensure('Roleplay/Scene', 'decor', 'Декор')` и второй
  для `terrain`. Шаг идемпотентен: повторный `bin/setup.php` ничего не
  дублирует.
- Порт `ensure` — единственная запись коллекций. Библиотека не содержит
  списка чужих коллекций и не импортирует `Roleplay/Scene`.
- `ensure` идемпотентен и не перезаписывает подпись существующей коллекции;
  выключенную коллекцию он тоже не включает — `is_active` остаётся ручным
  состоянием.
- `Roleplay/Map` позже добавляет свой шаг и свои коды. Правок в
  `Library/Asset` для этого не требуется.
- Коллекция в запросах задаётся парой `collectionModule` + `collectionCode`
  (плоские поля: биндер action не обещает вложенные объекты).

## 5. Права

| Операция | Личная | Общая |
|---|---|---|
| Чтение | владелец | любой аутентифицированный |
| Создание | любой аутентифицированный | только `actor.hasBypass()` |
| Переименование | владелец | только bypass |
| Архив | владелец | только bypass |

- «Супер-админ» — активная группа с `bypass`; отдельных permission-ключей
  в первом срезе нет.
- Чужие личные ассеты не выдаются и не изменяются, включая администратора.
- Неаутентифицированный запрос — `AUTH_REQUIRED`; чужое действие —
  `ASSET_DENIED`.

## 6. HTTP

| Действие | Вход | Результат |
|---|---|---|
| `asset.findPage` | `collectionModule`, `collectionCode`, `scope` (`shared`/`personal`), `q`, `limit`, `offset` | `items`, `total` |
| `asset.create` | `collectionModule`, `collectionCode`, `filePublicId`, `name?`, `scope` | созданный ассет |
| `asset.update` | `id`, `name` | обновлённый ассет |
| `asset.archive` | `id` | пустой успех |

- `scope` обязателен: диалог показывает общую и личную части отдельными
  вкладками, смешанной выдачи нет.
- `limit` `1…100`, `offset ≥ 0`.
- Страница сортируется по `name ASC`, затем `id ASC`; архивные ассеты в
  выдачу не попадают.
- `q` — подстрока `name`, регистронезависимо средствами SmartTable.
- JSON-вид: `id`, `collectionModule`, `collectionCode`, `collectionTitle`,
  `filePublicId`, `name`, `width`, `height`, `mime`, `size`, `isShared`,
  `ownerId`, `isArchived`, `createdAt`. Если строка файла архивная или
  пропала, поля файла приходят как `null`; запись ассета остаётся видимой.
- Ошибки: `ASSET_INVALID`, `ASSET_DENIED`, `ASSET_NOT_FOUND`,
  `ASSET_FILE_INVALID`. Неизвестная или выключенная коллекция —
  `ASSET_INVALID`.
- Маршруты `asset.*` с `csrf: true`; контейнер и порты — по образцу
  `Roleplay/Scene`.

## 7. Фронтенд

### Модуль

- `Dto/AssetItem.ts`, `Dto/AssetPage.ts`, `Dto/AssetQuery.ts`,
  `Dto/AssetCreateRequest.ts`, `Dto/AssetApiError.ts`; часть библиотеки —
  `Enum/AssetScope.ts`.
- `Service/AssetApi.ts`, `Interface/IAssetApi.ts`,
  `Interface/AssetLibraryOptions.ts`, `Composables/useAssetLibrary.ts`,
  `init.ts`, `Mock/mockAssetApi.ts`; регистрация в `main.ts` в обеих ветках.
- `Component/AssetLibraryDialog.vue` — переиспользуемый диалог,
  `Component/AssetLibraryCard.vue` — карточка и переименование,
  `Component/AssetLibraryField.vue` — поле выбора для формы элемента.

### Диалог

- Вкладки «Общие» и «Мои»; активная вкладка грузит свою страницу.
- Поиск по имени, счётчик, догрузка по скроллу или кнопке.
- Карточка: превью через `Core/File/FileImage` (ленивая загрузка уже есть),
  имя, размеры; выбранный ассет подсвечен.
- Загрузка: файл → `file/upload` → `asset.create` в открытую коллекцию и
  вкладку. В общей вкладке кнопка видна только при `user.bypass`.
- Контекстное меню: переименовать, архив — по правам.
- Пустое состояние: «В общей библиотеке пока пусто» / «Загрузите первый
  ассет».
- Диалог не удаляет файлы и не показывает чужие личные ассеты.

### Интеграция со сценой

- `Roleplay/Scene` получает константы коллекций и передаёт их в диалог.
- `SceneElementSettings` для `decor` и `terrain`:
  - превью текущего ассета;
  - «Выбрать из библиотеки» — открывает диалог с нужной коллекцией;
  - «Очистить» — снимает `assetPublicId`;
  - загрузка — внутри диалога, чтобы ассет сразу попадал в «Мои».
- Прямой `FileUploadField` у декора и текстуры террейна заменяется на это
  поле. Подложка поля остаётся на `FileUploadField`: она не ассет
  библиотеки.
- Сцена по-прежнему хранит только `assetPublicId`, поэтому архив ассета не
  ломает сохранённые локации.

1. **Документация.** Этот план, ссылки из `scene-plan-01.md` и

   библиотеки.

## 9. Тесты и гейт

- PHP unit: разбор и валидация входа, имя по умолчанию, инварианты
  shared/owner, запрет не-картинки.
- PHP MySQL: уникальность коллекции, CRUD ассета, фильтры выдачи, личная и
  общая видимость, идемпотентный `ensure`.
- HTTP MySQL: обычный пользователь не создаёт общий ассет; bypass создаёт;
  чужой личный не виден; архив скрывает из выдачи и не трогает файл.
- Vue/Vitest: `AssetApi` (payload/разбор), mock, состояние диалога,
  переключение вкладок и выбор.
- `npx eslint src/modules/Library/Asset src/modules/Roleplay/Scene`,
  `npx vue-tsc --noEmit`, `npx vitest run` по затронутым файлам.
- PHP: `composer stan`, затронутые PHPUnit-тесты, затем `composer test:unit`.
- Ручная проверка: админ грузит общий ассет, обычный пользователь видит его
  в «Общих», грузит свой, не видит чужой; в редакторе выбирает ассет,
  сохраняет сцену, перезагружает; архив ассета не ломает сцену.
- Полный `bash tools/test-full.sh` — после ручной проверки и отдельного
  подтверждения.

## 10. Не входит

- Серверные превью и миниатюры: в первом срезе отдаются исходные байты,
  сетка использует ленивую загрузку. Производные через `Core/Image` — долг.
- Теги, категории внутри коллекции, рейтинг и кураторский порядок.
- Перемещение личного ассета в общую часть и обратно.
- Модерация чужих личных ассетов.
- Коллекции `Roleplay/Map`, портреты, иконки и подложки полей.
- Удаление файлов и каскадная чистка `var/file`.
- Runtime-ассеты Game: библиотека нужна авторскому слою, не бою.
- Пакетное чтение метаданных файлов: выдача использует публичный порт
  `IFiles` (`activePublicIds` + `requireReadable`) и обходится N+1 чтением
  на страницу до 100 записей; batch-метод — долг `Core/File`.

## 11. Критерии готовности

- Общая коллекция видна всем, личная — только владельцу.
- Общую часть наполняет только bypass; личную — любой пользователь.
- `asset_item` не дублирует байты и не меняет `Core/File`.
- Сцена выбирает ассет из нужной коллекции и хранит только `assetPublicId`.
- Архив ассета не ломает уже сохранённые сцены.
- `Roleplay/Map` сможет добавить свои коллекции без правок `Library/Asset`.
