## Как вес устроен сейчас

Вес — одно поле `ItemSpec.weight`. Отдельного веса у профиля оружия и у профиля щита нет. `applyWeight` не смотрит, оружие это или щит: каждый подошедший абзац умножает то же поле. Если в spec есть и блок оружия, и блок щита, абзацы «Оружие» и «Щит» оба подходят, и вес `×1.25` применяется дважды.

## Целевая модель

Модификатор — правило. У него имя, описание и категория (`typeCode`, у «Утяжелённого» это вес). Категория группирует модификаторы, например «только один такой на предмете». Источником чисел она не является. Источник — отдельное правило типа `source`. На операции он записан явно кодом `source_code`. Из категории, кода предмета и подписи абзаца он не выводится.

Посадка на предмет уже описана и остаётся. `ItemModifierApplies` хранит коды признаков `keyword_all`, `keyword_any`, `keyword_none`. «Клинок и короткий» — оба кода в `keyword_all`. «Клинок и не длинный» — клинок в `keyword_all`, длинный в `keyword_none`. «Металлическое и (топор или клинок)» — металл в `keyword_all`, топор и клинок в `keyword_any`. Глубже этой тройки условие не вкладывается. На фронте показываются названия признаков, в spec лежат коды. Подписи «Оружие», «Щит», «Доспех» признаками не являются. Признаки снаряжения, которые уже используются при посадке, — коды `weapon`, `shield-item`, `armor-item`.

После посадки модификатор даёт список операций. Операция — одно изменение одного стата, один раз:

- какой стат;
- на сколько, множителем или слагаемым;
- условие по кодам признаков той же тройкой `keyword_all` / `keyword_any` / `keyword_none`. Пустое условие — стат меняется всегда;
- `source_code` — код правила типа `source`, если он проставлен.

Один и тот же стат от одного проставленного источника схлопывается общим правилом source: сильнейший бонус и сильнейший штраф. Две прибавки минимальной силы с одним и тем же `source_code`, `+2` и `+1`, дают `+2`. Множитель больше 1 — бонус, меньше 1 — штраф. От источника берётся наибольший множитель-бонус и наименьший множитель-штраф, затем они перемножаются. `×0.2`, `×0.5` и `×2` дают `×0.2 × ×2 = ×0.4`. Множитель `×1` не бонус и не штраф. Слагаемые и множители схлопываются отдельно. К базе сначала применяется итог множителей, затем итог слагаемых: так одно поле уже меняет `scaleDefense`. Итоги разных источников для множителя перемножаются, для слагаемого складываются. Операция без `source_code` — уникальный источник: с другими пустыми она не схлопывается.

Статы предмета, а не блока: вес, цена, признаки, проводник магии. Операция веса читает и пишет одно `ItemSpec.weight`. Наличие блока оружия или щита само по себе вес второй раз не запускает.

Статы, которые есть только у блока, операция трогает у блока, чьё условие по признакам выполнено. Блок есть у оружия и у щита. Защита и потолок ловкости есть у доспеха. Минимальная сила есть и у оружия, и у щита: это два поля, пока так записан spec. Прибавка с условием признака `weapon` пишет оружейное поле. Прибавка с условием признака `shield-item` пишет щитовое. Если обе операции с одним `source_code` попали в одно и то же поле, остаётся сильнейшая.

Текстовый абзац для карточки остаётся текстом. Он не выбирает, какие числа применять.

## Форма операции

Новый список `operations` в spec модификатора. Старый `effects` остаётся текстом карточки, пока его не уберут отдельным срезом. Числа читаются только из `operations`. Абзац с `label` «Оружие» сам по себе стат не меняет.

Дискриминатор операции — уже существующий `type` веток `ItemModifierOp`: `weight`, `block`, `min_strength`, `action_strength`, `durability`, `defense`, `max_agility`, `strength_penalty`. Числовые поля те же, что у этих веток, не общее `add` на все статы. Сверх них только `when` и `source_code`.

- `when` — та же тройка кодов, что у посадки. Нет ключа — условие пустое;
- `source_code` — необязательный код правила типа `source`.

Нет ключа `operations` — пустой список. Документ только со старыми `effects` по-прежнему разбирается: `SpecShape::list` отсутствующий ключ не отвергает. Блок щита или оружия, которого в spec нет, операция не создаёт. Так уже делает `applyBlock`: нет `block_profile` или `shield.block` — поле не появляется.

Код в примере ниже — данные документа. Функция не ищет карточку по заранее известной строке и не подставляет категорию `item-weight` вместо источника.

## Пример: Утяжелённый

Посадка остаётся как сейчас: признак любой из `weapon`, `shield-item`, `armor-item`. Категория остаётся `item-weight`. Вес в списке один раз и без `when`.

```json
{
  "type_code": "item-weight",
  "applies": {
    "keyword_all": [],
    "keyword_any": ["weapon", "shield-item", "armor-item"],
    "keyword_none": []
  },
  "operations": [
    { "type": "weight", "factor": 1.25, "source_code": "mass" },
    { "type": "block", "factor": 1.25, "when": { "keyword_all": ["weapon"] }, "source_code": "mass" },
    { "type": "min_strength", "delta": 2, "when": { "keyword_all": ["weapon"] }, "source_code": "mass" },
    { "type": "action_strength", "field": "damage", "delta": 1, "profiles": ["strike", "throw"], "when": { "keyword_all": ["weapon"] }, "source_code": "mass" },
    { "type": "block", "factor": 1.25, "when": { "keyword_all": ["shield-item"] }, "source_code": "mass" },
    { "type": "min_strength", "delta": 1, "when": { "keyword_all": ["shield-item"] }, "source_code": "mass" },
    { "type": "durability", "delta": 1, "when": { "keyword_all": ["shield-item"] }, "source_code": "mass" },
    { "type": "defense", "factor": 1.25, "when": { "keyword_all": ["armor-item"] }, "source_code": "mass" },
    { "type": "max_agility", "delta": -1, "when": { "keyword_all": ["armor-item"] }, "source_code": "mass" },
    { "type": "strength_penalty", "add": -1, "when": { "keyword_all": ["armor-item"] }, "source_code": "mass" }
  ]
}
```

`mass` здесь только пример записанного кода. Щит с признаками `weapon` и `shield-item` получает вес `×1.25` один раз, оружейный блок и щитовой блок по одному разу, оружейную минимальную силу `+2` и щитовую `+1`. Эти две силы лежат в разных полях и друг друга не схлопывают. Если обе прибавки попали в одно поле с `source_code` `mass`, в поле остаётся `+2`.

`action_strength` дописывает `delta` в `modifier` формулы `actionCharacteristic`. В `source_code` этой строки пишется `source_code` операции. Код самого модификатора предмета туда не подставляется: frontend `pushActionDelta` сейчас кладёт `rule.code`, этот срез так не делает. Формула другого вида не меняется.

`durability` в этом примере — прочность щита, уже существующее поле блока, не слот сопротивления. Слот сопротивления без порога в первый срез не входит.

## Срезы

1. **Rule, разбор и применение.** Форма `operations` выше. Функция принимает `ItemSpec`, список модификаторов и коды признаков предмета. Возвращает новый spec. Входной spec не меняет. Лист не читает. Старые `effects[].ops` не исполняет. Frontend этим срезом не меняется и пока считает по-старому.
2. **Frontend.** `ItemModifierService`, редактор и карточка читают `operations`. Подпись абзаца перестаёт выбирать числа. Каталог ещё может содержать старые абзацы: числа из них не берутся.
3. **Контент.** «Утяжелённый» и остальные модификаторы переписываются в `operations`. Это не угадывание подписи «Оружие» кодом.
4. **Сопротивление без порога.** Только вместе с [`rule-plan-08.md`](rule-plan-08.md). Новый слот без `durability` получает null, не `1`.

## Что не переносим

- Сравнение `effect.label` с «Оружие», «Щит», «Доспех», «Общее».
- Три копии операции веса в трёх абзацах.
- Порог `1` у нового слота сопротивления.
- Повтор логики в Character или в Mechanic.
- Подстановку категории или кода предмета в `source_code`.

## Приёмка среза 1

| Случай | Ожидание |
| --- | --- |
| Предмет с блоками оружия и щита и обоими признаками, операция веса одна | `ItemSpec.weight` умножен один раз |
| Две операции `min_strength` с одним `source_code`, `delta` `+2` и `+1`, в одно поле | В поле `+2` |
| Множители одного `source_code` `×0.2`, `×0.5`, `×2` на один вес | Вес умножен на `×0.4` |
| Две такие операции без `source_code` | Обе остаются, как уникальные источники |
| Операция блока при признаке `weapon`, признака нет | Блок оружия не меняется |
| Операция блока при признаке `shield-item` | Меняется блок щита, не блок оружия |
| Операция защиты при признаке `armor-item`, блока доспеха нет | Поле не создаётся |
| Старый абзац с подписью «Оружие» и без `operations` | Числа не применяются |
| Входной spec после вызова | Равен состоянию до вызова |

Character, Mechanic и Game actions срезом 1 не меняются.
