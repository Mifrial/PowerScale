# Система локаций сцен

**Статус:** ~В РАБОТЕ~, 2026-11-17 — authoring-слой локаций; `GameScene`, occupancy, LOS и движение остаются `DEFERRED` в [`battleground-system.md`](battleground-system.md).
**Реализация:** ~PHP~ — M1 готов, ~VUE~ — M2 (просмотр) готов, ~МОК~ — да.
**Опираться на:** ~PHP~ (`Core/File`, `Core/User`, `Core/SmartTable`), ~МОК~.

Документ фиксирует авторскую библиотеку локаций: как ведущий проектирует
тактическую сцену без персонажей и как Game позже получает её независимую
копию. Боевой runtime, видимость, движение и `GameScene` сюда не входят.

## Назначение

`SceneLocation` — авторский шаблон детальной сцены. Он содержит одно или
несколько полей (`SceneBoard`), геометрию, подложки, декор и служебные маркеры.
Локация не знает про игру, карту мира, персонажей и боевые процедуры.

Game позже читает локацию как snapshot и создаёт свою `GameScene`: независимую
копию с NPC/PC, occupancy, туманом и движением. Изменение локации после
копирования не меняет уже созданную сцену.

```text
SceneLocation «Таверна»
├── SceneBoard «Двор»
├── SceneBoard «1 этаж»
└── SceneBoard «2 этаж»

Map (карта мира) → позже может ссылаться на SceneLocation
GameScene        → независимая копия SceneLocation внутри игры
```

## Термины

| Термин | Код | Что это | Владелец |
|---|---|---|---|
| Локация | `SceneLocation` | Авторский шаблон детальной сцены. | `Roleplay/Scene` |
| Поле локации | `SceneBoard` | Одно 2D-полотно: подложка, границы, свои координаты. | `Roleplay/Scene` |
| Элемент поля | `SceneElement` | Опора, препятствие, проём, террейн, декор или маркер на поле. | `Roleplay/Scene` |
| Вложение | `SceneEnclosure` | Связь «поле внутри поля»: дом на поляне, этаж дома, подвал. | `Roleplay/Scene` |
| Этаж | `SceneEnclosure` + `SceneBoard` | Поле-вложение с вертикальной отметкой: выше, ниже или на той же отметке родителя. | `Roleplay/Scene` |
| Строение | `SceneEnclosure` | Верхнее вложение и его потомки: у строения своя стопка этажей. | `Roleplay/Scene` |
| Сцена игры | `GameScene` | Независимая копия локации в игре с актёрами и боевым состоянием. | `Roleplay/Game` (позже) |

В старых deferred-спеках battleground использовался `SceneSpace`. В этом каноне
термин заменён на `SceneBoard`, чтобы не путать с `Versioning/Space`,
`RuleSpace` и «пространством игры». `SceneSpace` считается историческим.

## Границы

- `Roleplay/Scene` не импортирует `Roleplay/Game`, `Roleplay/Map` и `Roleplay/Character`.
- `Map` позже может ссылаться на локацию: `Map → SceneLocation`. Обратной
  зависимости быть не должно. В `Scene` нет `mapNodeId`.
- `Game` позже читает локацию через публичный порт и создаёт независимый
  snapshot. `Scene` не знает, кто именно её прочитал.
- Локация не содержит PC/NPC, инициативы, ОД, тумана и результата боя.
- Локация не является картой мира и не участвует в маршруте по мировой карте.

## Единицы и масштаб

- Ипари — единственная единица расстояний в интерфейсе. Метры не используются.
- `resolution` — целых единиц сцены на 1 ипари; по умолчанию 64. Допустимы
  только степени двойки (16…1024), чтобы любое расстояние переводилось в
  размерное число `{base|size}` без дробей.
- Внутри хранятся целые единицы сцены. Интерфейс показывает ипари: при
  `resolution = 64` 1 ед. = `{1|-6}` ипари, 0,5 ипари = 32 ед. = `{1|-1}`,
  0,25 = 16 ед. = `{1|-2}`, 0,375 = 24 ед. = `{3|-3}`.
- Размерность: `{3|1}` = 6 ипари, `{4|-1}` = 2 ипари. `1 ипари = 1,5 м`
  остаётся справочным фактом вне сцены; в UI метры не показываются.
- `gridStep` — визуальная сетка: `0` — выключена; по умолчанию 0,5 ипари
  (32 ед.), жирная линия каждые два шага (1 ипари).
- `occupancyCell` — клетка сэмплинга света/укрытий, по умолчанию 0,25 ипари
  (16 ед.). На движение и отрисовку карты не влияет; это ручка производительности
  будущих расчётов.
- Клетка движения 1×1 ипари не является полем карты: её применяет Game.
- Смена `resolution` — пересчёт всех координат, размеров и высот в черновике
  (`new/old`) с округлением; сохраняется обычным `scene.save` и поднимает
  `version`. Карта сохраняет физический размер, меняется только точность.

## Модель

### `scene_location`

```
id             IdField
owner_id       UserReferenceField, indexed
name           StringField 255, required
description    TextField, required, default ''
resolution     IntField, required, default 64, min 1, max 1024
schema_version IntField, required, default 1, min 1
is_archived    BoolField, required, default false, indexed
version        IntField, required, default 1, min 1
updated_by     UserReferenceField, nullable, onDelete setNull
created_at     DateTimeField, required, default now
updated_at     DateTimeField, required, default now
```

- `resolution` — целых единиц сцены на один ипари. По умолчанию `64`;
  допустимы степени двойки от `16` до `1024`.
- `schema_version` — версия формы snapshot, не версия строки.
- `version` увеличивается только успешным `scene.save`.
- `updated_at` и `updated_by` пишет только `scene.save`.
- Удаление — `is_archived = true`, не hard-delete.

### `scene_board`

```
id             IdField
location_id    ReferenceField scene_location, indexed, onDelete cascade
name           StringField 255, required
sort_order     IntField, required, default 0, min 0
base_file_id   FileReferenceField, nullable, onDelete setNull
bound_width    IntField, required, min 1
bound_height   IntField, required, min 1
occupancy_cell IntField, required, default 16, min 1
z_quantum      IntField, required, default 16, min 1
grid_step      IntField, required, default 0, min 0
created_at     DateTimeField, required, default now
```

- Поле — не «этаж всей локации» и не слой. У него своя подложка и свои
  координаты. В предпросмотре поля-этажи одного строения рисуются как стопка
  в мире корневого поля; это слой отображения, а не слияние данных: стены
  этажа по-прежнему не блокируют нижний этаж в навигации.
- `bound_width`/`bound_height` — логические границы в единицах сцены.
  Ориентир: типичная карта ~40×40 ипари, запас — 200×200 ипари.
- `occupancy_cell` и `z_quantum` — параметры будущей occupancy-сетки. В
  authoring-слое они только хранятся; сетка не строится. Значение по умолчанию
  `16` соответствует `resolution = 64`; при другом разрешении редактор
  предлагает `resolution / 4`. Это сэмплинг света/укрытий, не клетка движения.
- `grid_step = 0` — визуальная сетка выключена. Редактор рисует тонкие линии
  с шагом `grid_step` и жирные — каждые два шага (1 ипари при значении по
  умолчанию).
- Подложка хранится ссылкой на `Core/File`; пиксели изображения не являются
  единицами сцены. Масштаб выводится из `bound_width/height` и размеров файла;
  отдельного float-поля нет.

### `scene_element`

```
id              IdField
board_id        ReferenceField scene_board, indexed, onDelete cascade
kind            StringField 32, required, indexed
shape           JsonField, required
props           JsonField, required, default {}
sort_order      IntField, required, default 0, min 0
target_board_id IntField, nullable, indexed
created_at      DateTimeField, required, default now
```

Один writer и один валидатор на все примитивы. Новый тип не требует миграции:
добавляется `kind` и правила его `props`. Типизация остаётся на границе DTO и
серверного валидатора.

Первый набор `kind`:

| `kind` | Назначение | `props` первого среза |
|---|---|---|
| `support` | Земля, настил, крыша, стойка, мост, съезд, лестница. | `kind`, `height`, `elevation`, `rotation`, `speed`; у крыши — `walkable`, у лестницы — `railing` |
| `obstacle` | Стена, ствол, мебель, непроходимый объём. | `blocksMovement`, `blocksVision`, `height`; у стены толщина — `shape.width` и материал — `material` |
| `opening` | Дверь, окно, ворота, лестница, телепорт. | `kind`, `state`, `blocksVision`, у окна `sill` и `lintel`; цель — колонка `target_board_id` |
| `terrain` | Грязь, лёд, вода, высокая трава, пол из досок и плитки. | `kind`, `shoreKind`, `shoreWidth`, `speed`, `label`, `overWater`, опционально `assetPublicId`; у воды — `depth` |
| `decor` | Декоративный токен или ассет. | `assetPublicId`, `rotation`, `scale`, `footprint`, `silhouette`, `blocksVision`, `speed`, `baseRadius`, `sightRadius`, `sightBottom`, `label` |
| `marker` | Служебная точка: вход, спавн, добыча. | `role`, `label` |

`enclosure` не является элементом: это связь двух полей, см. ниже.

### Стена-лента и проёмы

`obstacle` с фигурой `wall` — стена-лента: осевая линия и `shape.width`
(толщина). `opening` с фигурой `wall` — проём в стене: короткий участок той же
осевой и той же толщины. Проём не лежит поверх стены: стена режется на участки
между проёмами — и в рисунке, и в сетке поверхностей. Поэтому окно не наследует
непрозрачность стены, а открытая дверь действительно прорезает проход.

Материал стены — `props.material`: `plaster` (по умолчанию), `wood`, `log`,
`brick`, `stone`. Это верхняя грань полосы, которую видно сверху: ровный тон,
обводка силуэта и швы. Материал есть только у стены-ленты; у остальных препятствий он
отбрасывается при сохранении, потому что верх у них не рисуется. Пресеты
редактора: «Стена» и «Кольцо» ставят штукатурку, «Забор» — доски, толщину
`0,125` и высоту `0,75` ипари.

Свойства проёма: `kind` (`door`, `window`, `gate`, `stairs`, `teleport`),
`state` (`open`/`closed`), `blocksVision`, у окна — `sill` и `lintel` в
единицах сцены. Закрытая дверь — полоса на всю высоту; открытая — проход и
прозрачность; окно не проходимо никогда, а обзор открыт только между
подоконником и перемычкой: ниже и выше — стена. В сетке поверхностей у окна
поэтому две полосы перекрытия, а не одна: полоса над перемычкой кончается на
верху стены, которую режет окно, а не уходит в небо — иначе с крыши, которая
выше стены, окно читалось бы стеной до неба и бросало тень полосой на настил.
`blocksVision = false` у закрытой двери — стекло: видно, но не пройти.

`props.wallId` и `props.offset` — редакторские: привязка проёма к стене и его
начало вдоль осевой. В снимок они не пишутся: временные id после вставки строк
сменились бы. При загрузке привязка восстанавливается проекцией проёма на
стену, поэтому проём продолжает ездить за стеной.

`decor.footprint` и `decor.silhouette` — основание и перекрытие обзора в
**единицах сцены**, локально от якоря. Форма — круг (`radius`) или полигон
(`points` с необязательными `handles`); у силуэта ещё `bottom` — высота, с
которой начинается перекрытие, и необязательный `top` — где оно кончается.
Без `top` перекрытие идёт до неба, как у ствола или стены; с `top` объект
виден сверху, если луч идёт выше него. `offset` двигает всю форму от якоря, не
трогая сам объект: так круг отвязывается от точки спрайта. Полигон и смещение
поворачиваются вместе с `props.rotation`, поэтому перенос и поворот объекта не
требуют правки контура. Кривые Безье разворачиваются в площадь: ход, маршрут и
обзор идут по нарисованному контуру. Основание задаёт ход, силуэт — обзор:
`bottom = 0` перекрывает от земли, у кроны дерева он выше глаз.

Обе зоны редактируются одинаково: в карточке — вид (круг или полигон), радиус,
смещение X/Y, «Обвести» и сглаживание, на карте — вершины, ручки Безье,
двойной клик добавляет вершину, Alt удаляет. У зоны непрозрачности ещё два поля
высот: «Низ силуэта» и «Верх силуэта» в ипари. Пока `silhouette` не задан
явно, зона непрозрачности совпадает с основанием: мастер уже обвёл видимую
массу объекта, и тень должна начинаться от неё, а не от круга, посаженного на
якорь. Кнопка «Отделить» снимает копию с основания: дальше зоны живут отдельно,
у силуэта появляются свои вершины на карте, и правка одной зоны не меняет
другую. До отделения вершины силуэта не рисуются — они лежали бы на вершинах
основания, и перетаскивание попадало бы в чужую зону.

`decor.speed` — проходимость основания: `0` (по умолчанию) — непроходимо,
выше нуля — проходимый декор, который не вычитается из навмеша.
`blocksVision: false` выключает перекрытие обзора целиком, включая силуэт.

Старые сцены новых полей не имеют: для них работают `baseRadius`,
`sightRadius` и `sightBottom` — проценты ширины спрайта. Это совместимость, а
не канон: прозрачные поля картинки попадают в такую зону, поэтому у новых
объектов основание задаётся в ипари и от спрайта не зависит.

При выборе ассета декора карточка подставляет пресет по имени загруженного
файла (`SCENE_DECOR_PRESETS`): у `tree.png` узкое основание ствола, у куста —
почти весь спрайт. Пресет задаёт стартовые `scale`, `baseRadius`, `sightRadius`
и `sightBottom`; при первом редактировании карточка переводит их в
`footprint`/`silhouette`, и элемент хранит уже конкретные значения.

Прозрачные поля картинки не сбивают ни якорь, ни масштаб: при загрузке
`Core/File` считает `content_box` — рамку видимой массы, а сцена ставит на
якорь её низ и считает `scale` от её ширины. Рамка приходит вместе с ассетом
и не сохраняется в локации: файл неизменяем. У старой картинки без рамки
рисуется весь файл, как раньше
([`scene-plan-06-objects.md`](scene-plan-06-objects.md)).

Объект библиотеки — снимок физики декора в `asset_item.meta` под ключом
`sceneObject`: `version`, `kind`, `resolution`, `scale`, `footprint`,
`silhouette`, `speed`, `blocksVision`, `rotation`. Объект — отдельная запись
ассета на том же файле, поэтому один спрайт даёт несколько шаблонов. Постановка
копирует числа в элемент, а не ссылается на шаблон: правка объекта не
переписывает сохранённые карты. Формы записаны в единицах сцены того
разрешения, где объект сохраняли, поэтому при постановке на поле с другим
разрешением они пересчитываются. Палитра «Объекты» показывает записи с `meta`
и ставит декор кликом по карте
([`scene-plan-06-objects.md`](scene-plan-06-objects.md)).

`terrain.kind` — шаблон отрисовки (`grass`, `dirt`, `stone`, `sand`,
`mud`, `water`, `ice`) и материал пола (`wood` — доски, `tile` — плитка).
Скорость поверхности — явное целое `props.speed`
(`0…10000`, `100` — норма, `0` — непроходимо); значения по типу служат только
пресетами новых элементов. Предпросмотр локации использует её же для маршрута,
Game — для runtime-движения. `assetPublicId` — необязательная
картинка-текстура террейна. В редакторе декор и текстура выбираются из
коллекций `decor` и `terrain` библиотеки ассетов
([`asset-library-plan-01.md`](asset-library-plan-01.md)); сцена хранит только
`assetPublicId`, поэтому архив ассета не ломает сохранённую локацию.

`terrain.shoreKind` и `terrain.shoreWidth` — кромка террейна: внешняя полоса
вокруг поверхности. Это свойство того же элемента, а не отдельный элемент,
стена или препятствие.

- `shoreKind` — материал кромки: `none`, `grass`, `dirt`, `stone`, `sand`,
  `mud`, `ice`. По умолчанию `none`.
- `shoreWidth` — ширина кромки в целых единицах сцены, `0…100000`; интерфейс
  показывает ипари. При `shoreKind = none` ширина `0`.
- У `path` кромка расширяет ленту с обеих сторон; у замкнутой фигуры
  (`rect`, `circle`, `polygon`) это наружная полоса по контуру.
- Кромка не меняет проходимость и обзор. Для воды это берег
  (песок, камни, трава), для дороги — обочина; материал выбирается отдельно
  от поверхности. Высоту кромка меняет только у врезанной воды: там она
  становится откосом (см. ниже).
- У воды кромка задаёт берег **всего водоёма**, включая острова: остров,
  целиком окружённый водой, вода считает дыркой в своём поле глубины. Мель,
  поглощение, накат, пена и мокрый песок у острова считаются теми же
  шейдерами и теми же `shoreKind`/`shoreWidth`/`depth` воды. Сухую полосу
  берега вода рисует внутрь контура острова на `shoreWidth`; собственная
  кромка такого острова не рисуется, чтобы берег не задавался дважды.
  Полуостров и насыпь, упирающиеся в сушу, в дырки не попадают: у них
  остаётся собственная кромка.
- Разные материалы по сторонам ленты и по участкам — позже; текущий контракт
  задаёт один материал и одну ширину на элемент.

Полы `wood` и `tile` — твёрдые поверхности: у них нет кромки и осыпи, а
материал лежит по контуру фигуры. Пресеты «Пол: доски» и «Пол: плитка» в
редакторе ставят вид пола и скорость `120`. Кромку у такого пола задавать
бессмысленно: он не сыплется на соседей, а край режется по контуру.

`terrain.depth` — глубина воды в целых единицах сцены, `0…100000`; интерфейс
показывает ипари. Поле есть только у `kind = water`; у остального террейна оно
отбрасывается. `0` — вода вровень с берегом (старые сцены живут так), больше
нуля — врезанное русло.

Пресет «Река» в редакторе ставит `water` + `sand`, ширину кромки `1,5` ипари
и глубину `0,5` ипари; это значения пресета, а не умолчания валидатора.

`terrain.overWater` — контур лежит поверх воды: остров, насыпь, полуостров.
Вода рисуется над сушей (река перекрывает дорогу), поэтому без признака трава
острова утонула бы под озером. Порядок один для рисунка и для сетки
поверхностей: суша → вода → `overWater`. Пресет «Остров» в редакторе ставит
`grass` и этот признак; берег острову задаёт вода, в которой он лежит (см.
выше), а не собственная кромка острова. Декор на острове не считается мокрым:
поле глубины воды вырезает контур острова, поэтому глубина под ним нулевая.
Террейн **внутри** острова — пол дома, дорожка, двор — тоже ставит `overWater`,
иначе остров нарисуется поверх него. Редактор ставит признак сам, когда создаёт
пол комнаты на острове. Для высот `overWater` — ещё и поверхность под ногами:
пол дома над водой не проваливается до воды, иначе съезд или лестница на нём
садились бы низким концом на воду, а не на пол.

Поле можно залить террейном целиком: редактор создаёт обычный элемент
`terrain` с `rect` по границам поля. Если такой элемент уже есть, меняется его
шаблон, а не добавляется второй. При изменении `bound_width`/`bound_height`
террейн, который ровно совпадал со старыми границами, растягивается вместе с
полем.

`height` и `elevation` — вертикальные размеры в единицах сцены; интерфейс
показывает ипари. `height` — вертикальный размер/толщина, `elevation` — высота
верхней поверхности опоры над нулём поля. Толщина стены — это `shape.width`, а
не `height`.

Высоты — данные для Game, а не рисунок: top-down рендерер не поднимает настил
над берегом. По `elevation`, `height` и поверхности под опорой Game считает
зазор и рёбра доступа. Исключение — лестница: её подъём виден и в рисунке, но
не боковой гранью, а мягкими ступенями по тому же `elevation`. Перила
лестницы (`props.railing`, по умолчанию выключены) подняты на
`SCENE_BRIDGE.railHeightIpari` и участвуют в навигации как отдельный уровень.
Пороги — `SCENE_NAVIGATION.stepIpari`,
`climbIpari`, `dropIpari` и `bodyHeightIpari`; вода остаётся проходимой
поверхностью, поэтому маршрут под мостом возможен, если зазор достаточен.

Навигация знает уровни: настил выше `stepIpari` — отдельный уровень, а не
замена пола. Уровни связываются порталами `walk` / `climb` / `drop` по
перепаду; переходы направленные: вверх — `climb` в пределах `climbIpari`,
вниз — `drop` в пределах `dropIpari` (2 ипари = 3 м). Звено существует, если
разрешено хотя бы одно направление, поэтому с настила можно сойти там, где
забраться уже нельзя. Съезд — наклонный уровень, который садится на
поверхность низким концом. Верхний торец съезда не связывается с нижним
уровнем: под ним пол верхнего этажа, а не край настила, иначе маршрут
«спрыгивал» бы с верхней ступени сквозь перекрытие. Зато торец связывается с
уровнем прямо над ним — проходимой крышей или настилом выше: так лестница
внутри дома выходит на крышу, не прорезая её. Уровень площадки перехода —
пол: маршрут с площадки начинается с её уровня, а не с верхнего настила,
который может её накрывать (крыша над лестничной клеткой). Перила — ступень
`SCENE_BRIDGE.railHeightIpari` (0,5 ипари) над настилом: отдельный уровень,
через который можно перелезть с доплатой, а вход на настил остаётся с торцов.

Вода опущена на `props.depth` в единицах сцены: `0` — вровень с берегом (так
живут старые сцены), больше нуля — врезанное русло. Береговая полоса
`shoreWidth` при этом становится откосом: в сетке поверхностей она линейно
опускается от отметки берега до поверхности воды, поэтому вход в воду — наклон,
а не обрыв. Без береговой полосы откоса нет и вход остаётся спуском; карточка
об этом предупреждает. Навигация пока полигональная и плоская: уровень земли
один, и глубина маршрут по земле не меняет — она задаёт высоты, зазор под
настилом и вид откоса. Настил над врезанным руслом при этом становится
отдельным уровнем: его верх может быть на отметке берега, но под ним есть
место для тела, поэтому вода остаётся проходимой, а доски — потолком.

Клик по карте в предпросмотре различает уровни и этажи: клик приходит с полем,
которое накрывает точку (`SceneCanvas`), `levelsAt` отдаёт все уровни под
точкой, Alt+клик всегда ведёт по земле, обычный клик при нескольких уровнях
открывает меню «на настил / под настилом». Если верхний уровень недоступен,
маршрут откатывается на землю. Клик по другому видимому этажу строит маршрут
через площадку и не меняет фокус.

Обзор тоже знает уровни. Сетка поверхностей хранит полосу перекрытия
`sightBottom…sightTop` в ипари и пол под настилом отдельно от настила
(`ground` против `elevation`). Настил перекрывает только свою толщину: луч с
настила идёт над ним, луч из-под настила — под ним, а сквозь доски не видно ни
тому, ни другому. Пол под настилом остаётся прежним, поэтому вода и берег не
теряют своей высоты. Под настилом глаза упираются в зазор: тело не выходит за
потолок, иначе луч из-под моста начинался бы внутри настила. Зазор считается
до самой низкой поверхности под настилом, а не до самой высокой: мост через
врезанное русло опирается торцами на берег, но проход считается по воде. Под
настилом закрыты только полосы, где просвет меньше роста тела; у такого моста
это торцы на берегу, а вода под серединой остаётся проходимой.

Высоты обзора считаются от роста тела: глаза — 90% роста. Цель видна, если
видна любая точка её тела: клетка с полосой `sightBottom…sightTop` закрывает
диапазон высот, интервалы сливаются, и цель скрыта, только если они покрыли
весь рост. Поэтому низкий забор не скрывает голову, а ствол или стена скрывают
всё. Рост хранится целыми единицами сцены, поэтому глаз остаётся целой
единицей, а в ипари переводится делением на степень двойки. Рост по
умолчанию — `SCENE_NAVIGATION.bodyHeightIpari` (1,2 ипари): при
`resolution = 64` это 77 ед., глаз — 69 ед. = `{69|-6}` ипари. У высокого
персонажа глаз выше, у низкого — ниже; фиксированных дробных высот в данных
нет. Под настилом глаз по-прежнему ограничен зазором, а на настиле зазор
относится к пространству под ним и высоту не режет.

Стена в сетке несёт верх из `props.height`: полоса идёт от пола этажа до этой
отметки, а без высоты — до неба. Поэтому низкий забор двор не скрывает, стена
дома выше глаз закрывает, а на крыше глаз выше стен и настил просматривается
целиком. Тонкая стена не теряется между центрами клеток: разметка идёт с
допуском в полклетки, и проём режется тем же допуском, иначе калитка в заборе
закрылась бы. Видимость своего поля считается точным лучом по клеткам (DDA)
на высоте глаз, поэтому у кромки проёма нет боковых «крыльев», а своё и чужие
поля используют одну и ту же геометрию.

Марш и съезд — наклонные настилы: высота верхней поверхности пишется по
клетке, а не одним высоким торцом. Когда марш идёт под проходимой крышей, он
остаётся нижним настилом (`deck`), а крыша занимает `elevation`; глаз на
марше ограничен низом потолка и на нижней части лестницы видит комнату, а не
весь этаж. Крыша считается крышей только тогда, когда актор стоит на её
верхней поверхности: признак приходит из уровней навигации, а не только из
типа клетки. На люке полоса крыши снята, и глаз выходит на крышу. Марш
доводится до ближней к нему кромки площадки перехода: верхние ступени под
площадкой — ровная ступень, а не наклон под доской.

Верхний этаж — тоже потолок: глаз наблюдателя, стоящего в его пятне ниже его
пола (на марше, площадке, в колодце), не поднимается выше этого пола. Иначе
марш у самого верха смотрел бы поверх стен своего этажа и открывал двор и
чужие комнаты. Ограничение общее: маска тумана, видимость акторов и запрос по
растрам считают глаз одинаково, а на самом верхнем этаже (и на его площадке)
его уже нет.

Край радиуса — поле расстояний до видимой области, а остаток радиуса
применяется только рядом с ней: иначе он подсвечивал бы клетки за стеной и на
границе круга оставались бы световые дуги.

Между этажами обзор считает `SceneFloorSightService`: луч идёт в мире корня,
плиты проверяются на пути, а стены — у всех этажей, чью полосу высот он
пересекает: стены своего и верхних — потому что с марша луч идёт выше своего
этажа, стены нижних — потому что к воде или нижнему актору он уходит вниз и
может пройти под стеной своего этажа. Проём
прозрачен по своей высоте: дверь и ворота — от пола до неба, окно — только
между подоконником и перемычкой, как в сетке поверхностей. Растр стен хранит
верх стены и полосы окна, поэтому луч выше стены проходит поверх, а окно не
становится дырой во всю стену: с крыши свет не уходит сквозь нижнее окно или
дверь полосой в двор. Со второго этажа двор виден через низкий забор, а глухая
стена дома всё ещё закрывает. Плита — террейн этажа, кроме воды: луч
перекрывается, только если пересекает её плоскость внутри пятна и вне колодца
или площадки (проём-лестница). Поверхность воды лежит ниже пола, поэтому под
водой пола нет: луч к ней проходит вниз, иначе вода с другого этажа всегда
оставалась бы в тумане. Поэтому с этажа видно ступени и актора снизу через
колодец, а двор — через окно; глухая стена и глухой пол скрывают то, что за
ними. В разрезе плита полупрозрачна и показывает нижний этаж планом: она не
перекрывает взгляд, а стены разрезанного этажа под её пятном (нарисованным
полом, а не всем полем) не считаются — они срезаны и в рисунке.

С крыши плиты не отключаются. Крыша — настил (`support`), а не уровень этажа:
её плоскость в растр плит не входит, поэтому «плита под ногами» луч не режет,
и настил крыши виден целиком. Но пол этажа, на котором крыша лежит, остаётся
на пути луча: он не даёт лучу нырнуть внутрь дома и выйти на траву сквозь
дверь или окно нижнего этажа. Поэтому с крыши видны двор за краем плиты и
настил, а земля под домом и светлые полосы у нижних проёмов — нет; стены
своего этажа на крыше пропускаются отдельным признаком (`onRoof`), потому что
они ниже настила.

Разрез просвечивает только вниз: актор над наблюдателем остаётся за плитой и
скрыт (`hidden`), потому что иначе с первого этажа было бы видно, кто на
втором. Туман чужого этажа целится в план пола, а не в верхний настил: под
проходимой крышей человек стоит на полу, а луч к верху крыши проскакивал бы
через колодец и подсвечивал половину этажа.
Призраки — только на этаже
наблюдателя; актор чужого этажа либо виден, либо скрыт (`hidden`), но остаётся
в списке акторов.

`target_board_id` используется `opening`; для остальных `kind` он `null`.
Валидатор проверяет, что целевое поле принадлежит той же локации, а не самому
элементу.

Будущие `kind` без изменения таблицы: `water`, `instance_layer` (лес), другие
объекты. Добавление `kind` сопровождается правилами валидации и рендера.

### `shape`

Все координаты — целые единицы сцены, начало координат — левый верхний угол
поля, `x` вправо, `y` вниз.

```json
{ "type": "rect",    "x": 0, "y": 0, "w": 640, "h": 320 }
{ "type": "circle",  "cx": 320, "cy": 320, "r": 160 }
{ "type": "wall",    "points": [[0, 0], [640, 0]], "width": 16 }
{ "type": "polygon", "points": [[0, 0], [640, 0], [640, 480]],
  "handles": [{ "in": [0, 0], "out": [120, 0] }, { "in": [0, 0], "out": [0, 0] }, { "in": [0, 0], "out": [0, 0] }] }
{ "type": "path",    "points": [[0, 320], [640, 320]], "widths": [40, 40],
  "handles": [{ "in": [0, 0], "out": [100, 0] }, { "in": [-100, 0], "out": [0, 0] }] }
{ "type": "point",   "x": 320, "y": 320 }
```

- `rect`, `circle`, `wall`, `polygon`, `path`; `point` для маркеров и декора.
- `handles` — необязательные ручки Безье по вершинам: `in` и `out` — смещения
  относительно самой вершины. Закрытый `polygon` замыкает последний сегмент на
  первую вершину; открытый `path` концами остаётся прямым.
- `path` — лента: река, дорога, тропа. `widths` — ширина в каждой вершине;
  край строится по нормали к осевой. Лента — это **террейн**, а не отдельный
  `kind` и не стена: она лежит на земле, не задаёт высоту и не блокирует
  обзор. Шаблон (`water`, `dirt`) выбирается в `terrain.kind`. Скорость и
  проходимость остаются за Game, как и у остального террейна.
- Полигон и лента рисуются кликами: замыкание полигона — по первой вершине,
  двойному клику или `Enter`; лента завершается двойным кликом или `Enter`;
  `Esc` — отмена. Двойной клик по ребру вставляет вершину с сохранением
  кривой, ручки вершины гнут сегменты, `Alt` разрывает зеркальность ручек,
  `Alt`+клик по вершине удаляет её. У ленты ромб на вершине тянет ширину.
- Стена — лента с толщиной: рисуется полилинией по кликам, замыкание — по
  первой вершине, ветка — новая полилиния от существующего узла. Инструмент
  «Кольцо» строит замкнутую стену по центру и радиусу. Концы свариваются в
  общий узел: близкие вершины стягиваются, а конец, упёршийся в тело другой
  стены, вставляется в неё коллинеарной вершиной. Поэтому перетаскивание стены
  тянет смежные стены за общие узлы, а не отрывает их. Углы одной ленты
  сходятся митрой, а соседние ленты на угле и Т-стыке сводятся в общий силуэт
  булевой геометрией: ступеньки в половину толщины не остаётся.
- Комната — ограниченная грань сети стен. Инструмент «Комната» выбирает грань
  под курсором; в набор входят её стены, проёмы, пол и содержимое, поэтому
  перетаскивание двигает комнату целиком. Пол — обычный `terrain`-полигон по
  контуру грани; кнопка «Пол комнаты» создаёт его и ставит под уже
  существующие полы внутри.
- Строение — связная сеть стен и всё внутри её внешнего контура. Инструмент
  «Строение» выбирает его кликом в любом месте контура; из вложенных берётся
  самое маленькое, поэтому клик в доме выбирает дом, а клик во дворе — двор со
  всем, что в нём стоит. `Alt`+клик по стене и кнопка «Выбрать строение» в
  карточке делают то же самое. Чужая стена входит в набор, только если лежит
  внутри контура целиком: забор, который строение лишь пересекает, остаётся
  собой, иначе дом, наехавший на забор, утащил бы весь двор. Проём входит
  только вместе со своей стеной: калитка чужого забора не едет за домом.
- Область выбора — один переключатель «Выбор» с вариантами `Объект`,
  `Комната`, `Строение`; активный вариант виден на кнопке. Выделенная группа
  рисуется общим пунктирным габаритом, а нажатие внутри неё тянет группу
  целиком, а не верхний объект под курсором.
- Пол, совпадающий по площади с гранью (в пределах 15%), тянет эту грань:
  пол комнаты — комнату, пол дома — всё строение со стенами, проёмами и
  содержимым. Дорога или заплатка внутри двора по площади не совпадают и
  остаются собой.
- Этаж — отдельное поле-вложение (`SceneEnclosure`), а не настил на том же
  поле: стены этажа на одном поле блокировали бы нижний этаж и для хода, и для
  обзора. Инструмент «Этаж» протяжкой плана создаёт дочернее поле: его границы
  — план плюс поля обзора (`SCENE_FLOOR.contextMarginIpari`), вложение хранит
  область родителя, а план вписан в поле с тем же отступом. Пятно вложения едет
  со строением, когда перетаскивается весь его контур; содержимое поля остаётся
  в своих координатах. Инструмент задаёт направление (вверх или вниз), высоту
  (по умолчанию `SCENE_FLOOR.storeyIpari`) и подпись: она попадает в `label`
  вложения и в имя поля. Отметку и подпись существующего этажа можно поправить
  в карточке поля. Вкладки этажей сгруппированы по строениям: корень первым,
  этажи — по возрастанию отметки, у этажа значок направления.
- Вертикальный порядок этажей задаёт `elevation` вложения: знаковое целое в
  единицах сцены относительно родителя (`+` вверх, `-` вниз, `0` — помещение на
  той же отметке). Абсолютная отметка — сумма по цепочке; корень — `0`. Верхнее
  вложение и его потомки образуют строение; на одном корневом поле может быть
  несколько строений. Корень — общая земля и нижняя опора стопки: в сцене 3
  первый этаж нарисован на корне, поэтому корень считается этажом `0` стопки,
  хотя и не является строкой `scene_enclosure`. Подвал или пещера — вложение с
  отрицательной отметкой. Схема, миграция и этапы — в
  [`scene-plan-07-floors.md`](scene-plan-07-floors.md).
- В предпросмотре мир один: корневое поле и видимые этажи
  рисуются в координатах корня, камера при смене этажа не вписывается заново,
  плита выбранного этажа полупрозрачна (тумблер «показать нижний этаж»), а
  лестничный проём — настоящий вырез в плите. Стены и крыша этажа под плитой
  срезаны её пятном — нарисованным полом этажа (габарит террейна, кроме воды),
  а не всем полем с полями обзора: забор двора и ворота в нём остаются. Сквозь
  пол виден план, а не стены первого этажа. Этажи
  выше фокуса скрыты. Для
  каждой стопки кандидаты — корень (`0`) и все поля цепочки; берётся этаж с
  наибольшей отметкой не выше фокуса, при равенстве — дочернее поле. Если в
  стопке нет этажа на отметке не выше фокуса, стопка не рисуется: её землю
  уже показывает корень, а верхний этаж поверх корня закрыл бы двор. Активная
  стопка дополнительно рисует ближайший этаж ниже и идёт последней; у корня
  плита не просвечивает целиком — только пятна подвалов и колодцы. Композит
  сделан в F1; этапы F2–F5 — [`scene-plan-07-floors.md`](scene-plan-07-floors.md).
- Лестница — опора `support` с `props.kind = 'stairs'`: наклонный марш, как
  съезд, но со ступенями и без досок и перил моста. `elevation` — высота
  верхнего конца, `height` — толщина марша, длинная сторона прямоугольника —
  направление подъёма. Лестничного «дома» и дверей у неё нет: марш стоит в
  комнате открыто.
- Одна лестница может соединять любые два этажа, не только соседние: верхняя
  площадка ссылается на целевое поле, и это ребро графа. Подвал → десятый
  этаж — такое же ребро, как первый → второй. Длинный марш рисуется на нижнем
  поле; если фокус выше, на верхнем показывается шахта перехода. Если марш
  проходит сквозь промежуточные этажи, в их плитах вырезаются проёмы шахты —
  те же вырезы, что и колодец. Ограничение «только соседний этаж» не
  закладывается.
- Площадка лестницы — прямоугольный `opening` с `props.kind = 'stairs'`:
  верхняя ступень марша и площадка перехода. Проём без цели — лестничный
  колодец: он закрыт для хода, но прозрачен для взгляда, поэтому с этажа видно
  ступени, уходящие вниз. Площадка большая (несколько ступеней), наведение
  мыши её подсвечивает. Марш доводится до ближней к нему кромки площадки:
  верхние ступени под площадкой — ровная верхняя ступень, а не наклон под
  доской, иначе актор на них стоял бы в перекрытии. Плита этажа под площадкой
  вырезана так же, как под колодцем, поэтому не закрывает актора на марше.
- Проём с `target_board_id` — ребро перехода между полями, а не телепорт. В
  целевом предпросмотре маршрут идёт по лестнице, на площадке актор меняет
  поле и продолжает путь; поле не переключается. Марш лежит на нижнем поле:
  при подъёме актор идёт по нему на нижнем поле и на верхней площадке меняет
  поле на верхнее, при спуске — наоборот. Сделано: `SceneRouteService` ищет
  путь по графу площадок и строит участки с `boardId`; стык полей — одна
  точка мира, поэтому актор не прыгает и не оставляет копию. Точка перехода —
  кромка площадки у лестничного колодца, а не её центр: актор выходит из
  колодца на пол верхнего этажа, а не идёт под настилом до середины площадки
  и не «выныривает» из него. Если колодца рядом нет, переход идёт через центр
  пары. Клик по площадке и колодцу рядом с ней ведёт через переход на парную
  площадку, а не только к самой площадке; клик по самому маршу ставит на
  ступени в точке клика и на этаж не уводит. Ступени, видимые в колодце
  верхнего этажа, кликаются как ступени нижнего: вырез в плите отдаёт клик
  тому полу, который сквозь него виден. Переход заканчивается на парной
  площадке и при подъёме, и при спуске: она стоит на верхнем торце марша, а
  не у его подножия. Площадка — это пол: подход идёт
  на её уровень, а не на верхний настил, который может её накрывать (крыша над
  лестничной клеткой); на нижнем поле площадка стоит наверху марша, поэтому
  подход идёт по ступеням. Клик по колодцу вплотную к площадке — тот же
  переход.
  Двери для манекена открыты, состояние в данных не меняется.
- Навигация предпросмотра строится при включении и смене поля по всем видимым
  этажам, а не в момент клика: иначе первый клик подвисает и актор прыгает с
  места. Сетка кэшируется по полю.
- Стены, комнаты и строения выводятся из геометрии и не хранятся отдельными
  сущностями: в снимке остаются те же `obstacle`-ленты и `opening`-проёмы.
- Крыша — опора `support` с `props.kind = 'roof'`: накрытие на высоте стен
  (`elevation`, у дома по умолчанию два ипари) толщиной `height`. Сейчас крыша
  не пол: высота под ней считается по полу, а маршрут по накрытию не
  прокладывается. В целевом строении крыша — верхняя опора выше последнего
  этажа. Обычная крыша остаётся потолком; `props.walkable` делает её настилом
  над полом, а не вторым полом вместо него: интерьер под крышей остаётся
  проходимым, у клетки есть нижний пол и верхняя поверхность, а актор на крыше
  имеет уровень настила. Вход — лестница или люк с верхнего этажа; это переход
  уровня внутри поля, а не ребро между полями. Люк — настоящий проём в
  настиле и в навигации: с крыши шагают в него и спускаются по маршу. Обычная
  крыша рисуется в слое
  `roofs` над стенами и декором; проходимая — плоским настилом в слое
  `deckRoofs`, ниже акторов, чтобы они сортировались над настилом. Тумблер
  «Крыши» скрывает картинку, не данные. В
  редакторе крыша скрыта по умолчанию, в предпросмотре показывается тумблером
  или когда выбранный актор на ней. В строение крыша входит и едет вместе с
  ним, а кликом внутри дома достаётся пол, не она: за накрытие считается
  только свес за стеной.
- Размер прямоугольника задаётся в карточке и ручками на карте: у опор —
  «Длина» и «Ширина» (длинная и короткая стороны), у остальных — «Ширина» и
  «Высота». Восемь ручек тянут стороны от противоположного угла, у опор есть
  ручка поворота. Центр при изменении размера из карточки остаётся на месте.
  Поворот первого среза — у `decor` и прямоугольных опор (`support` с
  `shape.type = "rect"`): мост, съезд и настил крутятся через
  `props.rotation` вокруг центра. Препятствия остаются axis-aligned.

### `scene_enclosure`

```
id              IdField
parent_board_id ReferenceField scene_board, indexed, onDelete cascade
child_board_id  ReferenceField scene_board, indexed, unique, onDelete cascade
footprint       JsonField, required
elevation       IntField, required, default 0, signed
label           StringField 255, nullable
sort_order      IntField, required, default 0, min 0
created_at      DateTimeField, required, default now
```

- `footprint` — контур в координатах родительского поля.
- `elevation` — знаковое целое в единицах сцены относительно родителя: `+`
  вверх, `-` вниз, `0` — помещение на той же отметке. Абсолютная отметка —
  сумма по цепочке; корень — `0`.
- `label` — имя строения или этажа для интерфейса. У верхнего вложения — имя
  строения; пусто — берётся имя поля.
- Строение — верхнее вложение и его потомки; на одном корневом поле может быть
  несколько строений. Корень — нижняя опора стопки. Подвал или пещера —
  вложение с отрицательной отметкой.
- `child_board_id` уникален: у поля не больше одного родителя.
- Циклы запрещены: поле не может быть предком самого себя.
- Крыша и мост — не enclosure, а `support` на поле строения: крыша — на
  верхнем этаже, мост — на поле, где он лежит.
- Двор, кольцо частокола и атриум — стены на том же поле, без вложения.
- Совместимость: старые снимки без полей читаются; миграция выставляет `+2`
  существующим вложениям, интерьеры на той же отметке — `0` вручную.

### Проходимая крыша (F5)

У опоры-крыши необязательное `props.walkable`: она идёт по пути настила
(`isSceneDeck`/`SceneDeck`), а не потолка, и не меняет таблицу вложения.
Клетка поверхности получает вид `roof` с верхней отметкой `elevation` и
зазором под ней, навигация строит по крыше отдельный уровень, а лестница с
верхнего этажа связывает её с полом. Интерьер под крышей остаётся
проходимым: нижний пол и верхняя поверхность живут в одной клетке. Настил
крыши непрозрачен и прорезан по верхней части марша, который на неё выходит:
это люк шириной в марш, а не щель во всю его длину. Проём настоящий и в
навигации — уровень крыши вычитает его из себя, поэтому с настила шагают в
люк и спускаются по ступеням, а не ходят поверх них; обзор вниз не упирается
в крышу. Уровни навигации несут вид поверхности, поэтому выбор уровня подписан
«На крышу», «На лестницу» или «На настил»; крыша и лестница могут стоять на
одной отметке и больше не выглядят двумя одинаковыми «настилами». С крыши
луч обзора идёт поверх стен своего этажа. Обычная крыша без свойства
остаётся потолком. Кликом крыша выделяется только за свес; скрытая тумблером
крыша не ловится кликом, но данные, поверхность и маршрут остаются.

## Сохранение и конкурентность

`scene.save` принимает полный snapshot локации. Промежуточных запросов на
каждое действие нет.

- Новые сущности клиент нумерует отрицательными `id` (`-1`, `-2`, …);
  `id = 0` запрещён.
- Ссылки внутри snapshot (`boardId`, `targetBoardId`, `parentBoardId`,
  `childBoardId`) могут указывать на временные id; писатель заменяет их на
  реальные в той же транзакции.
- Запись — одна транзакция: проверка доступа и `expectedVersion`, валидация
  всего snapshot, реконсиляция строк, обновление `version`.
- `expectedVersion` не совпал — типизированный конфликт с `currentVersion`.
  Автоматического разрешения нет: перечитать, перезаписать или сохранить копией.
- Успешный ответ возвращает сохранённый snapshot; клиент принимает его как
  новый эталон.
- Версии подсущностей не нужны.

Snapshot верхнего уровня:

```json
{
  "schemaVersion": 1,
  "id": 12,
  "name": "Таверна",
  "description": "",
  "resolution": 64,
  "version": 3,
  "boards": [],
  "elements": [],
  "enclosures": []
}
```

## Права

- `scene.edit` — создавать локации.
- `scene.view_all` и `scene.edit_all` — административный доступ.
- Владелец видит и правит свою локацию.
- Шаринг локаций и публичная видимость — `OPEN`; в первом срезе нет.
- Архивная локация не появляется в обычном списке; доступ к ней остаётся у
  владельца и администратора.

## Контракт копирования в Game

`SceneLocationSnapshot` — единственный вход для будущей `GameScene`.

- Game сохраняет `sourceLocationId` и `sourceVersion`.
- Все id полей, элементов, вложений и `targetBoardId` пересоздаются.
- Ссылки на файлы (`baseFileId`, `assetFileId`) сохраняются.
- PC/NPC в локации нет. Копируются только декор и служебные маркеры.
- `GameScene` — независимый snapshot. Правка локации после копирования не
  меняет игру.
- Occupancy, navmesh, LOS и туман не входят в snapshot локации. Предпросмотр
  Scene строит их из геометрии элементов только для витрины; Game при
  копировании собирает свой runtime — `OPEN`.
- Зависимость только `Game → Scene` на чтении; `Scene` не вызывает Game.

### Витрина и runtime

Предпросмотр Scene и runtime Game — разные потребители одной геометрии.
Граница между ними зафиксирована, чтобы витрина не стала вторым runtime.

- Витрина считает обзор по `occupancyCell` с конечным радиусом и только для
  показа: карта видимости, туман и призраки акторов — авторская подсказка, а не
  контракт. Пересчёт идёт по событию, а не каждый кадр; бесконечный радиус в
  витрине не требуется.
- Туман витрины считается на всех видимых полях: своё поле наблюдателя — по
  сетке поверхностей, чужие — по запечённым растрам. Это два состояния, видно
  или скрыто: разведанное и неизвестное — состояние карты боя, его ведёт
  `Game`, в данные локации оно не попадает. Растры плит и стен строятся один
  раз при смене данных; на тике остаются клетки в радиусе и обход растра по
  лучу, поэтому цена не зависит от числа строений в селе. Маска мельче клетки,
  край — поле расстояний и аналитический остаток радиуса.
- Runtime-туман рисует клиент Game: GPU/WASM по occupancy-блоку, бюджет
  ≤100 мс на ход. LOS токенов — сотни DDA по акторам, а не луч на каждую
  клетку; visibility polygon и глобальный граф по стволам не строятся
  ([`battlegroundLockedDecisions.md`](../specs/battlegroundLockedDecisions.md)).
- Лес масштаба ~40k деревьев — `InstanceLayer` на ~10 прототипов, не 40k
  `scene_element`. Рендер — instancing + LOD + culling по камере
  ([`scene-renderer.md`](scene-renderer.md)).
- Сетка vis = `occupancyCell`, потолок ≤1024² клеток; иначе ячейка
  укрупняется. 200×200 ипари при 0.25 — это 800×800, в потолок влезает.
- Авторская сетка хранит один интервал `sightBottom…sightTop` во Float32 —
  это упрощение витрины. Runtime-клетка — 8 байт: два непрозрачных интервала
  + крона + illumination + `portalId`, границы u8. Преобразование делает
  штамп при копировании в Game, а не рендерер.
- Акторы витрины живут в слое `decor` ради Y-сортировки; в runtime это
  отдельный слой `tokens`. Смешивать 200 токенов с 40k инстансов леса нельзя.

Практическое правило authoring-среза: не хранить лес как 40k отдельных
элементов и не делать витрину обязанной считать обзор без радиуса.

## Что не входит

- `GameScene`, актёры, инициатива, ОД, бой.
- runtime-навигация и туман Game; предпросмотр Scene считает только витрину.
- движение, полёт, рёбра опор, порталы как runtime-переходы.
- realtime/SSE и совместное редактирование.
- публичный шаринг локаций.
- связь с картой мира (появится позже в `Roleplay/Map`).

## Открытые вопросы

- Хранение occupancy/navmesh: `BLOB` в SmartTable, `Core/File` или кэш.
- Точная форма связи `Map → SceneLocation`: nullable `scene_location_id` или
  отдельная таблица.
- Шаринг локаций пользователям и группам.
- Импорт геометрии из SVG/растра.
- Правила LOD и инстансинга для больших лесных массивов.
