# Стандарты разработки Mifrial (PHP)

Эти правила применяются ко всему коду внутри `www/mifrial/`.

## Ориентация

Код ориентирован на **KISS**, **SOLID**, **DRY** и **чистое разделение слоёв**.
Quality-gate ловит размер и сложность; эти принципы ловят смешение ролей,
которого линтер не видит. При конфликте: сначала простой рабочий дизайн,
потом вынос слоя, когда появляется вторая причина меняться.

- **KISS.** Не заводить интерфейс, фабрику, translator или «стратегию» ради
  одного вызова. Пустой абстрактный класс «на будущее» запрещён. Имя модуля
  не копировать в имя порта (`ISmartTable` у модуля SmartTable — нет).
- **SOLID.** Один тип — одна причина меняться (SRP). Зависимости на абстракции
  **публичной** границы модуля; внутри модуля конкретный адаптер допустим
  (не публиковать Illuminate/PDO в `Interface/` и в карте портов). Открытость
  к расширению — новые типы полей/листья ошибок, не `switch` на всю карту в
  одном боге. Интерфейс не раздувать «на всякий случай» (ISP). Модуль не тянет
  чужой `Service/` (DIP + граница DEC-064/070).
- **DRY.** Повторяющийся разбор (SQLSTATE, DSN, ключи карты) — один тип.
  Не обобщать две похожие строки. Копия в тесте фикстуры допустима, если
  общая база полей скроет смысл сценария.
- **Слои.** Не смешивать в одном классе карту полей, DDL, Query Builder и
  HTTP. Папки:
  - `Table/`, `Field/`, `Dto/`, `Value/` — определение и значения, без SQL;
  - `Service/` — сценарий прикладного модуля: не имена колонок, не `ListQuery`.
    SmartTable сам — шлюз таблиц, его адаптеры живут в `Service/` этого модуля;
  - `Repository/` — хранение своего модуля (`IOpenedRecords` с фабрики, map ошибок строки).
    Не порт соседа, не чужой `Repository/`, не `open`;
  - `Schema/` — сверка своей карты с физикой (`IOpenedSchema`: `createTable` / `updateTable`);
  - внутри модуля допустимы подпапки по причине меняться (`Cache/`, …), когда
    кластер уже стабилен; публичные порты остаются в `Interface/Service/`,
    не зеркалить каждую подпапку;
  - `Container/` — только контейнер портов, не домен;
  - `Interface/` зеркалит путь класса; в карту портов контейнера попадают
    только сервисы, которые сосед имеет право `get`.
  Нижележащий слой не импортирует вышележащий: definition не знает Schema;
  поле не знает Query Builder; контейнер не знает строку таблицы.

Маркеры `composer quality` ниже — численная страховка тех же правил, не замена.

## Стиль и именование

- PHP 8.2+, `declare(strict_types=1);` в каждом PHP-файле.
- Форматирование выполняется PHP CS Fixer, проверка — PHPCS.
- Все используемые классы, включая глобальные (`Closure`,
  `JsonException`), импортируются через `use`.
- Код Mifrial бросает только наследников `MifrialException`. Голый
  `RuntimeException` / `InvalidArgumentException` не бросаем. Чужие PHP
  throwable ловим на границе (например JSON тела) и не оборачиваем пачкой
  «ради семейства».
- Интерфейсы имеют префикс `I`.
- Имена параметров и локальных переменных должны объяснять доменный смысл.
  Однобуквенные и бессмысленные сокращённые имена запрещены.
- Зависимости передаются через конструктор. Сервисы не получают локатор и не
  обращаются к нему во время выполнения.
- Локатор каталогизирует контейнеры модулей, а не отдельные сервисы. Фабрика
  контейнера — единственное место, где читают локатор или карту портов.
  Класс контейнера живёт в `Container/`, контракт — в `Interface/Container/`.
  `Service/` — сценарий, не контейнер и не колонки таблицы.
- Доступ к MySQL только через SmartTable. `illuminate/database` (Query Builder,
  Schema) и PDO допустимы лишь внутри `modules/Core/SmartTable`. Eloquent,
  `bootEloquent` и глобальный Capsule запрещены (`DEC-078`).

## Документация типов и методов

Каждый класс, интерфейс, trait и enum должны иметь PHPDoc с коротким
описанием на русском языке: зачем тип существует. `{@inheritdoc}`
допустим только при полном наследовании описания.

Каждый метод (`public`, `protected`, `private`) и конструктор должны иметь
PHPDoc:

- короткое описание на русском языке;
- `@param` для каждого параметра с описанием смысла;
- `@return` с описанием результата;
- `@throws` для возможных исключений;
- `{@inheritdoc}` используется только при полном наследовании документации.

Документация должна помогать IDE показать назначение типа, метода, параметров,
результата и исключений. PHP quality-gate считает отсутствие документации
или обязательного тега ошибкой PHPCS. Для `throw`, находящегося
непосредственно в методе, обязателен `@throws`; транзитивные исключения
проверяются по смыслу, так как PHPCS не может надёжно вывести их из графа
вызовов.

## Порядок методов

Методы класса располагаются в следующем порядке:

1. `__construct`;
2. `public`;
3. `protected`;
4. `private`.

Конструктор располагается первым независимо от его видимости. Внутри каждой
группы методы следует располагать ближе к месту их вызова и по связанным
операциям.

## Маркеры качества

`composer quality` проверяет не только форматирование, но и сигналы,
требующие пересмотра дизайна:

- больше трёх `return`;
- больше 30 строк в методе;
- Cognitive Complexity больше 8;
- Cyclomatic Complexity больше 8;
- вложенность больше трёх уровней;
- больше трёх логических связей в одном условии;
- чрезмерный размер класса;
- чрезмерное число публичных или защищённых методов;
- более 6 зависимостей конструктора;
- суммарная complexity класса больше 40.

Порог размера класса в phpcs: 500 строк. 10 публичных методов и 5 защищённых.
Число приватных методов само по себе ограничением не является.

Если после расширения класс стал больше 300 строк — это сигнал проверить
причины и то, не смешивает ли он задачи. Дробить ради дробления запрещено.
Дробить с ухудшением качества (та же одна причина меняться в двух файлах,
дублирование зависимости, обёртка без своей оси изменений) запрещено.

Все сигналы phpcs имеют уровень `error`. Это не приказ немедленно резать
файл. Если линтер ругается на размер или сложность класса — согласовать
решение с Андреем. С его явного решения либо точечное исключение
(`phpcs:disable` / `phpcs:ignore` на конкретный код с комментарием, почему
целое лучше), либо согласованное раздробление. Самовольно пилить класс,
чтобы пройти sniff, нельзя. Глобальные отключения запрещены.

Репозитории и другие специализированные роли могут иметь отдельные,
осознанно заданные пороги.

## Проверки

Из каталога `www/mifrial/`:

```bash
composer cs-fix
composer cs-check
composer quality
vendor/bin/phpunit
```

Форматтер исправляет безопасные формальные нарушения. Архитектурные и
complexity-маркеры автоматически не исправляются.
