# План Rule 15 — признак инициативы на проверке

**Статус:** каркас PHP сделан, 2026-10-05. Нарезка — [`rule-roadmap.md`](rule-roadmap.md) шаг 15. Канон — [`rule-system.md`](rule-system.md), «Экземпляр может отсутствовать». Стандарты — [`php-coding-standards.md`](php-coding-standards.md). Потребитель — Game G21; план G21 этим заходом не пишется.

Цель: на `CheckSpec` появляется bool того же рода, что `willpower` и `hitCheck`. Истина значит: эта проверка задаёт инициативу. Character и Game не меняются и не импортируются. Каталог карточек не наполняется. Бросок и порядок хода не считаются.

## Термины

| Термин | Смысл |
|---|---|
| Признак | Поле документа `spec` правила типа `check`. Не код карточки и не колонка. |
| Имя | JSON-ключ `initiative`. В PHP — аргумент `$initiative`, геттер `isInitiative()`. |
| Нет ключа | `false`. Старый документ проверки остаётся проверкой без инициативы. |

`initiative` на спеке характеристики — другое поле другого типа (запасная инициатива). Этот шаг его не читает и не переименовывает.

## Решения

### 1. Что появляется

В `CheckSpec` — ещё один bool рядом с `willpower` и `hitCheck`. `RootSpecs::check` читает его через уже существующий `SpecShape::bool`: нет ключа — `false`, не bool — та же ошибка формы, что у соседних bool.

Геттер — `isInitiative(): bool`. Отдельного порта, фабрики и листа ошибок нет.

### 2. Карты

Новых карт нет. Тело по-прежнему json `spec` на `rule_version`. Колонка, linkset и reference не заводятся. `IRules` не меняется.

### 3. Фасад

Фасад шага — тот же разбор документа, что уже собирает `CheckSpec`. Новый метод `IRules` не появляется. Поиск «единственной живой проверки с этим признаком» в срезе — забота G21, не этого модуля.

### 4. Ошибки

Чужой тип значения `initiative` бросает уже существующий `RuleSpecShapeException` (`RULE_SPEC_SHAPE`, сообщение — ключ `initiative`). `RuleSpecs::read` ловит его, как ловит чужую форму других ключей: у `RuleVersionRecord` `isSpecBroken()`, `getSpec()` пустой, сырой документ на месте. Новый лист не вводится. Две карточки с `initiative: true` в одном срезе этот шаг не запрещает: единственность — контракт G21.

Нет ключа — ветка `SpecShape::bool`, не ветка `dialog_launch` (у того нет ключа значит true).

### 5. Тесты

В `RuleSpecTest`, через `RuleVersionRecord`, как соседние разборы spec. Документ `check` с обязательным `allowed_modes`. Нет ключа и `false` — spec целая, `isInitiative() === false`. `true` — spec целая и признак истинен. Не bool — версия битая, spec пустая, документ сохранён. Mysql и фикстуры Game не трогаются: их документы без ключа остаются `false`. `GameCheckRoll` признак не читает.

### 6. Чего нет

Строка `check-initiative` и любой другой код правила в PHP. Наполнение каталога. Правка Vue DTO. Импорт Character и Game. Бросок, `IMechanicRolls`, порядок хода, запись урона. План G21. Заморозка спек. Новый шаг Mechanic.
