# План реализации магии 01 — вход в Арканиста

**Статус:** `IN_PROGRESS`, 2026-09-20.  
**Дизайн:** [`magic-content-design-01-arcanist-progression.md`](magic-content-design-01-arcanist-progression.md).  
**Источник:** [`spell-inventory-01.md`](spell-inventory-01.md), `AI.html`.  
**Первая группа:** `becoming-arcanist`, `structure-substitution`.

## 1. Цель

Замкнуть минимальный контентный вход в ветку Арканиста:

```text
Волшебство → Пути волшебства → Арканист → Образование → Базовое
  ├→ Становление Арканиста
  │   └→ изучение заклинаний до стоимости 2
  └→ Подмена структур → изучение non-spell навыков до стоимости 2
```

Это контентная посадка в Rule/Character editor. Новые Game-механики в план
не входят.

## 2. Что проверить до изменения мока

- точный текст двух карточек в исходной выгрузке;
- зона и стоимость каждой карточки;
- подтверждение, что `becoming-arcanist` сохраняет grant пути и общего
  Контроля магии;
- подтверждение раздельных grant scope:
  `spell` у Становления и `non_spell` у Подмены;
- наличие всех ссылок по code в текущем каталоге.

Если исходник не отвечает на вопрос, карточка остаётся `needs_work`, а
неподтверждённая часть сохраняется в `description`/`contentNote`.

## 3. План изменений

### 3.1 Контент

- исправить две карточки в `mockSpellImport`;
- сохранить семантические коды и каталог-секцию
  `abilities-acquired-magic-paths-arcanist`;
- не дублировать общие правила пути в каждом spell;
- не добавлять `has_ability_keyword magic-path` на заклинания;
- проверить `parent_ability_code`: эти две карточки не являются улучшениями;
- выставить `contentStatus` и `contentNote` согласно результату сверки.

### 3.2 Валидация и Character

- проверить требования и grants через существующий
  `RuleValidationService`;
- проверить, что путь открывает только нужный scope и `max_cost`;
- проверить, что `structure-substitution` не открывает spell;
- проверить, что потеря пути/источника блокирует использование, но не удаляет
  изученную способность;
- не добавлять отдельный тип grant или отдельный тип магической способности.

### 3.3 Тесты

Добавить/обновить тесты только на контракты этой группы:

- форма карточек и ссылок по code;
- grant пути Арканиста;
- `magic_study(scope: spell)` с потолком 2;
- `magic_study(scope: non_spell)` с потолком 2;
- отсутствие перекрёстного открытия spell/non-spell;
- требования входа в путь;
- редакторские `domainCode`/параметры, если они затрагиваются.

Тесты не должны проверять наличие живого каталога по случайному числовому
ID и не должны считать карточки доказательством готовности Game runtime.

## 4. Гейт

Группа считается закрытой, когда:

- две карточки сверены с источником и имеют честный `contentStatus`;
- требования и grants проходят typed validation;
- редактор показывает ветку без ручных исключений;
- `magic_study` корректно разделяет spell и non-spell;
- тесты группы проходят;
- `magic-content-design-01-arcanist-progression.md` дополнен фактическими
  решениями и записью о результате;
- следующая группа не открывается автоматически.
