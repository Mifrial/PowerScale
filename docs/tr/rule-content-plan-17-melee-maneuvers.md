Цель — посадить группу «Боевые манёвры» через общий примитив «действие сразу
после удара», а не через отдельную ветку кода под каждую карточку.
Манёвр — обычное действие: игрок объявляет его **после** успешной атаки, если
РУ этой атаки дотянул до порога карточки. Цена списывается при объявлении
манёвра, эффект применяется к цели прошлого удара. Движение, позиция предмета и
немедленная атака в этот срез не входят.

## 2. Что уже есть в коде

- Исход удара — целое РУ (`GameStrikeResolution::successOf`); для ближнего
  боя блок успешного защитника режет РУ до 1, уклонение при победе даёт 0.
  Поэтому порог «3РУ» проверяется по уже посчитанному success, без второй
  арифметики.
- Сразу после удара бой хранит `last_strike_snapshot` в
  `pending_action_effects` актора: цель, РУ, реакция, урон, оружие удара.
  Любое следующее действие снимает снимок, поэтому манёвр возможен только
  следующим действием.
- Неустойчивость — состояние с флагом `unstable`; код состояния ищется по
  флагу (`GamePushRules::unstableCode`), а не по строке карточки.
- Запись состояния в лист и проверка прироста — `GameActionManeuver`
  (`putState` + `GameStateIncreaseChecks::plan`); толчок идёт тем же путём.
- Не-атакующее действие уже умеет быть заявкой после удара: `followUpTargetKey`,
  `GameActionPerform::requiresFollowUp`, `GameLastStrikeSnapshot`.
- Мастерство оружия удара считается `GameStrikeOutcome::weaponMasteryOf`
  (так уже проверяется Поддержка).
- Подсказка «можно совершить один из манёвров» в Vue — по тому же снимку и
  купленным карточкам; кнопка открывает обычный диалог действия.

## 3. Контракт спеки

Узел ставится на карточку-манёвр (`type: action | skill`):

```json
"strike_maneuver": {
  "min_success": 3,
  "min_weapon_mastery": 3,
  "effects": [
    { "kind": "state", "state": "<код состояния>", "amount": 1 }
  ]
}
```

- `min_success` — минимальный РУ прошлого удара. Манёвр нельзя объявить, если
  в снимке нет попадания по выбранной цели с таким РУ.
- `min_weapon_mastery` — минимум мастерства оружия, которым нанесён прошлый
  удар. Проверяется исполнением. Нет поля — проверки нет. Это не требование
  покупки: карточка может быть куплена при мастерстве 5, а удар нанесён
  оружием с мастерством 4 — тогда манёвр не сработает.
- `effects` — типизированные эффекты для цели прошлого удара. `kind: state`
  добавляет состояние; `state` — код правила состояния из контента, а
  `amount` — значение прироста (≥ 1). Кодов карточек и состояний в PHP нет:
  исполнение берёт код из данных и проверяет, что это `StateSpec`.
- Требование покупки «Мастерство боя с оружием N» записывается в обычный
  `requirements` способности типом `min_weapon_mastery_value` с признаком
  `weapon` и размерным `min`. Это значение мастерства (характеристика профиля
  плюс уровень владения), а не уровень владения семьёй: `{3|1}` = 6 проходит
  минимум `{5|0}`. Для уровня владения остаётся `min_weapon_mastery`
  (`min_level`) — им пользуются оружейные навыки.
- Цена — обычные `action_components` карточки; списывается при объявлении
  манёвра. Неудача проверки не возвращает цену.
- Узел сам делает карточку заявкой после удара; карточка остаётся обычным
  действием в списке и требует `followUpTargetKey`.

Усиление манёвра — отдельный узел на карточке-улучшении. Это общий примитив
«подмена эффекта при применении»:

```json
"maneuver_boost": {
  "maneuvers": ["zastavit-otkrytsya", "razbit-zaschitu"],
  "min_success": 4,
  "min_weapon_mastery": 5,
  "replaces": [
    { "kind": "state", "state": "<код состояния>" }
  ],
  "effects": [
    { "kind": "state", "state": "<код состояния>", "amount": 2 }
  ]
}
```

- `maneuvers` — коды усиливаемых манёвров, выбранные мультиселектором в
  редакторе. «Вскрыть слабость» по каталогу усиливает и «Заставить
  открыться», и «Разбить защиту».
- `min_weapon_mastery` — тот же рантайм-порог мастерства оружия прошлого
  удара, что и у базового манёвра.
- `replaces` — селекторы эффектов базового манёвра, которые убираются перед
  добавлением `effects`. Совпадение ищется по `kind` и `state`, без значения:
  смена базового `amount` не ломает усиление. Пустой `replaces` — ничего не
  убирать, новые эффекты добавляются к базовым.
- Требования покупки (мастерство 5 и «один из навыков») живут в обычном
  `requirements` карточки-улучшения, а не в узле. Поэтому в узле больше нет
  `requires_any` и дублирующего `min_mastery`.
- Усиление не объявляется отдельно: движок сам находит купленные улучшения,
  чьи `maneuvers` содержат объявленный манёвр и чьи рантайм-пороги выполнены.
- Если подходящих усилений несколько, побеждает усиление с наибольшим
  `min_success`; при равенстве — первое по коду, чтобы результат был
  детерминированным.

### Состояние S1

Сделано в PHP:

- `StrikeManeuverSpecs` читает `strike_maneuver` и `maneuver_boost`;
  пустые эффекты, нецелый порог, чужой вид эффекта, пустое состояние и
  пустая ссылка на манёвр — битая спека;
- `AbilityBase` получил `getStrikeManeuver()` и `getManeuverBoost()`;
- `GameActionPerform::requiresFollowUp` считает манёвр заявкой после удара;
  `GameActionApply` проверяет снимок до списания цены через
  `GameActionManeuver::assert`;
- проверяется: снимок прошлого удара есть, в нём есть попадание по выбранной
  цели с РУ ≥ `min_success`, удар был ближним (`profileType: strike`), а
  мастерство оружия удара не ниже `min_weapon_mastery`; манёвр нельзя
  применить к чужой цели;
- цена — ресурсные компоненты карточки-манёвра, списывается обычным сценарием
  действия;
- каждый эффект `kind: state` пишется в лист цели через `putState` и проверку
  прироста; одинаковые состояния складываются; чат получает хвост «цель
  получает <состояние> N»;
- усиление ищется в живых правилах актора; уровень улучшения ≥ 1,
  `maneuvers` содержит объявленный манёвр, рантайм-пороги выполнены; при
  РУ ≥ `min_success` эффекты из `replaces` убираются, затем добавляются
  `effects`;
- `min_weapon_mastery_value` считается по фактам листа: характеристика профиля
  (`weapon_mastery.profiles`) сдвигается уровнем владения семьёй; семья без
  купленного уровня получает базовое мастерство;
- снимок прошлого удара хранит оружие удара (`itemInventoryId`,
  `itemRuleCode`, `profileType`) — по ним считается мастерство оружия;
- ответ `game.runAction` получает `strikeManeuver` (`ruleCode`, `boosted`,
  `targetKey`, `effects` как список `{kind, state, amount}`, `sheetVersion`)
  для проверок и чата.

Не входит в S1: защитные манёвры, немедленная атака, выбивание предмета,
движение.

### Состояние S2 — `~ОТЛОЖЕН~`

Немедленная атака требует отдельного разрешения в
`pending_action_effects[$actorKey]`: следующая атака актора с фактической
ценой не выше лимита и нужной целью, иначе разрешение сгорает. Это меняет
цикл хода и окно объявления, поэтому S2 не смешивается с S1. Защитный триггер
добавляется в тот же узел, когда появится разрешение на атаку; парирование как
реакция по-прежнему недоступно.
