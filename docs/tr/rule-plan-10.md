# План Rule — один профиль блока у предмета

**Статус:** сделан, 2026-10-07. Профиль сейчас лежит в двух местах: необязательный `weapon.block_profile` и обязательный при блоке щита `shield.block`. Оба имеют тип `BlockProfile`. [`character-plan-12.md`](character-plan-12.md) этот файл не пишет: проекция читает уже одно поле.

Стандарты — [`php-coding-standards.md`](php-coding-standards.md). Выбор «руки, ноги или щит» при ударе сюда не входит. В проекцию приходит уже выбранная строка инвентаря.

## Поле

У `ItemSpec` одно необязательное поле `block_profile` того же `BlockProfile`, рядом с `weapon`, `shield` и `armor`. Нет ключа — профиля нет. Пустой объект не становится профилем с нулями.

`WeaponBlock` больше не хранит `block_profile`. `ShieldBlock` больше не хранит `block`. Прочность оружия и щита, минимальная сила, профили удара и лимиты остаются на своих блоках.

Старые ключи `weapon.block_profile` и `shield.block` разбор не читает. Документ, в котором после переноса заполнены оба и их защита, эффективность или сопротивления различаются, не разбирается. Одинаковое заполнение обоих в каталоге не оставляем: в spec остаётся один ключ.

## Операции

Операция `block` пишет этот профиль, а не блок оружия или щита. `when` по-прежнему решает, выполняется ли операция на этом предмете. Две операции с одним `source_code`, попавшие в этот профиль, схлопываются как сейчас. Профиль, которого в spec нет, операция не создаёт: так уже не создаётся отсутствующий блок оружия.

## Каталог

У предмета щита содержимое `shield.block` переезжает в `block_profile`, ключ `block` из щита убирается. У предмета оружия содержимое `weapon.block_profile` переезжает туда же, старый ключ убирается. Предметов, у которых заполнены оба разных профиля, в `mockItemImport` нет; если такой документ попадёт в разбор, это отказ, не выбор щита.

Фронтовые `ItemSpec`, `WeaponBlock` и `ShieldBlock` получают ту же форму. Редактор правит один профиль на предмете.

## Приёмка

| Случай | Ожидание |
| --- | --- |
| Только `shield.block` в старом виде | После переноса каталога профиль на предмете, у щита ключа `block` нет |
| Только `weapon.block_profile` | То же для оружия |
| Нет ни одного | `block_profile` нет, щит и оружие без этого поля разбираются |
| Оба заполнены и различаются | Отказ разбора |
| Операция `block` при выполненном `when`, профиля нет | Поле не создаётся |
| Операция `block` при невыполненном `when` | Профиль не меняется |

Character, Mechanic и Game actions этим шагом не меняются.
