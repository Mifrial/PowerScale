# План Rule 14 — обход формул

**Статус:** каркас PHP сделан, 2026-10-05. Нарезка — [`rule-roadmap.md`](rule-roadmap.md) шаг 14. Канон узлов — уже разобранные `ScalarFormula` и `DimensionalFormula`. Стандарты — [`php-coding-standards.md`](php-coding-standards.md).

Цель: один обход в `Roleplay/Rule`. Вход — узел и узкий контекст вызывающего. Выход — число. `to_scalar` переводит размерный узел в скаляр внутри того же обхода. Character, Game и Mechanic не меняются. G20 не начинается.

## Термины

| Термин | Смысл |
|---|---|
| Узел | Уже собранный объект `ScalarFormula` или `DimensionalFormula`. Новый язык формул не вводится. |
| Контекст | Значения, которые передал вызывающий: характеристики, уровни способностей, параметры, базы характеристик действий. Лист не читается. |
| Число | Для скалярного узла — его скаляр. Для размерного — `floor(база × 2^размер)`. `to_scalar` отдаёт базу среднего размера, не это округление. |

## Решения

### 1. Один порт

`IFormulaEvaluations::evaluate(узел, контекст): int`. Класс `FormulaEvaluations`. Отдельного модуля под размер и под скаляр нет. Порт без часов и без фабрики соседей. HTTP нет.

Неизвестный класс узла — `RULE_INVALID`. Нет характеристики у узла `characteristic` / `actionCharacteristic` — тот же лист. Нет параметра — тот же лист, это не ноль. Нет уровня способности — ноль. Нет характеристики у `characteristic_size` / `characteristic_size_positive` — ноль. Нет одной из пар у `characteristic_size_gap` — ноль.

Шкала базы 3–5, шаг размера 3 — как у `CharacteristicNumber`. Сдвиг базы живёт на `DimensionalNumber`.

### 2. Чего нет

Удар, проверка, `CheckSpec`, `IMechanicRolls::rate`. Импорт Character и Game. Чтение листа. Заморозка спек. Второй язык узлов.

Поведение чисел сверено с Vue `FormulaEvaluationService`: те же ветки узлов и те же края (модификатор шкалы, множитель действия, делитель 0, `to_scalar`).
