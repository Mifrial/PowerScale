## 1. Границы

Входят:

- карточка отклонения в контенте: тип `simple` + механика-маркер
  `spell_deviation` с payload (кубы, порог, состояние, взрыв);
- ссылка с проверки сотворения (`failure_rule_codes`) и её чтение
  серверным кастом;
- серверный бросок 2d6 после **проваленного броска** проверки, сила
  `сумма − 7`;
- состояние на конкретном источнике каста (`boundSourceKey`), штраф к
  потолку мощи этого источника, затухание `−1` в конце хода кастера;
- взрыв при дубле: цели и дистанции из запроса (окно-заглушка), формула,
  сопротивление, `sr: 1`, последствия урона, чат;
- real-фронт: показ серверного 2d6, окно взрыва, штраф к мощи, единый ключ
  источника;
- уход `ARCANE_DAMAGE_TYPE_CODE` из real-пути фронта (в моке-предпросмотре
  константа остаётся; на сервере её нет).

Не входят:

- батлграунд, сетка и серверная геометрия взрыва (отдельный шаг; здесь
  окно-заглушка, см. 4.4);
- мана, кристалл, накопители (M10);
- длительности, поддержание и заряды (M6–M8);
- таблица эффектов силы отклонения сверх числа в чате;
- disruption и «разрушить заклинание»;
- перенос расчёта на клиент: real-режим остаётся серверным.

## 3. Контракт Rule

### 3.1. Карточка отклонения

Новый тип правила **не** вводится: карточка типа `simple`, поведение — в
механике-маркере (как `rule-6-and-1`, `movement-state`, `advantages`).
Спека `simple` контрактом не разбирается, данные живут в payload механики —
редактор уже умеет их править через `RuleMechanicsEditor`.

Каталог механик: одна строка `spell_deviation`, версия `1.0.0`, хендлер —
наследник `MarkerMechanicHandler` без подписок (создаётся в разделе
«Механики», как остальные).

Payload карточки `spell-deviation`:

```json
{
  "type": "spell_deviation",
  "data": {
    "dice_count": 2,
    "die_faces": 6,
    "neutral_sum": 7,
    "state_rule_code": "core-magic-deviation",
    "burst": {
      "damage_type_code": "arcane",
      "success_rating": 1
    }
  }
}
```

Правила чтения:

- `dice_count >= 1`, `die_faces >= 2`, `neutral_sum` — целое; иначе ошибка
  контента, а не тихий ноль;
- `state_rule_code` обязателен и должен быть живым правилом типа `state`
  с `magic_deviation: true`; второй источник кода состояния не заводится;
- `burst` опционален: без него дубль только пишется в чат;
- `burst.damage_type_code` — живой `damage_type`; `success_rating >= 1`.

Типизированный читатель — `Rule/Spec/SpellDeviationSpecs::read()` и DTO
`Rule/Dto/Spec/SpellDeviationSpec`. Это не новый корневой тип: `RuleSpecs`
не меняется.

### 3.2. Ссылка с проверки

У `CheckSpec` появляется общее поле `failure_rule_codes: string[] | null` —
«что запускать при провале этой проверки». Не ветка под магию: поле
применимо к любой проверке.

- Парсер `CheckSpecs::check`, DTO `CheckSpec`, редактор `CheckEditor`
  (мультиселект по карточкам, как «Правила на броске»), карточка проверки
  показывает коды текстом.
- `check-spell-cast` получает `failure_rule_codes: ["spell-deviation"]`.
- Сервер проверяет, что каждая карточка жива в ревизии и несёт механику
  `spell_deviation`; иначе `GameInvalidException`.
- Пустой список или отсутствие поля — отклонения нет (контентное решение).

### 3.3. Состояние

`core-magic-deviation` уже описывает поведение: сила снижает Магию
конкретного ядра, `−1` в конце хода кастера. M5 добавляет только:

- `boundSourceKey` в строке листа (`item:<inventoryId>`, `grant:<abilityCode>`,
  `characteristic:<code>`);
- чтение штрафа по этому ключу;
- затухание по флагу `magic_deviation` в `GameTurnTicks`.

`aggregation: independent` означает отдельные строки на разные источники;
накопление на одном источнике делает `patchState` (см. 4.3).

### 3.4. Тип урона взрыва

Код берётся из `burst.damage_type_code` карточки. В PHP константа
`ARCANE_DAMAGE_TYPE_CODE` не используется; на сервере её нет. На фронте она
остаётся только в моке-предпросмотре (`SpellCastDialog`/`HitLaunchDialog`
локальный расчёт) и уходит из real-пути.

## 4. Модель и API

### 4.1. Когда звать отклонение

| Исход | Отклонение |
| --- | --- |
| Проверка была и провалена (`needsCheck: true`, `roll` есть, `castOk: false`) | Да, 2d6 |
| Провал и молоко касания | Да (магия сорвалась) |
| Молоко при успешной проверке | Нет |
| Skip `{0|-1}` (`needsCheck: false`) | Нет |
| Auto-fail без броска (`roll: null`) | Нет |
| Отказ до старта (нет ОД, нет рук, чужая версия) | Нет |

Условие строго `roll !== null && roll.success === false`, а не
`!roll?.success`.

### 4.2. Бросок и сила

`GameSpellDeviation::outcome()`:

- `dice_count` независимых граней `1..die_faces` (RNG порта, как остальные
  кубы; без правила 6 и 1, преимуществ и пула);
- `face_sum` — сумма граней;
- `strength = face_sum − neutral_sum`;
- `has_effect = strength > 0`;
- `is_doubles` — все грани равны между собой (для 2d6 совпадает с каноном);
- `die_digit` — грань для формулы взрыва (при дубле `n+n` это `n`).

Сила — число, а не «прохождение»: у отклонения нет Сложности. Порог и кубы
приходят из payload, не из PHP-констант.

### 4.3. Состояние на источнике

Ключ источника — единый для сервера и фронта:

- `item:<inventoryId>` — магическое ядро-предмет;
- `grant:<abilityCode>` — ядро из гранта;
- `characteristic:<code>` — когда источника-предмета нет.

Сервер собирает ключ из уже нормализованного `usedPower.source`
(`GameSpellCastBody::usedPower`), а не из клиентской строки.

Операции листа кастера:

- есть строка `core-magic-deviation` с тем же `boundSourceKey` →
  `patchState` с `value = старый + strength`;
- нет → `putState` с `boundSourceKey` и `value = strength`;
- `strength <= 0` → операций нет.

`CharacterActualStateRows` принимает `boundSourceKey` в `putState` и копирует
его в строку. `patchState` ключ не меняет.

Штраф к мощи: `GameSpellCastFacts::usedPower` сравнивает `usedPower` не с
чистой характеристикой, а с `характеристика − сила отклонения на этом
источнике` (не ниже `{0|0}`); если потолок ниже минимального размера —
источник недоступен. Штраф действует только на каст с этим источником.

Затухание: `GameTurnTicks` для строк с флагом `magic_deviation` даёт
`value − 1`, при нуле — `removeState`.

### 4.4. Взрыв

Формула канона (M9, SR-090/093):

```text
powerN  = toNumber(usedPower)
radius  = powerN
amount  = max(0, (powerN − distanceIpari) * dieDigit)
injury  = max(0, (amount − сопротивление) * 1)
```

- тип урона, `sr` и наличие взрыва — из payload карточки;
- сопротивление — обычный расчёт `GameStrikeDefense` для типа (аркан уже
  помечен `defense_ignored: true`); грант сопротивления и броня входят один
  раз, как у урона заклинания;
- последствия (истощение, рана, деление повреждения) — через
  `GameStrikeConsequences`, как у урона;
- кастер всегда входит в список с дистанцией 0; убрать его нельзя.

**Окно выбора целей — заглушка.** До батлграунда список целей и дистанции
вводит игрок; сервер проверяет только то, что может: цель — участник боя с
живым листом, дистанция — целое `0 <= distance <= radius`, без дублей,
версии листов совпадают. После батлграунда сервер сам определяет, кого задел
взрыв и на каком расстоянии; поле `burstTargets` из запроса тогда удаляется.
Доверять геометрию игроку постоянно нельзя, это временная граница.

### 4.5. Фазы, хранение и запросы

- `GameSpellCast`/`GameSpellTouchFinish` после проверки зовут
  `GameSpellDeviation` и получают исход;
- пауза открывается, если нужно выбрать насыщение **или** есть дубль со
  взрывом (даже когда шагов насыщения нет);
- в `game_battle.pending_spell_cast` добавляется блок `deviation` (грани,
  `faceSum`, `strength`, `isDoubles`, `dieDigit`, `burst: {damageTypeCode,
  successRating, radius} | null`) и список источников для штрафа не нужен —
  источник уже в самом касте;
- `resolve` принимает в контексте `burstTargets` рядом с `saturationSteps`:

```json
{
  "phase": "resolve",
  "kind": "spell",
  "context": {
    "castId": "…",
    "saturationSteps": 0,
    "burstTargets": [
      { "type": "character", "id": 12, "distanceIpari": 0, "expectedSheetVersion": 7 }
    ]
  }
}
```

- пустой/отсутствующий список трактуется как «только кастер, дистанция 0»;
- закрытие диалога — тот же `resolve` с 0 шагов и кастером; `abort` остаётся
  для устаревших версий и GM;
- состояние и взрыв применяются в `resolve` одной транзакцией: если каст
  провален, но игрок так и не закрыл окно, действует открытое действие, и
  следующий шаг не начнётся; GM-`abort` отклонение не накладывает (осознанное
  решение, чтобы не мутировать лист в фазе `check`);
- replay обеих фаз отдаёт сохранённый результат, 2d6 не перебрасывается.

### 4.6. Ответ и чат

Ответ `check`/`resolve` получает:

- `deviation`: `{firstFace, secondFace, faceSum, strength, hasEffect,
  isDoubles, dieDigit}` или `null`;
- `burst`: список `{target, damage, injury, sheetVersion}` (урон — как у
  `spellDamage`), `null` без взрыва.

Чат:

- 2d6 — то же вложение `type: "roll"`, но с `scoring: "face_sum"`,
  `faceSum`, `deviationStrength` и без `check`; `PhpChatRollService` получает
  ветку для такого payload, `DiceRollResult.vue` уже читает `faceSum` и
  `deviationStrength`;
- строка силы: «Магическое отклонение силой N» / «Магического отклонения
  нет»;
- при дубле — «Собранная магия взрывается», затем урон по каждой цели
  существующим форматтером эффекта заклинания;
- replay не дублирует сообщения.

## 6. Тесты

Юнит (Rule/Game):

- парсер payload: полный набор, отсутствие `burst`, битые числа, битый код
  состояния;
- `failure_rule_codes`: живая карточка, отсутствующая, карточка без механики;
- сила: `7` → 0 (нет эффекта), `4+4` → 1 и дубль, `2+2` → −3 и дубль,
  `3+4` → 0 без дубля, `6+6` → 5 и дубль;
- состояние: `value` складывается на том же ключе, разные ключи — разные
  строки, `strength <= 0` — операций нет;
- штраф: потолок мощи падает только на своём источнике; нулевой размер —
  источник недоступен;
- затухание: `2 → 1`, `1 → removeState`, строки без флага не трогаются;
- формула взрыва: `powerN 5`, дистанция 0 и 2, `dieDigit 4`; дистанция
  больше радиуса — 0; `sr: 1`; сопротивление один раз.

MySQL:

- провал проверки без дубля: 2d6 в чате, состояние на источнике, ОД списаны,
  урона заклинания нет;
- `4+4`: пауза, `resolve` с кастером и вторым участником — урон обоим,
  версии листов в ответе, чат;
- пустой `burstTargets` — только кастер;
- дистанция больше радиуса и чужой участник — `INVALID_PARAMS`;
- закрытие диалога без шагов и целей — кастер получает взрыв, replay не
  дублирует;
- касание: провал после закрытия удара, состояние на кастере, взрыв через
  `resolve`;
- auto-fail, skip, успех и молоко при успехе — без 2d6 и без состояния;
- второе отклонение на том же источнике складывается, конец хода уменьшает
  на 1.

Vitest:

- real-диалог показывает серверное 2d6 и не бросает локально;
- окно взрыва отдаёт цели и дистанции в `resolve`;
- штраф к мощи виден в предпросмотре при `boundSourceKey`;
- `face_sum` payload проходит `PhpChatRollService`, пул-попап не рисуется.

## 7. Риски и открытые вопросы

1. **`boundSourceKey` как контракт.** Формат строки — часть ответа листа;
   зафиксировать в карточке модуля и не собирать её в трёх местах. Для
   `characteristic:` штраф бьёт по общему `magic-power` — это ожидаемо, пока
   нет ядер-предметов.
2. **Мощность и штраф.** Клиент присылает `usedPower`; сервер режет по
   потолку с учётом отклонения. Иначе после провала можно кастовать на
   полную мощь.
3. **GM-`abort` без отклонения.** Состояние применяется в `resolve`, а не в
   `check`: `check` не мутирует лист (инвариант M4). Если позже понадобится
   наказывать за брошенный каст, это отдельное решение.
4. **Доверие к целям взрыва.** Заглушка осознанная; сервер валидирует
   участника, дистанцию и версии, но саму дистанцию до батлграунда берёт из
   запроса. Явно указать в документации и в подсказке окна.
5. **Урон кастеру.** Кастер может быть и целью взрыва: операции кастера
   (отклонение) и его урон должны лечь в одну запись с одной ожидаемой
   версией.
6. **Молоко касания.** Урон оружием касания применяется как раньше; взрыв и
   отклонение — дополнительно. Не смешивать `attackSr` и `spellSr`.
7. **`defense_ignored` у аркана.** Проверить тестом, что грант
   сопротивления и броня входят один раз; поведение сложения слоёв уже
   реализовано в `GameStrikeLayers`.
8. **Чат.** 2d6 — то же вложение `roll`, не новый тип. Replay и повторный
   `resolve` не должны дублировать строки.
9. **Мок.** Локальный бросок и локальный взрыв остаются предпросмотром; в
   real-режиме источник правды — сервер. Расхождение допустимо, но не должно
   попадать в контракт.
10. **Порог силы.** `strength == 0` — «отклонения нет», эффекта нет; дубль
    всё равно взрывает. Это канон, а не ошибка знака.
