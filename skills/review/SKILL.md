# Skill: Frontend Review

## Когда запускать
По запросу пользователя "давай сделаем ревью" или "проведи ревью фронтенда"

## Процесс

### Фаза 0: Верификация
Проверить что код вообще работает:
```bash
cd draft-front_1.2ds
npx vue-tsc --noEmit  # типы
npm test              # тесты
npm run build         # сборка (опционально)
```

Если что-то падает — **сначала чиним**, потом продолжаем ревью.

### Фаза 1: Сбор проблем
Пройтись по чеклисту из `checklist.md`:
- Архитектура (слои, DI, зависимости)
- Vue 3 + Pinia (реактивность, watchers, lifecycle)
- TypeScript (типы, generics)
- Функциональность (auth, CRUD, навигация, состояния)
- Безопасность (токены, CSRF, guards)
- Производительность (N+1, debounce, списки)
- UI/UX (loading/error/empty states)

**Контекст для проверки:**
- `docs/tr/TR.md` — полноценное ТР (содержит всю информацию из ТЗ и ТР)
- `docs/review/context.md` — предыдущие решения ревью

### Фаза 2: Вывод результатов
Вывести таблицу:

```markdown
## Ревью фронтенда — [дата]

### Верификация
- [x] Типы
- [x] Тесты
- [x] Сборка

### Найденные проблемы (N)

| # | Проблема | Приоритет | Модуль | Описание |
|---|----------|-----------|--------|----------|
| 1 | ...      | CRITICAL  | Auth   | ...      |
| 2 | ...      | HIGH      | Chat   | ...      |
| 3 | ...      | MEDIUM    | UI     | ...      |

Готов обсудить проблемы по порядку. Начнём с #1?
```

**Приоритеты:**
- **CRITICAL** — ломает функционал или безопасность
- **HIGH** — серьёзная архитектурная проблема
- **MEDIUM** — влияет на поддерживаемость/производительность
- **LOW** — косметические улучшения

### Фаза 3: Обсуждение проблем (по запросу)
Когда пользователь говорит "давай обсудим проблему #N":

1. Дать 2-3 варианта решения
2. Для каждого: плюсы, минусы, рекомендация
3. Пользователь выбирает вариант
4. Внести правки, проверить типы/тесты
5. Перейти к следующей проблеме

**Формат обсуждения:**
```markdown
## Проблема #N: [название]

### Варианты решения

**A) [вариант]**
- Плюсы: ...
- Минусы: ...
- Рекомендация: ✅/❌

**B) [вариант]**
- Плюсы: ...
- Минусы: ...
- Рекомендация: ✅/❌

Рекомендую вариант [X]. Согласен?
```

### Фаза 4: Применение решений (по запросу)
Когда пользователь согласен с вариантом:
1. Внести правки в код
2. Проверить `vue-tsc --noEmit` и `npm test`
3. Обновить `docs/review/context.md`
4. Перейти к следующей проблеме

## Работа с ТР

Если найдено расхождение с `docs/tr/TR.md`:
1. Отметить в таблице как "Расхождение с ТР"
2. При обсуждении спросить:
   - Это **осознанное отхождение**? → Обновить ТР
   - Это **ошибка**? → Править код

## Правила

1. **Не привязываться к конкретным строкам** — искать системные проблемы
2. **Не писать готовый код сразу** — сначала обсудить варианты
3. **Итеративный подход** — одна проблема за раз
4. **Учитывать контекст** — mock-режим, отсутствие бэка, текущее состояние проекта
