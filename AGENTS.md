# PowerScale — первый релиз (активная разработка)

## Команды (в draft-front_1.2ds/)
- Dev: `npm run dev` → порт 3000. Сервер на 3000 держит пользователь для тестов — не убивать и не занимать порт.
- Build: `vite build` · Тесты: `vitest run` · TS: `vue-tsc --noEmit`.
- Верификация: в дебаге — только `npm run format` + `npm run lint` (автофиксят); вердикт по багу — тест зелёный (`npx vitest run <файл>`) или подтверждение разработчика. Полный батч `npm run format` + `npm run lint` + `npx vue-tsc --noEmit` + `npm run test` — на завершении бага/задачи. Файлов-исключений нет.

## Браузер и затыки
- Встроенный браузер Cursor (tabs/lock/navigate и прочие browser MCP) **не использовать**: у агента он зависает без результата. Нужна визуальная проверка UI — коротко написать, *что* посмотреть, и отдать это человеку.
- Если любой инструмент/шаг долго не отвечает или крутится без прогресса — **остановиться и написать**, а не повторять тот же вызов.

- В новой сессии, когда снова трогаем UI Vuetify, **подключить Vuetify MCP** — не угадывать API кнопок/групп.

## Чтение кода
- Читать файлы лениво, только по задаче. Не сканировать проект на старте.

## Память (знаниевый граф)
- Хранилище: `@modelcontextprotocol/server-memory` с `MEMORY_FILE_PATH` = `.opencode/memory.jsonl` (изоляция от других воркспейсов машины — у них свои файлы). Не менять путь/формат без причины.
- Читать по требованию: `memory_search_nodes` → открывать только нужные узлы; весь граф на старте не читать.
- Наполнение: стабильная архитектура, роли документов, решения с датой, `work_item` в конце сессии (коротко + ссылки на ТР/спеки). Не дублировать код и доки — класть указатели, не содержание.
- Регламент гигиены (защита от сваливания в свалку):
  - «1 факт = 1 узел»: не плодить пары decision+work_item на одну тему — канонический узел решение или документ.
  - Ограничение объёма узла: до ~1.5К симв., ≤8 наблюдений. Длинные детали — в доки, в память — указатель (путь + роль).
  - `work_item` писать только в конце сессии: дата, 2–5 наблюдений, ссылки на ТР/спеки; без пересказа реализации.
  - Feature-узлы и session-логи в память не класть (это код/ТР).
  - Устаревшее удалять в той же сессии (`memory_delete_*`): старые `work_item`, решения, уже зафиксированные в ТР/спеках, дубли, чужие воркспейсы.
  - Периодическая чистка графа по этому регламенту (по запросу).
